<section id="topic-overview" class="topic-overview">
<p class="reader-paragraph opening"><span class="paragraph-number" aria-label="00.01">00.01.</span><span class="paragraph-text">This report connects the interfaces used to manage an SSD and perform data operations: establish capabilities, configure behavior, receive status, and explain the range and completion guarantees of commands such as Read and Write. Start with the overall picture, then open Base and the NVM Command Set and move forward through their pages.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>NVM</dt><dd>Non-Volatile Memory, memory that retains data without power.</dd></div></dl>
<h2 id="main-ideas">The main ideas</h2>
<div class="topic-map">
<article><span class="axis-number">01</span><h3>Establish the device and its capabilities</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="01-01">01-01</span><span class="paragraph-text">Identify maps device and namespace capabilities; logs add status and changes. Know the target of each query before interpreting its response.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>namespace</dt><dd>Namespace, a formatted quantity of non-volatile memory accessed by a host through a controller.</dd></div></dl></article>
<article><span class="axis-number">02</span><h3>Arrange commands and configure behavior</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="02-01">02-01</span><span class="paragraph-text">Abort, AER, firmware, Format, Security, Features, and PCIe queues solve different management problems; they are not a mandatory sequence for every operation.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>PCIe</dt><dd>PCI Express, the transport and device interconnect used by an NVMe memory-based controller.</dd></div><div><dt>AER</dt><dd>Asynchronous Event Request: an NVMe Admin command posted in advance so that the controller can later complete it to report an event.</dd></div></dl></article>
<article><span class="axis-number">03</span><h3>Compare I/O by data flow</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="03-01">03-01</span><span class="paragraph-text">Read returns data, Write supplies it, Compare supplies expected data, Verify returns no normal payload, and Copy supplies descriptors. Compare all eight commands by direction and result.</span></p></article>
<article><span class="axis-number">04</span><h3>Understand what a result guarantees</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="04-01">04-01</span><span class="paragraph-text">Completion, immediate abort, matching content, persistence, and atomicity are distinct evidence. Bound each by target range, ordering, and format conditions.</span></p></article>
</div>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.02">00.02.</span><span class="paragraph-text">The audience knows operating systems and computer organization. Examples assume 4096-byte LBAs where stated; actual formats still come from Identify. The five existing specialist reports remain separate.</span></p>
<div class="overview-connections"><h3>Connecting the main ideas</h3>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.03">00.03.</span><span class="paragraph-text">For learning, connect capabilities → settings → operations → results. For the live specification report, follow Base 5 → Base 7 → selected NVM sections. The former builds understanding; the latter reduces page movement.</span></p>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.04">00.04.</span><span class="paragraph-text">Avoid repeatedly switching between common and command-set-specific definitions. Explain Format scope in Base and complete PIL/PI/MSET in the NVM part. Resolve those earlier questions together, switching documents only once.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>PI</dt><dd>Protection Information: Guard and tag fields used to check data and its associated information.</dd></div></dl>
</div>

<section class="lesson" id="module-adminio-command-map"><h2 id="heading-adminio-command-map"><span class="section-number">01</span> Separate management from data commands</h2>

<section class="lesson" id="module-adminio-abort"><h2 id="heading-adminio-abort"><span class="section-number">02</span> Abort: requesting and confirming termination</h2>
<!-- claim:ADMINIO-ABORT -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="02.01">02.01.</span><span class="paragraph-text">Abort identifies the original command by SQID and CID. A successful Abort CQE does not guarantee immediate termination; interpret IANP and the original command’s CQE separately.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>IANP</dt><dd>Immediate Abort Not Performed: 1 means immediate abort was not performed; 0 means it was.</dd></div><div><dt>SQID</dt><dd>Submission Queue Identifier, the numeric identifier of the SQ containing a command.</dd></div><div><dt>CID</dt><dd>Command Identifier, used with the SQ identifier to identify an outstanding command.</dd></div><div><dt>CQE</dt><dd>Completion Queue Entry, one completion-result structure in a CQ.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §5.2.1</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §5.2.1, printed pages 181-182, PDF pages 207-208</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="02.02">02.02.</span><span class="paragraph-text">For SQID=3 and CID=7, CDW10 is (7&lt;&lt;16)|3 = 00070003h. Even with successful Abort status, IANP=1 requires following the original command’s completion.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>CDW</dt><dd>CDW (Command Dword): a 32-bit command field. In CDW10, 10 is the field index, not a byte offset.</dd></div></dl></aside>
</section>
<section class="lesson" id="module-adminio-aer"><h2 id="heading-adminio-aer"><span class="section-number">03</span> AER: delivering events to the host</h2>
<figure><figcaption><strong>A typical event: notification precedes full log retrieval</strong></figcaption><ol class="flow-steps"><li>The host posts AERs so requests are available for completion.</li><li>An event completes an AER with AET/AEI/LID.</li><li>The host reads the associated log and validates its fields.</li><li>Clear the event according to its rules and maintain the required outstanding AERs.</li></ol><figcaption>This applies to the corresponding ordinary events; Immediate and One Shot exceptions are explained separately.</figcaption></figure>
<dl class="term-note" aria-label="Terms in this passage"><div><dt>AEI</dt><dd>Asynchronous Event Information: its meaning depends on the event type selected by AET.</dd></div><div><dt>AET</dt><dd>Asynchronous Event Type: selects the category in which event information is interpreted.</dd></div><div><dt>LID</dt><dd>Log Page Identifier: selects the type of log page to read.</dd></div></dl>
<!-- claim:ADMINIO-AER -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="03.01">03.01.</span><span class="paragraph-text">The host first submits an Asynchronous Event Request; the controller later completes it to report an event. Event type, event information, associated LID, and Event Specific Parameter determine the next observation.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>controller</dt><dd>Controller, the entity that implements the NVMe interface, fetches commands, and reports completions.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §5.2.2</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §5.2.2, printed pages 183-191, PDF pages 209-217</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="03.02">03.02.</span><span class="paragraph-text">A Firmware Activation Starting notice announces activation. <details class="review-question" id="qa-adminio-abort"><summary>1. Successful Abort status with IANP=1: may the original buffer be reclaimed immediately?</summary>

<details class="review-question" id="qa-adminio-lengths"><summary>2. How are eight blocks encoded for Read and a DSM range?</summary>
<div data-qa-answer="adminio-lengths"><p class="reader-paragraph review-answer"><span class="paragraph-number" aria-label="17.02">17.02.</span><span class="paragraph-text">Read uses NLB=7; a DSM range uses LLB=8. <details class="review-question" id="qa-adminio-format"><summary>3. Why can Format with NSID=3 affect other namespaces?</summary>
<div data-qa-answer="adminio-format"><p class="reader-paragraph review-answer"><span class="paragraph-number" aria-label="17.03">17.03.</span><span class="paragraph-text">SES selects the relevant FNS or SENS branch. <!-- qa:adminio-queue -->
<details class="review-question" id="qa-adminio-queue"><summary>4. Why is an empty shared CQ insufficient justification for deleting it?</summary>
<div data-qa-answer="adminio-queue"><p class="reader-paragraph review-answer"><span class="paragraph-number" aria-label="17.04">17.04.</span><span class="paragraph-text">Emptiness means there are no completions to consume now, not that no SQ references it. Remove referencing SQs and satisfy completion/lifetime requirements before deleting the CQ.</span></p></div>
