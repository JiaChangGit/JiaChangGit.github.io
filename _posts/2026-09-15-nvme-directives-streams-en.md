<section id="topic-overview" class="topic-overview">
<p class="reader-paragraph opening"><span class="paragraph-number" aria-label="00.01">00.01.</span><span class="paragraph-text">This report explains how a host tells an SSD which data belongs together. Establish the relationships among host, controller, namespace, and stream, then follow capability checks, enablement, allocation, writes, and release. Finally examine identifier sharing across paths and the meaning of SWS/SGS for data organization.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>controller</dt><dd>Controller, the entity that implements the NVMe interface, fetches commands, and reports completions.</dd></div><div><dt>namespace</dt><dd>Namespace, a formatted quantity of non-volatile memory accessed by a host through a controller.</dd></div><div><dt>Host</dt><dd>The system running the operating system and issuing NVMe commands.</dd></div><div><dt>SGS</dt><dd>Stream Granularity Size; allocation granularity measured in SWS units.</dd></div><div><dt>SWS</dt><dd>Stream Write Size; the optimal write alignment/size unit, measured in logical blocks for NVM.</dd></div></dl>
<h2 id="main-ideas">The main ideas</h2>
<div class="topic-map">
<article><span class="axis-number">01</span><h3>Why group data?</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="01-01">01-01</span><span class="paragraph-text">A Stream Identifier adds a relationship between writes while LBA still selects the destination. A stream is not another namespace.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Stream Identifier</dt><dd>A host-selected 16-bit grouping label interpreted with namespace, host identity, and sharing configuration.</dd></div></dl></article>
<article><span class="axis-number">02</span><h3>Management and data flow</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="02-01">02-01</span><span class="paragraph-text">Capability queries, identity registration, enablement, and allocation prepare the system; tagged Writes actually use streams. Management commands are not repeated for every payload.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>payload</dt><dd>Data carried by a command transfer, distinct from command fields and completion values.</dd></div></dl></article>
<article><span class="axis-number">03</span><h3>Identity and resource sharing</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="03-01">03-01</span><span class="paragraph-text">Host Identifier and SSID determine which paths share a stream. NSA, NSSA, and NSO distinguish capacity, the resource pool, and current use.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Host Identifier</dt><dd>The identity used to associate controllers with a host, distinct from a Stream Identifier.</dd></div><div><dt>NSSA</dt><dd>NVM Subsystem Streams Available; the non-exclusively allocated pool size, not its idle-resource count.</dd></div><div><dt>SSID</dt><dd>Shared Stream Identifiers; controls sharing of equal identifiers across nonzero host identities within a namespace.</dd></div><div><dt>NSA</dt><dd>Namespace Streams Allocated; the exclusive allocation for the namespace and visible host association, also returned by Allocate.</dd></div><div><dt>NSO</dt><dd>Namespace Streams Open; the open count for the selected namespace and visible host association.</dd></div></dl></article>
<article><span class="axis-number">04</span><h3>Size and lifetime</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="04-01">04-01</span><span class="paragraph-text">SWS/SGS guide writes and deallocation. Release, disablement, and reset affect tracking state independently of the continued existence of user data.</span></p></article>
</div>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.02">00.02.</span><span class="paragraph-text">The assumed background is operating systems, computer organization, and basic SSD concepts. Examples use PCIe controllers and cover the specified Directives/Streams scope, excluding Data Placement §8.1.9.4. Counts, LBAs, and host labels are illustrative; actual capabilities come from the device.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Directives</dt><dd>A mechanism for exchanging additional host/controller information, with type-specific management and I/O semantics.</dd></div><div><dt>Streams</dt><dd>A Directive that groups related writes using stream identifiers without selecting physical NAND addresses.</dd></div><div><dt>PCIe</dt><dd>PCI Express, the transport and device interconnect used by an NVMe memory-based controller.</dd></div></dl>
<div class="overview-connections"><h3>Connecting the main ideas</h3>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.03">00.03.</span><span class="paragraph-text">Follow a complete data-use cycle: decide which data is related, verify support, establish host identities and enablement, and choose a resource source. Writes create stream activity; release ends an identifier’s current grouping when it is no longer needed.</span></p>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.04">00.04.</span><span class="paragraph-text">Equal numbers need not mean equal things: the same Stream Identifier may belong to different hosts, and SWS=8 versus NSA=8 means data size versus resource count. The examples hold other conditions fixed while changing one factor.</span></p>
</div>

<section class="lesson" id="module-streams-model"><h2 id="heading-streams-model"><span class="section-number">01</span> What Streams communicates</h2>

<section class="lesson" id="module-streams-sizes"><h2 id="heading-streams-sizes"><span class="section-number">08</span> Convert SWS and SGS into data sizes</h2>
