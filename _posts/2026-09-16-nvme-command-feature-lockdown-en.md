<section id="topic-overview" class="topic-overview">
<p class="reader-paragraph opening"><span class="paragraph-number" aria-label="00.01">00.01.</span><span class="paragraph-text">Command and Feature Lockdown defines which management operations are prohibited, on which incoming interfaces and controllers. Connect capability checks, current state and state-changing commands, then determine how prohibitions end and whether they survive power cycles. One FID example leads from the overall process to command fields, both log formats and persistence exceptions.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Lockdown</dt><dd>Command and Feature Lockdown restricts management operations by operation class, incoming interface and controller scope.</dd></div><div><dt>FID</dt><dd>Feature Identifier: selects the Feature to read or configure.</dd></div></dl>
<h2 id="main-ideas">The main ideas</h2>
<div class="topic-map">
<article><span class="axis-number">01</span><h3>Discover what can be restricted</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="01-01">01-01</span><span class="paragraph-text">First check whether the device supports subsystem-wide or controller-scoped restrictions, then find eligible operations. Capability, command support and prohibitable eligibility are separate questions.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>controller</dt><dd>A controller receives and processes NVMe commands; one subsystem may contain several.</dd></div></dl></article>
<article><span class="axis-number">02</span><h3>Specify the affected scope</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="02-01">02-01</span><span class="paragraph-text">Select the operation, incoming interface and controllers in turn. Restricting one setting, one interface or one controller produces different affected scopes.</span></p></article>
<article><span class="axis-number">03</span><h3>Verify with the right query</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="03-01">03-01</span><span class="paragraph-text">Basic format reports common all-controller items. Enhanced format selects a controller or aggregates all and distinguishes whether each item applies to every controller. Match query conditions before comparing.</span></p></article>
<article><span class="axis-number">04</span><h3>Follow the restriction lifecycle</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="04-01">04-01</span><span class="paragraph-text">A command can remove a restriction. Survival across a power cycle also depends on the original controller scope and persistence settings. Finally, account for authenticated-unfreeze exceptions and vendor definitions.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>power cycle</dt><dd>A power cycle of the specified subsystem, distinct from an ordinary Controller Reset.</dd></div></dl></article>
</div>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.02">00.02.</span><span class="paragraph-text">Assumes operating systems, computer organization and basic SSD knowledge. The main context is PCIe host administration; Management Endpoint coverage is limited to the relationships defined by Base. Controller identifiers, eligibility lists and command encodings are illustrative and depend on actual device support.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Management Endpoint</dt><dd>An out-of-band management endpoint, selected separately from the host Admin Submission Queue.</dd></div><div><dt>Host</dt><dd>The system running the operating system and issuing NVMe commands.</dd></div><div><dt>PCIe</dt><dd>PCI Express, the transport and device interconnect used by an NVMe memory-based controller.</dd></div></dl>
<div class="overview-connections"><h3>Connecting the main ideas</h3>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.03">00.03.</span><span class="paragraph-text">Follow one question: to restrict controller 7 from setting FID 06h through its Admin Queue, which capabilities must be checked, which parameters must be sent, and which response confirms the restriction?</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Admin</dt><dd>Administrative, the control path used to create, configure, query, or manage controllers and queues.</dd></div></dl>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.04">00.04.</span><span class="paragraph-text">This sequence gives each list, selector and result a purpose. Log sizes, controller identifiers, operation codes and UUID indices are kept distinct throughout the examples.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>UUID</dt><dd>Universally Unique Identifier; a 128-bit value distinguishing vendor definitions in this context.</dd></div></dl>
</div>

<section class="lesson" id="module-lockdown-model"><h2 id="heading-lockdown-model"><span class="section-number">01</span> Start with the operation and its incoming interface</h2>
<figure><figcaption><strong>From intent to a verified restriction</strong></figcaption><ol class="flow-steps"><li>Specify the operation, incoming interface and controller set.</li><li>Check CFLS/CCFLS, then read the eligible-item list in LID14h.</li><li>Submit Lockdown with the selectors and PRHBT; await completion.</li><li>Read current prohibitions for the same scope to verify the result.</li><li>Matching later commands are rejected; allowance and power cycles follow lifecycle rules.</li></ol><figcaption>Queries observe, Lockdown changes state, and later commands encounter the restriction. <!-- claim:LOCKDOWN-MODEL -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="01.01">01.01.</span><span class="paragraph-text">Command and Feature Lockdown restricts selected management commands or Set Features operations targeting a particular FID. Each restriction has an operation class, incoming interface and controller scope. LID 14h reports what can be prohibited and what is currently prohibited; Lockdown changes that state.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>LID</dt><dd>Log Page Identifier: selects the type of log page to read.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §8.1.5</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §8.1.5, printed pages 597-599, PDF pages 623-625</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="01.02">01.02.</span><span class="paragraph-text">Assume FID 06h is prohibitable. Restricting Set Features for FID 06h differs from restricting the entire Set Features opcode: the former does not by itself prohibit setting other FIDs or reading with Get Features.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>opcode</dt><dd>An operation code selecting the command whose remaining fields supply its parameters.</dd></div></dl></aside>
</section>
<section class="lesson" id="module-lockdown-capability"><h2 id="heading-lockdown-capability"><span class="section-number">02</span> Check capability level before choosing an item</h2>
<!-- claim:LOCKDOWN-CAPABILITY -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="02.01">02.01.</span><span class="paragraph-text">OACS.CFLS advertises basic Lockdown support, while CCFLS advertises controller-scoped support. CFLS requires CSEL=0 and LID 14h; CCFLS additionally requires CSEL=1/2 and the enhanced log. The list still determines whether an individual OFI is prohibitable.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>CSEL</dt><dd>Controller Select; chooses all controllers, one controller or a primary’s secondaries.</dd></div><div><dt>OACS</dt><dd>Optional Admin Command Support; the Identify Controller capability bitmap for optional Admin commands and features.</dd></div><div><dt>OFI</dt><dd>Opcode or Feature Identifier; the target code interpreted according to SCP.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §8.1.5</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §8.1.5, printed pages 599, PDF pages 625</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="02.02">02.02.</span><span class="paragraph-text">Considering only OACS bits 13 and 10, 2400h sets both CCFLS and CFLS, while 0400h advertises only basic support. The latter does not guarantee CSEL=1 or ELPF=1.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>ELPF</dt><dd>Enhanced Log Page Format; selects the basic or enhanced LID14h structure.</dd></div></dl></aside>
</section>

<p class="reader-paragraph"><span class="paragraph-number" aria-label="03.01">03.01.</span><span class="paragraph-text">IFC selects the incoming interface: 00b is the Admin Submission Queue, 01b adds the Management Endpoint, and 10b is the Management Endpoint only. CSEL selects all controllers, one controller, or a primary controller’s secondaries; CSS supplies the required controller identifier.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Admin Submission Queue</dt><dd>The queue through which the host submits Admin commands, also shortened to Admin Queue here.</dd></div><div><dt>primary</dt><dd>A primary controller whose identifier can select its associated secondary controllers with CSEL=2.</dd></div><div><dt>CSS</dt><dd>Controller Select Specific; supplies the controller or primary identifier required by CSEL in this command.</dd></div><div><dt>IFC</dt><dd>Interface; selects where an incoming operation is subject to the restriction.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §5.2.16</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §5.2.16, printed pages 406-407, PDF pages 432-433</p></details>

The controller processing Lockdown need not be confused with the selected target, and IFC describes where the restricted command is received.</span></p></aside>

<section class="lesson" id="module-lockdown-query"><h2 id="heading-lockdown-query"><span class="section-number">04</span> Ask a precise question with LID 14h</h2>
<!-- claim:LOCKDOWN-QUERY -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="04.01">04.01.</span><span class="paragraph-text">For LID 14h, SCP selects the item class; CNTTS=00b requests prohibitable items, 01b current Admin Queue prohibitions, and 10b current Management Endpoint prohibitions. ELPF selects the basic or enhanced format. Enhanced requests use LSI.CNTLID, with FFFFh selecting all controllers.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>CNTLID</dt><dd>Controller Identifier; FFFFh selects all controllers for this enhanced-log query.</dd></div><div><dt>CNTTS</dt><dd>Contents; selects eligibility or current prohibitions on a particular incoming interface.</dd></div><div><dt>LSI</dt><dd>Log Specific Identifier; a sixteen-bit identifier interpreted according to the requested log.</dd></div><div><dt>SCP</dt><dd>Scope; selects the code class: Admin opcode, Set Features FID or a management-interface command set.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §5.2.13.1.20</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §5.2.13.1.20, printed pages 279-280, PDF pages 305-306</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="04.02">04.02.</span><span class="paragraph-text">A 512-byte basic request for currently prohibited Admin Queue FIDs uses LID=14h, SCP=2, CNTTS=1, ELPF=0 and NUMD=127, giving CDW10=007F1214h. Reading the log does not add prohibitions.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>NUMD</dt><dd>Number of Dwords; the Get Log transfer count encoded as Dwords minus one.</dd></div></dl></aside>
</section>

<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="05.02">05.02.</span><span class="paragraph-text">Header and list bytes 12 00 00 02 06 07 mean CFILA=12h: currently prohibited Admin Queue FIDs. <section class="lesson" id="module-lockdown-result"><h2 id="heading-lockdown-result"><span class="section-number">08</span> Separate a rejected configuration from a prohibited command</h2>
<!-- claim:LOCKDOWN-RESULT -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="08.01">08.01.</span><span class="paragraph-text">The Lockdown request can fail because the item is not prohibitable, an interface does not support it, or a controller selection is invalid. Command-specific 28h means Prohibition of Command Execution Not Supported and 1Fh means Invalid Controller Identifier. A subsequently prohibited Admin command instead returns the generic Command Prohibited by Command and Feature Lockdown status.</span></p><details class="source-note"><summary>Sources: Base 2.4 §5.2.16</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §5.2.16, printed pages 407-408, PDF pages 433-434</p></details>
<!-- claim:LOCKDOWN-PROHIBITED-EXECUTION -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="08.02">08.02.</span><span class="paragraph-text">A prohibited operation received on the Admin Queue is aborted with Command Prohibited by Command and Feature Lockdown; a Management Endpoint returns an Access Denied Error Response.</span></p><details class="source-note"><summary>Sources: Base 2.4 §8.1.5</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §8.1.5, printed pages 598, PDF pages 624</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="08.03">08.03.</span><span class="paragraph-text">Lockdown may succeed and the later Set Features fail with SCT=0, SC=23h. If Lockdown itself returns SCT=1, SC=28h because the OFI is not prohibitable, there is no successful configuration result. These failures describe different operations.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>SCT</dt><dd>Status Code Type: selects the completion-status category and is interpreted with SC.</dd></div><div><dt>SC</dt><dd>Status Code: identifies the completion result within the selected SCT category.</dd></div></dl></aside>

<section class="lesson" id="module-lockdown-persistence"><h2 id="heading-lockdown-persistence"><span class="section-number">09</span> Follow restrictions across allowance and power cycles</h2>
<figure><figcaption><strong>Which prohibitions survive one subsystem power cycle?</strong></figcaption><div class="table-wrap"><table><thead><tr><th scope="col">CSEL used to prohibit</th><th scope="col">Lockdown Persistence</th><th scope="col">Rule after the power cycle</th></tr></thead><tbody><tr><td>0: all controllers</td><td>Enabled</td><td>Persists; subsequent Lockdown can allow</td></tr><tr><td>0: all controllers</td><td>Disabled</td><td>Does not persist across the power cycle</td></tr><tr><td>1: one controller</td><td>Either state</td><td>LDPE1 does not grant power-cycle persistence</td></tr><tr><td>2: a primary’s secondaries</td><td>Either state</td><td>Ends at a power cycle or subsequent allowance</td></tr></tbody></table></div><figcaption>This compares power cycles, not ordinary Controller Resets. The prose separately explains freeze and authentication conditions. Source: Base §8.1.5.</figcaption></figure>

<!-- claim:LOCKDOWN-PERSISTENCE -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="09.01">09.01.</span><span class="paragraph-text">A CSEL=0 prohibition persists across power cycles when Lockdown Persistence is enabled; otherwise it lasts until a subsystem power cycle or subsequent allowance. CSEL=1/2 prohibitions last until a power cycle or allowance and do not inherit subsystem-wide power-cycle persistence from LDPE=1.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>LDPE</dt><dd>Lockdown Persistence Enable; enables power-cycle persistence for all-controller prohibitions.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §8.1.5</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §8.1.5, printed pages 598-599, PDF pages 624-625</p></details>
<!-- claim:LOCKDOWN-PERSISTENCE-EXCEPTIONS -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="09.02">09.02.</span><span class="paragraph-text">With persistence enabled, an unfrozen Lockdown Persistence Personality or one without authenticated unfreeze support prevents Lockdown from prohibiting Set Features or FID 22h. If any personality supports authenticated unfreeze, the specified CDP Authentication Security Send/Receive operations remain allowed.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>personality</dt><dd>A device configuration defined by the specification; this report focuses on Lockdown Persistence.</dd></div><div><dt>CDP</dt><dd>Configurable Device Personality; provides device configurations with query, change and freeze state.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §5.2.30.1.25.4.1</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §5.2.30.1.25.4.1, printed pages 494, PDF pages 520</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="09.03">09.03.</span><span class="paragraph-text">With Lockdown Persistence enabled, suppose CSEL=0 prohibits FID 06h and CSEL=1 prohibits FID 07h. After a subsystem power cycle, the first persists under the all-controller rule; the second does not gain power-cycle persistence from that setting.</span></p></aside>
</section>
<section class="lesson" id="module-lockdown-uuid"><h2 id="heading-lockdown-uuid"><span class="section-number">10</span> Select the intended vendor definition with a UUID</h2>
<!-- claim:LOCKDOWN-UUID -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="10.01">10.01.</span><span class="paragraph-text">For a vendor-specific FID, Lockdown uses CDW14.UIDX when SCP=2 and UUID selection is supported for the commands and item involved. LID 14h can likewise use UIDX for vendor FIDs with SCP=2; other scopes ignore it. UIDX is a UUID List index, not a FID or byte offset.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>byte offset</dt><dd>Distance in bytes from a structure’s start; index two need not mean byte offset two.</dd></div><div><dt>index</dt><dd>index: selects an item or format in a list. It answers “which one,” not “how far from the start.”</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §5.2.16</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §5.2.16, printed pages 406-407, PDF pages 432-433</p></details>
<!-- claim:LOCKDOWN-UUID-VALIDITY -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="10.02">10.02.</span><span class="paragraph-text">UIDX=0 selects no UUID. A nonzero index must identify a valid UUID supported for the information; zero, NVMe Invalid UUID or an unsupported UUID produces Invalid Field in Command.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>NVMe</dt><dd>Non-Volatile Memory Express, the specification family for a host interface to a non-volatile-memory subsystem.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §8.1.31.2</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §8.1.31.2, printed pages 737-738, PDF pages 763-764</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="10.03">10.03.</span><span class="paragraph-text">If two vendor definitions both use FID C0h and UUID List entry 2 identifies the intended definition, use UIDX=2. Neither FID C0h nor that entry’s byte offset 64 belongs in UIDX.</span></p></aside>
