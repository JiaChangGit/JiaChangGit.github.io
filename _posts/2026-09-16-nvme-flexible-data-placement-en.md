<section id="topic-overview" class="topic-overview">
<p class="reader-paragraph opening"><span class="paragraph-number" aria-label="00.01">00.01.</span><span class="paragraph-text">FDP translates the host’s knowledge of which data expires together into placement choices the SSD can use. This report connects reclamation cost, configuration, namespace mappings, Writes, RUH updates, and the status, statistics and events used to assess the result. Follow a PID to its current RU and distinguish changes to a reference, logical data, or the group configuration.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>namespace</dt><dd>Namespace, a formatted quantity of non-volatile memory accessed by a host through a controller.</dd></div><div><dt>Host</dt><dd>The system running the operating system and issuing NVMe commands.</dd></div><div><dt>FDP</dt><dd>Flexible Data Placement; host-directed organization of placement to reduce reclamation relocation.</dd></div><div><dt>PID</dt><dd>Placement Identifier; A 16-bit PID containing PHNDL and, according to the configuration, RGID.</dd></div><div><dt>RUH</dt><dd>Reclaim Unit Handle; A handle, abbreviated RUH, referencing one current RU in each RG.</dd></div><div><dt>RU</dt><dd>Reclaim Unit; A media unit, abbreviated RU, that receives a group of data in the FDP model.</dd></div></dl>
<h2 id="main-ideas">The main ideas</h2>
<div class="topic-map">
<article><span class="axis-number">01</span><h3>Why place data together?</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="01-01">01-01</span><span class="paragraph-text">Start with valid-data relocation cost, then separate RG, RUH and RU and compare initial versus persistent isolation. These define grouping and relocation constraints.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>RG</dt><dd>Reclaim Group; A group, abbreviated RG, containing Reclaim Units.</dd></div></dl></article>
<article><span class="axis-number">02</span><h3>From configuration to one Write</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="02-01">02-01</span><span class="paragraph-text">A configuration defines resources and PID layout. The namespace maps PHNDL to RUH, and the Data Placement Directive lets a Write choose RG and PHNDL.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>PHNDL</dt><dd>Placement Handle; a namespace-local mapping index that selects a RUHID.</dd></div></dl></article>
<article><span class="axis-number">03</span><h3>Data lifetime and host control</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="03-01">03-01</span><span class="paragraph-text">Status observes available writes, Update selects an empty RU, and DSM describes expired LBAs. Their distinct roles work together to reduce reclamation cost.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>DSM</dt><dd>Dataset Management: host hints about use and allocation of data ranges.</dd></div></dl></article>
<article><span class="axis-number">04</span><h3>Observe actual behavior</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="04-01">04-01</span><span class="paragraph-text">Usage shows allocation origin, Statistics measures cumulative work, and Events records causes and locations. Check scope, interval and validity before interpreting values.</span></p></article>
</div>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.02">00.02.</span><span class="paragraph-text">Assumes operating systems, computer organization and basic SSD knowledge. Examples use PCIe and the NVM Command Set. Counts and encodings are illustrative; device responses define actual capabilities. Necessary references explain the fields and conditions needed for FDP without expanding into unrelated topics.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>PCIe</dt><dd>PCI Express, the transport and device interconnect used by an NVMe memory-based controller.</dd></div><div><dt>NVM</dt><dd>Non-Volatile Memory, memory that retains data without power.</dd></div></dl>
<div class="overview-connections"><h3>Connecting the main ideas</h3>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.03">00.03.</span><span class="paragraph-text">Follow one data batch: group by expected expiration, configure resources and mappings, and use a PID to select the current RU. Filling it or issuing Update moves future writes to another RU. When the old data expires and the host describes deallocation is a separate, equally important part of the lifecycle.</span></p>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.04">00.04.</span><span class="paragraph-text">The explanation follows this data path before returning each specification structure to the question it answers. Data sizes, resource counts, list indices and zero-based count encodings are kept distinct.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>zero-based</dt><dd>zero-based: numbering starts at zero, so raw=3 can mean the fourth item or four units; the field definition still decides which.</dd></div></dl>
</div>

<section class="lesson" id="module-fdp-isolation"><h2 id="heading-fdp-isolation"><span class="section-number">02</span> Isolation before and after internal relocation</h2>
<figure><figcaption><strong>Same RG: changing only the isolation type</strong></figcaption><div class="table-wrap"><table><thead><tr><th scope="col">RUH type</th><th scope="col">New data from X and Y</th><th scope="col">After relocating old X/Y data</th></tr></thead><tbody><tr><td>Initially Isolated</td><td>Separate RUs</td><td>May share a destination RU</td></tr><tr><td>Persistently Isolated</td><td>Separate RUs</td><td>Must retain separate destination RUs</td></tr></tbody></table></div><figcaption>Both allow relocation within the same RG. <dl class="term-note" aria-label="Terms in this passage"><div><dt>Persistently Isolated</dt><dd>After relocation a destination RU contains only data originally written through the same RUH.</dd></div><div><dt>Initially Isolated</dt><dd>New writes are separated; relocation may combine data from different handles of this type.</dd></div></dl>
<!-- claim:FDP-ISOLATION -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="02.01">02.01.</span><span class="paragraph-text">An RU is referenced by at most one RUH, so new writes using different handles start separately. Initially Isolated handles allow relocated data from different handles of that type to be combined within the same Reclaim Group. Persistently Isolated handles require a destination RU containing only data written through the same handle.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Reclaim Group</dt><dd>Reclaim Group; A group, abbreviated RG, containing Reclaim Units.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §8.1.12.1</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §8.1.12.1, printed pages 649-650, PDF pages 675-676</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="02.02">02.02.</span><span class="paragraph-text">Relocated data from Initially Isolated RUH 1 and RUH 3 may share an RU. If both are Persistently Isolated, their remaining data cannot be combined merely because each has little data left.</span></p></aside>
</section>

<section class="lesson" id="module-fdp-write"><h2 id="heading-fdp-write"><span class="section-number">07</span> Follow one Write, including invalid PIDs</h2>
<!-- claim:FDP-WRITE -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="07.01">07.01.</span><span class="paragraph-text">An explicit-placement Write uses DTYPE=02h and DSPEC=PID while LBA and block count define the logical data.
