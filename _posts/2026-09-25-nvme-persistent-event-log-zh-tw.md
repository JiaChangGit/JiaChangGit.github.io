<section id="topic-overview" class="topic-overview">
<p class="reader-paragraph opening"><span class="paragraph-number" aria-label="00.01">00.01.</span><span class="paragraph-text">裝置重設後，如何知道之前發生過什麼？Persistent Event Log 保存跨重設的重要事件，將健康快照、韌體更新、電源、namespace 與設定變更放進共同的紀錄格式。本篇先說明如何讀出同一份資料，再學會把時間、對象、參數與結果連起來，同時分辨紀錄能證明什麼、不能證明什麼。</span></p><dl class="term-note" aria-label="本段名詞"><div><dt>Persistent Event Log</dt><dd>持久事件紀錄；保存subsystem重要事件的LID 0Dh紀錄。</dd></div><div><dt>namespace</dt><dd>namespace，主機透過 controller 存取的一份已格式化非揮發性容量。</dd></div></dl>
<h2 id="main-ideas">這篇的主軸</h2>
<div class="topic-map">
<article><span class="axis-number">01</span><h3>這份歷史保存什麼</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="01-01">01-01</span><span class="paragraph-text">事件種類支援、保存上限與實際內容是三件事。先認識 subsystem 範圍、持久性與遺漏的可能性，避免把有限紀錄當作完整流水帳。</span></p></article>
<article><span class="axis-number">02</span><h3>一次讀取的生命週期</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="02-01">02-01</span><span class="paragraph-text">建立 context → 讀 header → 分段讀取 → 比對 generation → 釋放。新事件與正在讀的事件集合分開，才能理解為什麼需要context。</span></p><dl class="term-note" aria-label="本段名詞"><div><dt>context</dt><dd>本次讀取使用的回報內容與追蹤資訊；建立後新增的事件不加入其中。</dd></div><div><dt>header</dt><dd>資料前端的共同說明區，記載種類、大小、版本等讀取內容所需資訊。</dd></div></dl></article>
<article><span class="axis-number">03</span><h3>資料的三層結構</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="03-01">03-01</span><span class="paragraph-text">外層log header描述整份報告；共同event header描述一筆事件；ED保存該種類的內容。每一層長度和版本各有用途。</span></p><dl class="term-note" aria-label="本段名詞"><div><dt>ED</dt><dd>Event Data，扣除共同header與廠商附加資訊後的事件內容。</dd></div></dl></article>
<article><span class="axis-number">04</span><h3>從事件還原合理的關係</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="04-01">04-01</span><span class="paragraph-text">按健康、時間／重設、儲存變更、清除、硬體及設定分組。一起看對象、動作和結果，不以單一名稱、百分比或時間戳推論成功。</span></p></article>
<article><span class="axis-number">05</span><h3>Base 與 NVM 怎麼接起來</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="05-01">05-01</span><span class="paragraph-text">Base提供Namespace Change外框，NVM補定FLBAS與DPS。最後再學廠商擴充，遇到未知內容也能辨認範圍並保留原始資料。</span></p><dl class="term-note" aria-label="本段名詞"><div><dt>FLBAS</dt><dd>Formatted LBA Size，保存格式編號與metadata傳輸方式，不是直接記錄bytes大小。</dd></div><div><dt>DPS</dt><dd>End-to-end Data Protection Type Settings，資料保護資訊的類型及位置設定。</dd></div><div><dt>NVM</dt><dd>Non-Volatile Memory，斷電後仍能保存資料的記憶體。</dd></div></dl></article>
</div>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.02">00.02.</span><span class="paragraph-text">適合已學過OS、Computer Organization並了解SSD基本概念的讀者。文中的控制器A／B、namespace7及示範數值只用來說明規則，不代表每台裝置都有相同配置。</span></p>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.03">00.03.</span><span class="paragraph-text">中文教學版以循序推理與欄位案例深入學習；中英文post先建立全局觀念，再接續順向Spec報告路徑。主範圍固定為上述兩節，其他來源只補足理解事件所需的欄位。</span></p>
<div class="overview-connections"><h3>把主軸連起來</h3>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.04">00.04.</span><span class="paragraph-text">可以把整篇想成五個連續問題：這台裝置會記什麼；這次讀到哪一份；每筆從哪裡開始；事件內容代表什麼；最後能做出什麼有根據的判斷。前一個問題沒弄清楚，後面的數字就容易讀錯。</span></p>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.05">00.05.</span><span class="paragraph-text">本文用流程圖說明context，用資料區塊圖說明長度，用時間與對象的對比解釋事件。規格欄位很多時採分組表格，共用格式只解釋一次，再由每張圖的獨立案例連回。</span></p>
</div>

<section class="lesson" id="module-pel-purpose"><h2 id="heading-pel-purpose"><span class="section-number">01</span> 先分清事件歷史、目前狀態與完整性</h2>
<!-- claim:PEL-PURPOSE -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="01.01">01.01.</span><span class="paragraph-text">Persistent Event Log（PEL，LID 0Dh）保存 NVM subsystem 的重要事件，跨 power cycle 與 reset 保留。它不是每筆 I/O 的流水帳，也不是永遠不會遺失的完整歷史：容量、同類事件數量、頻率抑制與淘汰策略由廠商決定，Sanitize 也可能移除或修改紀錄。</span></p><dl class="term-note" aria-label="本段名詞"><div><dt>NVM subsystem</dt><dd>NVM subsystem，包含 controller、port、namespace 與非揮發性儲存資源的 NVMe 系統邊界。</dd></div><div><dt>power cycle</dt><dd>斷電再上電的電源循環；不等同所有形式的reset。</dd></div><div><dt>I/O</dt><dd>Input/Output，對 namespace 執行資料輸入與輸出的操作類別。</dd></div><div><dt>LID</dt><dd>Log Page Identifier；指定要讀取哪一種 log page 的編號。</dd></div><div><dt>PEL</dt><dd>Persistent Event Log，本篇的持久事件紀錄。</dd></div></dl><details class="source-note"><summary>來源：Base 2.4 §5.2.13.1.14</summary><p>來源：NVME-BASE-2.4, Rev. 2.4, §5.2.13.1.14, 文件頁 244-245, PDF 頁 270-271</p></details>
<aside class="worked-example"><h3>說明性範例</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="01.02">01.02.</span><span class="paragraph-text">說明性範例：PELS=4 表示最大 256 KiB；本次 TLL=4096、TNEV=9，則只回報 4 KiB、9 筆事件。不能拿最大空間當本次長度，也不能拿 9 當事件種類數。</span></p><dl class="term-note" aria-label="本段名詞"><div><dt>PELS</dt><dd>Persistent Event Log Size，最大PEL空間，以64KiB為單位。</dd></div><div><dt>TNEV</dt><dd>Total Number of Events，本次回報實際包含的事件筆數。</dd></div><div><dt>TLL</dt><dd>Total Log Length，這份回報包含header在內的總byte長度。</dd></div></dl></aside>
</section>

<section class="lesson" id="module-pel-health"><h2 id="heading-pel-health"><span class="section-number">04</span> 健康、Telemetry 與溫度各留下什麼證據</h2>
<figure><figcaption><strong>三種事件，回答三個問題</strong></figcaption><div class="table-wrap"><table><thead><tr><th scope="col">事件</th><th scope="col">保存什麼</th><th scope="col">可以回答什麼</th></tr></thead><tbody><tr><td>01h SMART</td><td>512-byte健康快照</td><td>當時的健康與累計量</td></tr><tr><td>0Ch Telemetry</td><td>診斷資料的前512-byte header</td><td>當時捕捉了哪一份資料，邊界為何</td></tr><tr><td>0Dh Thermal</td><td>門檻代碼與相對溫差</td><td>跨過哪種門檻或改變哪種熱管理狀態</td></tr></tbody></table></div><figcaption>Telemetry事件未保存資料blocks；Thermal事件也不是另一份完整SMART。來源：Base Figures237、254、255。</figcaption></figure>

<p class="reader-paragraph"><span class="paragraph-number" aria-label="04.01">04.01.</span><span class="paragraph-text">ET=01h 保存 512-byte SMART 快照，記錄間隔不得超過 24 power-on hours；ET=0Ch 可保存新建 Telemetry 的前 512 bytes，並不包含完整診斷資料。ET=0Dh 記錄溫度門檻事件，其 OTMP 是相對門檻的 Kelvin 差值，不是絕對溫度。這些都是事件當時的資料。</span></p><details class="source-note"><summary>來源：Base 2.4 §5.2.13.1.14.2.1; 5.2.13.1.14.2.12; 5.2.13.1.14.2.13</summary><p>來源：NVME-BASE-2.4, Rev. 2.4, §5.2.13.1.14.2.1; 5.2.13.1.14.2.12; 5.2.13.1.14.2.13, 文件頁 252,264-266, PDF 頁 278,290-292</p></details>
