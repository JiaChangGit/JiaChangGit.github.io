<section id="ea"><h2>EA 的 entry 如何描述一段資源？</h2><dl class="st-terms" aria-label="本段名詞"><div><dt>EA</dt><dd>Enhanced Allocation，增強資源配置</dd></div></dl><p>EA（Enhanced Allocation，增強配置）在適用的永久連接拓樸中，以 entry 描述資源。先看 Figure 6-26 確認 Function 和 Bridge 兩側是否適用，再從 §7.8.5 找 entry。Type 0 的第一筆 entry 位於 Capability 起點加 04h；Type 1 有額外的第二個 DWORD，第一筆從 08h 開始。</p><p><strong>【模擬資料】</strong>假設另一個永久連接的 Type 0 Function，其 EA 起點為 E，第一筆 entry 的三個 DWORD 依序為 80FF0022h、A0000000h、0000FFFCh。Figure 7-168／Table 7-148 顯示 Entry Size=2，表示首個 DWORD 後面還有兩個 DWORD，所以這筆共 12 bytes，下一筆從 E+10h 開始。BEI（BAR Equivalent Indicator，對應 BAR 的編號）=2 指向 offset 18h；Enable=1，Writable=0。Primary Properties=00h 是 Non-Prefetchable Memory，Secondary Properties=FFh 表示須使用 Primary 定義。</p><p>再看 Figure 7-169：Base 與 MaxOffset 的 Field Size 均為 0，兩者都是 32-bit。Base 的低兩個地址位元補 00b，得到 A0000000h；MaxOffset 的低兩位補 11b，得到 0000FFFFh。因此涵蓋 A0000000h–A000FFFFh，共 64 KiB。這是該 entry 的資源範圍；對應的 BAR2 必須硬接為零，不能把同一筆資源再算成另一個 BAR 需求。</p><p>Enable=0 不表示這段資源可轉配給其他 Function。Bridge 的 EA 也不必列出所有下游資源，軟體仍須搜尋下游 Function；Memory Space Enable 與 I/O Space Enable 的規則仍適用。</p><p class="source-note">PCIe Base 6.0 §§6.23、7.8.5.2–7.8.5.3，Figure 6-26、Figures 7-168–7-169、Tables 7-148、7-150，印刷／PDF pp.810–812、1129–1133。</p></section>
<section id="topology"><h2>Hierarchy ID 和 FPB 要分別查什麼？</h2><dl class="st-terms" aria-label="本段名詞"><div><dt>FPB</dt><dd>Flattening Portal Bridge，扁平化入口橋接器</dd></div></dl><p>在多個 Hierarchy 的系統裡，單靠 Routing ID（路由識別碼）不一定能跨階層區分 Function。§6.25 使用 System GUID 與 Authority ID、Hierarchy ID，以及該階層中的 Routing ID 一起識別。假設同一系統有 Hierarchy 0001h 和 0002h，兩者都出現 Routing ID 0300h；階層不同，不能當成同一個 Function。這個例子假設系統識別資訊有效；若 Authority ID=00h，System GUID 並無意義，不能拿它當有效的全球識別資訊。</p><p>Hierarchy ID Message 由 Downstream Port 在軟體要求下產生，接收端的 Upstream Port 可透過 Hierarchy ID Extended Capability 回報資訊。Figure 2-55／2-56 分別是 Non-Flit／Flit Mode 的訊息格式，§7.9.17 描述接收後的 Capability；實際如何使用資訊仍由平台決定。</p><p>FPB（Flattening Portal Bridge，扁平化入口橋接）處理另一個問題：如何分配 Routing ID 與 Memory Space。先看 Figure 6-28 定位採用 FPB 的邏輯 Bridge，再看 Figure 6-29 的 Switch 扁平化，最後以 Figure 6-30 理解 bit vector 如何將資源區段指派給 Secondary Side。這是需要支援與設定的可選機制，不能直接套用到未啟用 FPB 的 Bridge。</p><p class="source-note">PCIe Base 6.0 §2.2.8.6.4，Figures 2-55／2-56，pp.185–186；§6.25，pp.815–816；§6.26.1，Figures 6-28–6-30，pp.819–821；§7.9.17，pp.1268–1271。印刷頁與 PDF 頁相同。</p></section>
