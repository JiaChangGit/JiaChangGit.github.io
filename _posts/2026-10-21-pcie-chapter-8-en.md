<p class="lead">PCIe transmission depends on Link training, receive-buffer credits, and reliable delivery. This chapter uses evidence from both ends of one Link to distinguish supported speeds, the configured limit, and the negotiated result, then separates credit accounting from replay.</p>
<p><a href="/DOCS/pcie-course/chapter-8.html">Full Chinese tutorial</a> · <a href="/pcie/chapter-8-zh-tw/">繁體中文</a> · <a href="/DOCS/pcie-course/index.html">Course roadmap</a></p>
<aside class="note"><strong>Version and assumptions</strong><p>Base 6.0. The authored example connects Switch Downstream Port 02:01.0 to Endpoint 03:00.0, with PCI Express Capability at 0x70, version 2, at both ends. It uses Non-Flit Mode; Flit Mode is compared separately.</p></aside>
<section id="layers"><h2>Link training and Function readiness are separate stages</h2><p>The Physical Layer LTSSM establishes receive synchronization, Lane relationships, and Link width. The main initial path is Detect, Polling, Configuration, and L0. Configuration here is a training state, not BAR programming. Recovery can restore synchronization or change speed; observing it alone does not establish a fault.</p><p>Once the Physical Layer is operational, the Data Link Layer still completes applicable Feature Exchange and VC0 Flow Control initialization before DL_Active. Configuration readiness, BAR setup, and DMA preparation are separate conditions. DLLPs remain between adjacent Link partners; TLPs can traverse Switches to another component.</p><details class="source-note"><summary>State-machine reading route</summary><p>§3.1–§3.4, Figures 3-1/3-2 (pp.263–276); §4.2.6.1–§4.2.6.5 (pp.444–445), Figure 4-48 (p.454), Table 4-48 (p.453); §6.6.1 (p.721).</p></details></section>
<section id="speed"><h2>Support for 16 GT/s does not require that current speed</h2><div class="table-wrap"><table><caption>Evidence from both ends of one Link</caption><thead><tr><th scope="col">Field</th><th scope="col">Downstream Port</th><th scope="col">Endpoint</th></tr></thead><tbody><tr><td>Link Capabilities 2, 0x9C</td><td>0x0180001E</td><td>0x0180001E</td></tr><tr><td>Maximum Link Width, decoded</td><td>8 lanes</td><td>4 lanes</td></tr><tr><td>Link Control 2, 0xA0</td><td>0x0003</td><td>Its Target is not used here for normal speed control</td></tr><tr><td>Link Status, 0x82</td><td>0x2043</td><td>0x0043</td></tr></tbody></table></div><p>Figure 7-38/Table 7-35: <code>(0x0180001E &amp; 0xFE) &gt;&gt; 1 = 0x0F</code>, so both ends support 2.5, 5, 8, and 16 GT/s. Figure 7-39/Table 7-36: Downstream Port Target=3 limits normal operation to 8 GT/s. Figure 7-29/Table 7-26: Current=3 and Width=4 give 8 GT/s ×4, consistent with that limit and the Endpoint width. Maximum implemented width also need not equal physically wired width.</p><p>The example Downstream Port supports Link Active reporting, making Status bit 13=1 evidence of DL_Active. The Endpoint does not implement that reporting; its zero is not evidence of disconnection. Current Speed/Width are undefined when the Link is not up. Retrain Link triggers on a write of 1 and always reads zero; inspect applicable Training/Active status and final Speed/Width instead. Link Training is Reserved in Endpoints.</p><details class="source-note"><summary>Fields and applicability</summary><p>Figure 7-27/Table 7-23 (p.967); Figure 7-29/Table 7-26 (pp.978–979); Figures 7-38/7-39, Tables 7-35/7-36 (pp.998–1002); Retrain Link: Table 7-24 (pp.972–973).</p></details></section>
<section id="credits"><h2>Credits manage space; replay protects this hop</h2><p>In Non-Flit Mode, each Virtual Channel separately tracks Header and Data credits for Posted, Non-Posted, and Completion traffic: six classes. One Data credit represents 16 bytes; Headers are accounted separately. An authored VC0 example starts with finite, unscaled available PH=2 and PD=5, without competing traffic. A 64-byte MWr consumes 1 PH and 4 PD, leaving 1/1. A following 32-byte MWr requires 1/2 and waits until available PD increases by 1. This is an available-credit ledger, not a standard software-readable Register or a minimum initial advertisement.</p><p>A 256-byte MRd has no data Payload and needs only 1 NPH; its return traffic consumes Completion credits in the opposite direction. Sufficient credits do not guarantee immediate scheduling: ordering and arbitration still apply.</p><p>Non-Flit sequence numbers, LCRC, ACK/NAK, and replay provide adjacent-Link reliability. The transmitter retains copies; a NAK or acknowledgement timeout can cause replay. The receiver handles duplicate copies, and the Transaction Layer does not charge new credits again for the same TLP. An ACK on one hop is neither a transaction Completion nor device-work completion. Posted MWr has no ordinary Completion but still receives Link-level protection.</p><details class="source-note"><summary>FC and replay sources</summary><p>§2.6.1, Tables 2-44/2-45 (pp.236–237); Figures 3-9–3-11 (pp.283–284); §3.1 (p.264), Figure 3-17 (p.288), Figures 3-21/3-22 (pp.299, 303).</p></details></section>
<section id="flit"><h2>Flit Mode uses a fixed transport unit</h2><p>64 GT/s uses Flit Mode, which can also operate at lower rates. A 256-byte Flit contains 236 bytes for TLPs, 6 for DLP, 8 for CRC, and 6 for ECC. TLPs can span Flits, and multiple TLPs can share one Flit; the TLP region is not all application data. Replay operates at Flit granularity. FEC neither eliminates replay nor corrects every possible error.</p><p>Check Flit Mode Supported in PCI Express Capabilities before interpreting Downstream Port Link Status 2. A projection containing only Presence and the Flit bit of 0x4400 means Presence=100b and Flit=1: Link up, with no DRS received yet. A projection of 0x3400 means negotiation has completed but the Data Link Layer is not active. These are field projections, not full dumps; the Flit bit is meaningful only for Presence=011b, 100b, or 101b.</p><details class="source-note"><summary>Flit sources</summary><p>§4.2.3 (p.340), §4.2.3.3–§4.2.3.4 (pp.351–390), Figure 4-33 (p.383); Table 7-19 (p.955), Figure 7-40/Table 7-37 (pp.1004–1007). This chapter uses Base 6.0 without silently incorporating later ECNs.</p></details></section>
