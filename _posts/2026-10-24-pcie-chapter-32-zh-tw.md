<section id="setup"><h2>Capability、Stream 設定與金鑰各從哪裡查？</h2><p>先在兩個終端 Port 的管理 Function 查 IDE Extended Capability：Figure 7-371 的 ID=0030h、Version=1。Endpoint Upstream Port 由 Function 0 管理，Downstream Port 由其 Bridge Function 管理；Root Port 的金鑰管理介面可能不同。金鑰建立另查 IDE_KM，不會因 Configuration Register 可讀就自動完成。</p><p>接續模擬情境，假設 Root Port 和 Endpoint Port 的 IDE Capability 均為 00000063h：Link IDE Supported、Selective IDE Supported、PCRC Supported 和 IDE_KM Protocol Supported 為一，支援演算法編碼為 0，兩個數量欄位皆為 0，分別表示一個 Link IDE TC 與一個 Selective Stream。支援欄位表示硬體能力，還要查控制、協定和目前狀態。</p><dl class="st-terms" aria-label="本段名詞"><div><dt>TC</dt><dd>Traffic Class，流量類別</dd></div></dl><p>令 Root Port 的 IDE Capability 起點為 R。依 Figure 7-370，Header、Capability、Control 後有一組 Link IDE Control／Status，因此第一組 Selective Stream Capability、Control、Status 分別從 R+14h、R+18h、R+1Ch 開始。這個位移依本例的 Link Stream 數量推得，不能把它當所有裝置的固定 offset。</p><div class="table-wrap"><table><thead><tr><th>Root Port 位置</th><th>模擬讀值</th><th>解讀</th></tr></thead><tbody><tr><td>R+14h：Selective Stream Capability</td><td>00000001h</td><td>一組 Address Association Register</td></tr><tr><td>R+18h：Selective Stream Control</td><td>05000001h</td><td>Stream ID=05h、TC=0、Selected Algorithm=0、Enable=1</td></tr><tr><td>R+1Ch：Selective Stream Status</td><td>00000002h</td><td>State=0010b（Secure）</td></tr></tbody></table></div><p>另一端 Endpoint Port 也使用 Stream ID=05h、TC=0 與相同演算法；假設它的 Enable=1、State=0010b。這是案例給定的兩端快照。Enable 的作用是允許在 IDE_KM 觸發後開始操作，不能單靠 Enable=1 判定已進入 Secure。若 State 為保留編碼，軟體應視為未知狀態。</p><p class="source-note">PCIe Base 6.0 §6.33.2–6.33.3，印刷／PDF pp.868–869；§7.9.26–7.9.26.5.3，Figures 7-370–7-378、Tables 7-323–7-330，pp.1303–1313。</p></section>
<section id="association"><h2>哪一筆 Memory Request 可以進入這條 Stream？</h2><p>先用 Table 6-33 檢查 TLP 類型：Memory Read／Write 可以使用 Selective IDE，I/O Read／Write 不可以。再依 §6.33.4 檢查 Stream Enable、TC、對應範圍及其他適用條件；只有地址相符還不足以完成所有檢查。</p><dl class="st-terms" aria-label="本段名詞"><div><dt>TLP</dt><dd>Transaction Layer Packet，交易層封包</dd></div></dl><p>本例假設 Root Port 的 Partner Endpoint RID=0300h。依 Figure 7-370 接著讀 RID Association Register 1／2：R+20h=00030000h 表示 RID Limit=0300h，R+24h=00030001h 表示 RID Base=0300h、Valid=1。Valid 表示範圍已配置，不等同 Stream Secure。Endpoint 端要描述自己的 Partner Port，應讀取並核對 Endpoint 端的相應設定，不能把 Root Port 的值照搬過去。</p><dl class="st-terms" aria-label="本段名詞"><div><dt>RID</dt><dd>Routing ID，封包使用的路由識別碼</dd></div></dl><p>Root Port 的第一組 Address Association 假設為 R+28h=90090001h、R+2Ch=00000000h、R+30h=00000000h。依 Figure 7-381 與 Tables 7-333–7-335，Valid=1，Base 的低 20 bits 隱含為零，Limit 的低 20 bits 隱含為一，因此範圍是 90000000h–900FFFFFh。Root Port 發出的 TC0 Memory Read 若目標為 90010000h，地址落在此範圍；假設其餘路由、選擇及保護條件均成立，可與這條 Stream 關聯。</p><p>超出範圍或 TC 不同的 TLP 不符合本例這條 Selective Stream 的相關條件；還須依其他 Stream、Link IDE 與平台設定處理。Memory Read 的 Completion 則須與原 Non-Posted Request 的 Stream ID 和 T bit 相符。即使兩端 State=Secure，也不能只用這個快照證明目標裝置已完成讀取。</p><p class="source-note">PCIe Base 6.0 §6.33.4，Table 6-33 <em>TLP Types for Selective IDE Streams</em>，印刷／PDF pp.889–890；§§7.9.26.5.4–7.9.26.5.5，Figures 7-379–7-383、Tables 7-331–7-335，pp.1313–1315。</p></section>
<section id="state"><h2>Enable 已設為一，為什麼仍可能是 Insecure？</h2><p>Figure 6-49 把 Ready 畫在 Insecure 之內。Ready 表示必要配置已完成，是系統軟體／韌體需要追蹤的概念子狀態；規格不要求硬體直接回報這個轉換。兩端還需完成適用的金鑰、設定和觸發流程，才能各自進入 Secure。</p><p>以本例為例，若兩端 Enable 均為一，但 Root Port 的 State=0000b、Endpoint 的 State=0010b，目前只能說 Root Port 尚未處於 Secure；兩份資料的時間也要對齊。Selective Stream Enable=1 時若 RID Association 的 Valid=0，該 Stream 必須轉為 Insecure。Selected Algorithm、PCRC Enable、RID Base／Limit 與 Valid 必須在 Enable 前配置；啟用中修改這些指定欄位，結果為 undefined。</p><p>Stream Enable 被清除，或 Port 偵測到安全遭破壞時，Stream 必須轉為 Insecure。若 TEE（Trusted Execution Environment，可信執行環境）要求這條 Stream，Figure 6-50 的條件是所有必要 Stream 均為 Secure 才能進入 Locked；任何必要 Stream 為 Insecure 時須回到 Not Locked。原本要求安全保護的傳送不可默默改用未受保護的 TLP。</p><p>收到 Integrity Check Fail Message 的狀態是另一個 RW1C 事件欄位；清除事件記錄不等於重新建立 Stream，也不能由單一快照還原完整失效原因。</p><p class="source-note">PCIe Base 6.0 §6.33.1，Figures 6-49–6-50，印刷／PDF pp.866–868；§7.9.26.5.2–7.9.26.5.3，Tables 7-329–7-330，pp.1310–1313。</p></section>
<section id="example"><h2>Appendix L 的輸入與輸出怎麼對照？</h2><p>Figure L-1 先給一個 Memory Write，Table L-1 再列出演算法的 A（附加驗證資料）、P（明文）以及 C（密文）和 MAC（Message Authentication Code，訊息驗證碼）。最後看 Figure L-2，辨認 IDE Prefix、加密後資料、PCRC 與 MAC 在封包中的位置。範例位於 Non-Flit 格式；Flit Mode 的欄位位置需回到對應格式。</p><p>這組值是規格中的測試範例，用來理解欄位如何連接，不代表已驗證本機實作。本文不提供實機金鑰或私密設定。</p><p class="source-note">PCIe Base 6.0 Appendix L <em>Example IDE TLP</em>，Figures L-1–L-2、Table L-1 <em>Inputs and Outputs for Example IDE TLP</em>，印刷／PDF pp.1903–1904；§6.33.4，p.882。</p></section>
