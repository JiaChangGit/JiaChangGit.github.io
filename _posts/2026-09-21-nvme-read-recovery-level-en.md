<section id="topic-overview" class="topic-overview">
<p class="reader-paragraph opening"><span class="paragraph-number" aria-label="00.01">00.01.</span><span class="paragraph-text">When data is difficult to recover, should a controller spend more effort or use less recovery before returning a result to the host? Read Recovery Level provides this tradeoff. Start with levels and affected scope, then connect capability bits, configuration, readback and reset behavior so each field answers a concrete question.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>controller</dt><dd>The interface entity that receives and processes host NVMe commands.</dd></div><div><dt>scope</dt><dd>The objects sharing a setting, such as one NVM Set or an entire subsystem.</dd></div><div><dt>Host</dt><dd>The system running the operating system and issuing NVMe commands.</dd></div></dl>
<h2 id="main-ideas">The main ideas</h2>
<div class="topic-map">
<article><span class="axis-number">01</span><h3>Understand the tradeoff</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="01-01">01-01</span><span class="paragraph-text">Levels adjust read-error recovery effort. Compare maximum, default and minimum recovery, separating policy from measured latency and successful recovery.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>default</dt><dd>The default value; RRL defaults to level 4, independently of the current value.</dd></div></dl></article>
<article><span class="axis-number">02</span><h3>Find who shares the setting</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="02-01">02-01</span><span class="paragraph-text">Determine whether sets exist and which namespaces share a set. This identifies the affected spaces and those that cannot independently choose different levels.</span></p></article>
<article><span class="axis-number">03</span><h3>Connect capability, request and result</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="03-01">03-01</span><span class="paragraph-text">Discover supported levels, choose the target and value, then read back using the correct format. Level support, current value and saveability answer different questions.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>current</dt><dd>The feature value currently in use.</dd></div></dl></article>
<article><span class="axis-number">04</span><h3>Follow the setting over time</h3><p class="axis-paragraph"><span class="axis-paragraph-number" aria-label="04-01">04-01</span><span class="paragraph-text">Use successful completion to distinguish earlier and later commands. Then consider reset scope, current and saved values to explain when a new or restored value applies.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>saved</dt><dd>The saved feature value used in applicable restoration cases.</dd></div></dl></article>
</div>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.02">00.02.</span><span class="paragraph-text">Assumes operating systems, computer organization and basic SSD knowledge. Sets 7/9, namespaces A/B/C and encoded values are illustrative and depend on actual device capabilities.</span></p>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.03">00.03.</span><span class="paragraph-text">Follow one set’s configuration, then compare easily confused values and scopes. The goal is to explain which spaces share a setting and what each query actually answers.</span></p>
<div class="overview-connections"><h3>Connecting the main ideas</h3>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.04">00.04.</span><span class="paragraph-text">Follow one question: to use minimum recovery for reads in set 7, what must be discovered, which parameters are needed, and how can the current setting be confirmed?</span></p>
<p class="reader-paragraph"><span class="paragraph-number" aria-label="00.05">00.05.</span><span class="paragraph-text">The comparisons distinguish identical numbers in different result formats and identical settings under different reset scopes.</span></p>

<section class="lesson" id="module-rrl-levels"><h2 id="heading-rrl-levels"><span class="section-number">01</span> How much recovery should a difficult read receive?</h2>
<!-- claim:RRL-LEVELS -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="01.01">01.01.</span><span class="paragraph-text">Read Recovery Level (RRL) balances read completion time against recovery effort. When the feature is supported, level 4 is the mandatory default and level 15 is mandatory Fast Fail. Optional level 0 provides maximum recovery. Higher levels provide less recovery; interaction with an I/O command’s LR field is implementation-specific.</span></p><dl class="term-note" aria-label="Terms in this passage"><div><dt>Fast Fail</dt><dd>The name of RRL level 15, providing minimum recovery without a fixed completion-time guarantee here.</dd></div><div><dt>I/O</dt><dd>Input/Output, the class of data operations performed on a namespace.</dd></div><div><dt>RRL</dt><dd>Read Recovery Level; selects the recovery effort applied to difficult reads.</dd></div></dl><details class="source-note"><summary>Sources: Base 2.4 §8.1.23</summary><p>Source: NVME-BASE-2.4, Rev. 2.4, §8.1.23, printed pages 689-690, PDF pages 715-716</p></details>
<aside class="worked-example"><h3>Illustrative example</h3><p class="reader-paragraph"><span class="paragraph-number" aria-label="01.02">01.02.</span><span class="paragraph-text">Illustrative scenario: a service with another usable copy may prefer less device recovery before deciding its next action. A workload willing to wait for this copy may prefer a supported level with more recovery. These are policy choices, not latency or success-rate guarantees.</span></p></aside>
</section>

<section class="lesson" id="module-rrl-set"><h2 id="heading-rrl-set"><span class="section-number">04</span> Encode the target set and requested level</h2>
<!-- claim:RRL-SET -->
<p class="reader-paragraph"><span class="paragraph-number" aria-label="04.01">04.01.</span><span class="paragraph-text">Set Features selects Read Recovery Level Config with FID 12h. <details class="review-question" id="qa-rrl-bitmap"><summary>1. With RRLS=8011h, is level 8 available, and should level 15 be encoded as 8000h?</summary>
<div data-qa-answer="rrl-bitmap"><p class="reader-paragraph review-answer"><span class="paragraph-number" aria-label="09.01">09.01.</span><span class="paragraph-text">No: bit 8 is zero. For level 15, check RRLS bit 15, then encode Fh in the four-bit RRL field. The value 8000h is a support-bit mask, not the level code.</span></p></div>

<!-- qa:rrl-scope -->
<details class="review-question" id="qa-rrl-scope"><summary>2. Can A’s NSID select level 15 only for A when A and B share one set?</summary>
<div data-qa-answer="rrl-scope"><p class="reader-paragraph review-answer"><span class="paragraph-number" aria-label="09.02">09.02.</span><span class="paragraph-text">No. RRL is shared at set scope and NVMSETID selects the set. NSID should be zero for this scope; nonzero does not narrow the effect and causes the command to be aborted.</span></p></div>

<!-- qa:rrl-result -->
<details class="review-question" id="qa-rrl-result"><summary>3. Why is successful Get DW0=4 not enough to conclude that the current level is 4?</summary>
<div data-qa-answer="rrl-result"><p class="reader-paragraph review-answer"><span class="paragraph-number" aria-label="09.03">09.03.</span><span class="paragraph-text">Check SEL: zero returns current, while three makes 4 the CHANG=1/NSSPEC=0/SVBL=0 capability combination. With SEL=1, it is the default value.</span></p></div>

<details class="review-question" id="qa-rrl-timing"><summary>4. After Set level 15 succeeds, must both an outstanding read A and a subsequently submitted read B use 15?</summary>
<div data-qa-answer="rrl-timing"><p class="reader-paragraph review-answer"><span class="paragraph-number" aria-label="09.04">09.04.</span><span class="paragraph-text">B must use the new setting; already-submitted A may or may not use it.
