# PCIe 自學教材：選題與寫作

## 先用當次授權決定交付範圍

使用者於 2026-10-24 授權開始實作，並明確說明所有參考題、分類與回答格式皆可調整。前一輪的唯讀狀態已解除；歷史停止點不限制新授權。題目代碼可在內部保留為對照，不必成為公開頁面的標題或模板。

現有 PCIe 課程已有 Chapter 0–37。先比較既有主題與本次學習目的，修改合適的主要文章並保留 URL、有效錨點；避免另建一套重複答案。當次沒有授權的新系列或其他專案，不因這份規則而自動納入。

## 用學習目的決定是否保留一題

比較讀者取得的資料、需要查的規則與最後要完成的分析。三者高度重疊時，選一個主要位置完整教學，把其他參考題中的有效條件或觀察資料併入案例。只更換數字、速度、TLP 類型或 Error bit，不算新增學習目的。

基礎原理只完整解釋一次；其他文章短述必要背景並連回主要教學。綜合案例要有實質的跨主題分析，不能只把幾份答案接在一起。結尾的「完整分析」若沒有新增的理解，就併入本章帶讀案例。

`.ai/pcie-course/self-study-plan.json` 保存本輪選題提案及已完成位置，不是固定題數、格式或完成保證；後續可根據 PDF 與實際教學繼續調整。

## 寫作方式

先說本篇要處理的問題，用必要的總覽定位角色，再完整示範主要流程。問題緊接解說；核心資訊直接可見。只回顧接下來需要的背景，不加入無關歷史。

每一個推理步驟說清楚：目前觀察對象與資料、為何查這段規格、應讀的條件或欄位，以及這項資訊如何帶到下一步。數值幫助說明欄位與流程，不以大量算題取代教學。

採用適合主題的段落、對照表、拓撲、狀態圖或時序圖。先確定圖要說清楚的關係，再畫圖。圖旁放必要說明與來源，不在圖後逐格重述。規格查閱順序與硬體運作時序分開描述。

「一句話重點」「原題檢查」「判讀邊界」「常見誤解」等可作編輯工具；公開文章不必逐項照填。修正前提的原因只在確實影響讀者時交代。延伸問題按需要加入，不設題數、分數或通過門檻。

小節、圖數、句長與術語提醒次數也依理解需要調整。前兩次就近解釋仍是預設寫法，但固定次數不是教學品質指標；若原有模板或提示妨礙閱讀，改用能把當前關係說清楚的形式。

英文關鍵字與縮寫在每篇、每個語言版本前兩次就近解釋。中文先確立話題，改變 Function、Port、方向或時間時重新交代對象；依實際關係使用連接詞。可多寫幾句完成必要推理，不用重複同一結論增加篇幅。

## 查證與證據

主要技術答案先查指定 Base 6.0 PDF，連同相關完整頁面、圖表、註解與例外閱讀。不要依記憶補章號、圖號、正式名稱、欄位屬性、編碼、Reset 行為或適用範圍。列明實際使用的章節、正式圖表名稱、文件頁與 PDF 頁；不可靠的頁碼寫明無法確認。

分清 Capability、Control/Enable/Target、宣告資訊、協商結果、目前狀態、歷史事件與平台選擇。涉及 Link 先配對相鄰的兩端 Port；先檢查欄位對該 Function/Port/模式是否適用，再使用其值。尚未取得的資料不可補成既定事實。

Base 6.0 已收錄的功能應先查本版內容，不能依舊印象一概歸到外部規格。若查閱後依據仍不足，明確寫「Specification 中尚未找到足夠依據。」並列出實際缺少的資料。未查閱與查閱後依據不足是不同狀態。

作者建立的拓撲、讀值或 Trace 就近標為模擬資料，說明適用假設；由規則推得的結論交代推理，不冒充原文。模擬資料先驗證欄位、範圍、模式、時間及算式。刻意示範錯誤封包時說清楚錯誤是案例的一部分。

原文只在規範強度或例外會影響答案時短引，不大量複製。Linux、工具、平台與裝置補充另標為實務延伸，附文件與版本；不得把工具摘要當成規格狀態。

## 教學方法的外部參考

以下來源於 2026-10-24 查閱，只支持教學與表達選擇，不作 PCIe 技術依據：

- [NSW CESE, Cognitive load theory in practice](https://education.nsw.gov.au/about-us/education-data-and-research/cese/publications/practical-guides-for-educators/cognitive-load-theory-in-practice.html)：依既有知識安排完整示範，排除無關資訊，集中必要資訊。
- [AERO, Managing cognitive load optimises learning](https://www.edresearch.edu.au/summaries-explainers/explainers/managing-cognitive-load-optimises-learning)：分段解釋、連接既有知識，以案例與提示支援新內容。
- [臺大寫作教學中心，學術寫作的構句原則與技巧](https://awec.ntu.edu.tw/專題1：學術寫作的構句原則與技巧/?lang=en)：確立話題、適度斷句，檢查轉承詞與句意是否一致。
- [Google Technical Writing, Illustrating](https://developers.google.com/tech-writing/two/illustrations)：先決定圖的教學重點，再安排資訊與視覺提示。
- [Google Technical Writing, Audience](https://developers.google.com/tech-writing/one/audience) 與 [Paragraphs](https://developers.google.com/tech-writing/one/paragraphs)：依讀者知識選材，每段維持清楚主題。

上述方法不等於已證明讀者學會。腳本用來核對來源登記、數值、結構與輸出；教學語意及中文仍須實際校閱。公開發布前沿用既有的頁面、下載包與資安檢查，不把來源 PDF、擷取全文、本機路徑或內部檢查產物放上網站。
