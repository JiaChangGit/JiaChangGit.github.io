本章從已找到的裝置功能出發，查詢 Device Serial Number（DSN，裝置序號）。先依功能種類選擇清單，再沿指標找到結構，最後讀取資料並按規格重組序號。

版本與前提

依 PCI Express Base Specification Revision 6.0。以下位置與讀值為作者設計，不是量測；目標是已找到的一般 Type 0 PCI Express Endpoint，非 RCiEP／VF，不用 ARI、SR-IOV 或 RCRB 清單。設定讀取成功、快照穩定，平台可存取完整設定空間。本例不支援 Flit Mode，因此 AER（Advanced Error Reporting，進階錯誤回報） Header 可採 Version 2。頁碼為所採 PDF 的文件頁／PDF 頁，兩者相同。

先區分查詢對象、設定 offset 與 CPU 位址

先用 Segment（匯流排的邏輯分組） 與 BDF（Bus、Device、Function 識別號） 選定 Function（可個別辨識與設定的功能），再用 byte offset 選它的設定暫存器。這份空間共 4096 bytes，前 256 bytes 是 PCI 相容區，0x100–0xFFF 是延伸區。ECAM（Enhanced Configuration Access Mechanism）提供 CPU 的記憶體映射設定存取；平台提供實際映射，offset 本身只表示 Function（可個別辨識與設定的功能） 內的位置。它與裝置 Memory BAR 的工作區分開。

傳統 Capability（描述或控制能力的結構） 清單由 Header 的 Capabilities Pointer 進入，本章 Type 0／1 的指標在 0x34。Extended 清單則直接從 0x100 開始。PCI Express Capability（描述或控制能力的結構） 本身在傳統清單，DSN（Device Serial Number，裝置序號） 才在 Extended 清單；不能靠名稱是否含 PCIe 來分類。

ID 為 0 與 Next 為 0，不能混為一談

傳統清單一般以 16-bit 開頭的低 byte 表示 ID、高 byte 表示 Next。教學資料中的路徑是 0x40 → 0x50 → 0x70 → 0xD0 → 0，依序為 PM、Null、PCIe、MSI-X。

Next 已經是從 Function 起點計算的 byte offset，因此直接在該位置繼續讀取；DWORD 對齊不改變它的單位。遇到未知 ID 時，仍可沿有效 Header 走到下一項。教材另檢查範圍、對齊與是否重訪，以辨認無法可靠解析的清單；合法位置可以前後移動。

找到 DSN 後，還要分清資料位置與表示順序

先以 Figure 7-242／Table 7-221 確認 ID 0003h，再以 Figure 7-241 找 Lower DW 與 Upper DW：它們位於結構起點 +0x04、+0x08。本例從 0x184 讀 32 bits 得 0x33221100，從 0x188 讀 32 bits 得 0x77665544。

Register 整數 = (0x77665544 << 32) | 0x33221100
              = 0x7766554433221100

Table 7-222 另外規定 Register byte 與 EUI-64 byte 的對映；依 EUI 高 byte 到低 byte 書寫，本例為 00-11-22-33-44-55-66-77。數字只示範重組，不宣稱是已配發或可使用的產品序號；實際值須符合 IEEE 公司識別碼與製造商延伸識別碼規則，也不能單憑此值當成身分認證。

DSN 是可選能力。一般多功能 Device 若實作 DSN，Function 0 必須實作；其他有實作的 Function 必須回報相同值。因此 DSN 不能代替 BDF（Bus、Device、Function 識別號） 中的 Function Number。

DSN 的精確位置

Base 6.0 §7.9.3–§7.9.3.2，Figures 7-241–7-243、Tables 7-221／7-222，pp.1205–1207。RCiEP 與 PF／VF 有不同條件，本例不適用。

讀到資料，不代表可以原樣回寫

Attributes 欄必須與位元定義一起讀。RO 不表示硬體狀態永遠不變；RW1C（寫入一才清除對應狀態） 則在寫 1 時清除狀態，寫 0 不作用。若假設一個 4-bit 欄位全部為 RW1C（寫入一才清除對應狀態），讀到 1001b，只想清 bit 0，應寫 0001b；沒有新事件時剩下 1000b。這是語義示例，不是某個真實 Register。

RsvdP 要保存讀值，RsvdZ 要寫 0，不能把所有 Reserved 都當成同一種欄位。存取失敗不能當成「不支援」的有效回覆；成功讀到 0 也不保證該處實作了有意義的 Register。只有在正確入口與有效結果成立後，才依格式解讀。

屬性與結果邊界

Base 6.0 §7.4、Table 7-2，pp.913–915。未實作 Register 在無其他錯誤時，設定讀取成功回 0：§7.3.3，p.913。0x100 的全零 Extended Header 表示沒有 Extended Capabilities：§7.6.1，p.1009。此規則不等同傳統 Null Capability 的 ID=0。

沿完整查詢處理不同讀值

把本例串起來：從 0x100 進入延伸清單，在 0x180 找到 DSN，再讀 0x184 與 0x188。Next 指向另一個結構；資料位移則定位目前結構的欄位。以下延伸說明沿用這項區分。

在 0x180 讀到 0x24010003，DSN 的 Lower DW 改到 0x244 了嗎？

沒有。0x240 是下一項的位置；目前 DSN 仍在 0x180，Lower DW 仍位於 0x184。（Figure 7-241，p.1205；Table 7-39，p.1010。）

在傳統清單找不到 DSN，就能宣告不支援嗎？

不能。DSN 在 Extended 清單，必須透過能存取該區域的介面查詢；查錯清單或無法存取，都不是有效的不存在證據。（§7.6.1，p.1009；§7.9.3，p.1205。）
