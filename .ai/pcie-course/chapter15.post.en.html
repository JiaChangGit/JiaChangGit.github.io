After parsing a TLP (Transaction Layer Packet), follow the receiver into validity and acceptance checks. An AtomicOp (Atomic Operation) performs an atomic read-modify-write; DMWr (Deferrable Memory Write) supports shared work submission. Both return completions, with different operation and status rules.

Why does link receipt not finish a transaction?

Section 2.3 begins after the Data Link Layer has checked integrity. The Transaction Layer still validates the packet and separates requests from completions. A Malformed TLP (invalid packet format) must be discarded. Figure 2-81 provides the overall route; sections 2.3.1 and 2.3.2 give branch rules. Link receipt, transaction acceptance, and receipt of all completion data occur at different participants.

Trace an atomic counter update

Start with section 6.15, then check completer size support and intermediate AtomicOp Routing Supported in Device Capabilities 2. Check Requester Enable and Egress Blocking in Device Control 2. Discovery of requester capability itself is outside this specification. FetchAdd adds an operand, Swap replaces the value, and CAS replaces it only on a comparison match; all return the original value.

Author example: with supported 32-bit FetchAdd, a valid route and permissions, original value 7 and operand 1, the completer atomically writes 8 and returns 7. A requester needing the operation observed before its next request must wait for this completion.

Handle temporarily unavailable shared work

DMWr (a non-posted write that permits deferral) is defined in section 6.32. A completer may return Request Retry Status for a temporary condition, leaving the target unchanged. This is not an error, and the completer must not assume the requester will retry. In the author scenario, only a later successful submission establishes acceptance; retry and software notification mechanisms depend on the requester implementation.

Timeout and legacy locked traffic

Completion Timeout is supervised by the requester. A split Memory Read finishes only after all completions arrive. Section 2.8 explicitly says timeout ranges are not typical service latency estimates. Locked Transactions in section 6.5 are a separate compatibility mechanism: only a Root Complex may initiate them; PCI Express Endpoints must not support locked accesses, and new software must not cause locked I/O accesses.
