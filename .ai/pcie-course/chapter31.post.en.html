DOE (Data Object Exchange) lets firmware/software exchange objects through configuration space. CMA (Component Measurement and Authentication) can use SPDM (Security Protocol and Data Model) over it. First establish the transport exchange, then interpret protocol content and trust.

Discover the object protocol first

Find a DOE instance, then use its mandatory Discovery protocol in Table 6-32. The returned Vendor ID/protocol combinations identify supported object protocols. CMA (component measurement/authentication) is not fully implied by DOE presence. DOE relies on Configuration Requests and is not a direct function-to-function P2P channel; software may supply relaying where needed.

Acknowledge each mailbox word

Author scenario: a valid response length is established from its header and protocol. With Ready=1, reading the mailbox returns the current DW (Double Word, four-byte unit). A subsequent write acknowledges it so the next read returns the following word. Missing that acknowledgement repeats data. Section 6.30.2 supplies a one-second processing bound unless protocol-specific requirements apply; Abort also has completion timing, so setting its bit is not proof of finished recovery.

Separate transport success from trust

SPDM (the security protocol and data model) and platform trust policy still apply. Figure 6-43 separates the protocol, secured messages, and DOE/MCTP transport layers. Section 6.31 says PCIe-specific requirements belong here while foundational messages and architecture come from the referenced SPDM documents. Transport completion alone does not validate identity or measurements, and this lesson does not invent a certificate algorithm or silently substitute a newer SPDM revision.
