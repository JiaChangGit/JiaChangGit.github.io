PCIe 封包能否傳送，取決於連線訓練、接收緩衝額度與可靠傳遞機制。本章用同一條 Link 的兩端證據，區分支援速率、設定上限與目前結果，再說明 credit 與 replay 分別解決什麼問題。

版本與前提

採 Base 6.0。案例為 Switch Downstream Port 02:01.0 與 Endpoint 03:00.0，兩端 PCI Express Capability 均假設在 0x70、版本 2；使用 Non-Flit Mode。以下數值是作者假設，Flit 比較另行處理。

訓練 Link 與準備 Function 是不同階段

Physical Layer 的 LTSSM 負責建立接收同步、Lane 關係與 Link 寬度。初次建立的主要路徑為 Detect、Polling、Configuration、L0；這裡的 Configuration 是訓練狀態，不是配置 BAR。Recovery 可恢復同步或變更速率，出現該狀態本身不足以證明故障。

Physical Layer 可運作後，Data Link Layer 還需完成適用的 Feature Exchange 與 VC0 Flow Control 初始化，進入 DL_Active。Function 能否接受設定、BAR 與 DMA 是否準備完成，是後續不同的條件。DLLP 僅在相鄰 Link 兩端交換，TLP 才可能跨越 Switch 到另一個元件。

credit 控制空間，replay 處理這一跳的傳輸

Non-Flit Mode 中，每個 Virtual Channel 分別追蹤 Posted、Non-Posted、Completion 的 Header 與 Data，共六類 credits。Data 一單位為 16 bytes，Header 另計。作者假設 VC0 目前有有限、未縮放的 PH=2、PD=5，沒有其他競爭：64-byte MWr 消耗 1 PH、4 PD，剩 1／1；隨後 32-byte MWr 需要 1／2，必須等待。若可用 PD 增加 1，才通過這項檢查。這是可用額度帳本，不是標準可讀 Register 或最低初始宣告。

256-byte MRd 本身沒有資料 Payload，只需 1 NPH；回覆在反方向消耗 Completion credits。credit 足夠仍不保證立即排到傳送，排序與仲裁也要成立。

Non-Flit 的 sequence number、LCRC、ACK／NAK 與 replay，保障相鄰兩端傳輸。發送端保留副本，NAK 或確認逾時可引發重送；接收端辨識重複副本，Transaction Layer 不再為同一 TLP 扣一輪新 credit。某一跳收到 ACK，不是最終交易 Completion，也不是裝置工作完成；Posted MWr 沒有一般 Completion，仍有 Link 層可靠傳遞。

Flit Mode 另有固定傳輸單位

64 GT/s 使用 Flit Mode，較低速率也可能使用。每個 Flit 為 256 bytes：236 bytes TLP 區、6 bytes DLP、8 bytes CRC、6 bytes ECC。TLP 可跨 Flit，也可多筆共用一個 Flit；236 bytes 不能全部當成使用者資料。可靠傳遞改以 Flit 為 replay 單位，FEC 不代表取消重送或能修正所有錯誤。

查模式先確認 PCI Express Capabilities 的 Flit Mode Supported，再看 Downstream Port 的 Link Status 2。只擷取 Presence 與 Flit bit 得到 0x4400，表示 Presence=100b、Flit=1，Link up 但尚未收到 DRS；0x3400 則是協商已完成、Data Link Layer 尚未 active。這是欄位投影，非完整 dump；Flit bit 只在 Presence=011b、100b、101b 有意義。

用問題確認邊界

PD=0，就表示 MRd 也不能送嗎？

不一定。MRd 檢查 NPH，仍須滿足其他傳送條件。（Table 2-45，p.237。）

ACK 能當成 CPU 已使用 DMA 資料的證據嗎？

不能。它的範圍是相鄰 Link 的傳輸確認；最終資料可見性、所有權與工作完成仍須依各自介面判斷。
