不同流量共用一條 Link，如何避免一起被堵住？

選擇步驟後，圖中對應的元件與下方解說會加上重點標示。完整圖與所有解說會持續顯示；也可用方向鍵切換步驟。

先看分類如何對到資源，再看多個可傳送通道如何共用實體線路。兩條 VC 分支可以並存。

TC（Traffic Class，流量類別）是封包上的分類；VC（Virtual Channel，虛擬通道）則把這些流量接到佇列、緩衝與流量控制資源。先分清分類與資源，才能看懂為什麼提高 TC（用來標示流量的類別）數字，不會自動增加頻寬。

  1. 從封包分類找到映射

    一個類別不能在同一 Port 或 Function 被映射到多個通道；同一 Link 兩端須一致。

    §2.5 說明資源模型；§2.5.2 的 Table 2-43 列出可行的分類到通道映射。TC0 固定對應 VC0。

    Base 6.0 §2.5、§2.5.2，pp.229、233。

  2. 把需要隔離的流量分開

    額外通道必須受支援並完成有效配置；表內的配置只是合法範例，不是所有裝置的預設。

    本例把一般流量留在基本通道，將一組週期流量配置到額外通道。分開的是緩衝與流量控制資源，仍共用同一條實體 Link。

    Base 6.0 §2.5.2／Table 2-43，p.233。

  3. 最後檢查仲裁及整條路徑

    Flit 模式的共享流量控制另有共享與專用資源，不能直接照搬非 Flit 的獨立池模型。

    獨立通道能減少因流量控制造成的相互阻擋，服務時機仍取決於仲裁、可用頻寬與接收端。

    Base 6.0 §2.5，p.229；§2.6，p.235。

應該先查分類，還是先查通道？

先沿 Table 2-43 讀一個具體配置：裝置只提供 VC0、VC1 時，可以把 TC0–TC6 放在 VC0，TC7 放在 VC1。再看 Figure 2-88，確認映射發生在 Link 兩端。VC（承接流量與控制資源的虛擬通道）不增加新的 Lane，也不改變實體速率。

接著走過整條路徑。Switch 各 Port 可以獨立配置映射，因此跨到下一條 Link 時，須再核對兩端。把所有 Port 抄成同一份設定，不是規格給的必要條件；真正必須相同的是同一 Link 的兩端。

一組流量沒 credit，其他流量還能走嗎？

作者情境：假設兩端已完成上述配置，使用非 Flit 模式且各通道有獨立流量控制。VC0 的接收緩衝暫時不足，但 VC1 有足夠資源，TC7 的封包也滿足其他傳送條件。這時 VC0 的 credit 不足，不會直接變成 VC1 的 credit 不足；TC7 仍可參與傳送仲裁。

這說明的是阻擋的隔離。若 VC1 自身的 credit 不足、排程未選到，或共同 Link 已滿載，TC7 仍會等待。隔離一個阻擋來源，不等於取得固定延遲保證。

週期資料需要保證，還要補看什麼？

要安排週期服務，從 §6.3 的映射、仲裁與等時性支援，接到 Appendix A 的 Isochronous Contract（等時性服務契約）。契約把時間週期、有效資料量、頻寬與延遲連在一起；Endpoint、Switch、Root Complex 和沿路 Link 都會限制結果。

沿 Figure A-1 找到要求者、完成端與共同路徑，再用 Figure A-2 看過度配置與壅塞。契約必須同時處理資源保留與流量調節。這些服務需要整條路徑完成配置，不能把範例數值當成所有 PCIe 裝置的保證。若需求只是一般非週期傳輸，先回到實際通道與仲裁能力。
