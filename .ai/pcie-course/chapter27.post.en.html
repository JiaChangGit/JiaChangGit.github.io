ATS (Address Translation Services) obtains mappings and permissions. PRI (Page Request Interface) requests page service, while PASID (Process Address Space ID) adds address-space identity. Follow one case through lookup, data access, invalidation and page groups without treating their responses as equivalent.

One invalidation can require more than one reply

Suppose the platform changes PASID 21h's mapping for 40001000h–40001FFFh. Use the mode-specific Figures 10-18/10-19 and Figure 10-20's untranslated range. Assume ITag 3, TC0, a 4 KiB range for this PASID only, and no Global Mapping.

New Requests must not use stale translations. Related outstanding Reads must complete or be marked for discard; Posted Writes must be pushed to the TA. Deleting the ATC entry alone is insufficient. Section 10.3.6 also handles an overlapping outstanding Translation Request so a delayed old result does not repopulate the cache after invalidation.

For this multi-TC continuation, assume the Function later needed to Write, requested a new translation, and obtained R=W=1 before issuing relevant Posted Writes on TC0 and TC1. Replies on these two channels provide the required push. Figure 10-5 illustrates multiple Invalidate Completions for one Request. Figures 10-21/10-22 identify the replies as Msg, Code 02h, ID routed, not ordinary Cpl packets. ITag Vector bit 3 identifies ITag 3:

CC encoding 0 means eight messages, not none. ITag, Memory Request Tag and PRI PRG Index are separate mechanisms.

These semantics cover invalidation and push to the TA, not application persistence; memory reclamation needs platform lifecycle coordination. A Function with ATS Capability must accept/complete invalidations even when ATS is disabled, and clearing BME does not remove that duty.

What if an old translation response and invalidation cross?

Teaching scenario: An Endpoint has an outstanding Translation Request covering 40001000h; the platform sends an overlapping Invalidate Request before its response arrives. They may use different TCs, so Link-level ordering does not establish their relative order.

  1. Per §10.3.6 the ATC checks outstanding Translation Request ranges against arriving invalidations and marks an overlapping request invalid.
  2. The corresponding result must be discarded as required so an old mapping does not remain after invalidation. If the response arrives before Invalidate Completion is sent, an implementation may temporarily use it, provided the new-request, outstanding-read, and posted-write conditions of §10.3.3 are met.
  3. After the applicable work meets completion conditions, send Invalidate Completion. The platform considers the invalidation complete only after collecting all required responses.

Receipt of a translation response and completion of the invalidation exchange are distinct events. When Shadow Functions are enabled, §10.3.3 includes relevant requests from the Function and its Shadows; one invalidation may target either, subject to the specified Posted Write push conditions. Base 6.0 §10.3.3 and §10.3.6, pp.1501 and 1503–1504.

Does Invalidate Queue Depth=4 mean only four requests can be accepted?

These mechanisms describe different things. Invalidate Queue Depth is the number the function can buffer before applying Link backpressure; 00000b means invalidate flow control is not necessary for a non-VF Function; Table 10-10 interprets non-VF zero as accepting 32 requests, while a VF reads zero and uses its associated PF value. Input, output, or hybrid queuing is an implementation choice.

Section 10.3.4 forbids making acceptance of a new Invalidate Request depend on transmitting an earlier Invalidate Completion: both are Posted transactions and such a dependency can deadlock. Its implementation note describes up to 32 outstanding invalidations from one TA to an ATC; this does not require a 32-entry input queue.

With SR-IOV, VFs associated with a PF share an Invalidation Request queue in the PF. For a nonzero PF Invalidate Queue Depth, the TA must keep the total outstanding targeting that shared queue within that value. If the earlier assumed value 4 is used in such a shared PF/VF configuration, count the relevant functions together.

Invalidate Completions may coalesce multiple ITag Vector bits when the specified conditions, including the same TC and CC, hold. All fragments must have identical Requester ID, CC, and ITag Vector; the TA still collects the required replies for each ITag. Base 6.0 §10.3.2 and §10.3.4–§10.3.5, pp.1500–1503.

Page service returns to ATS

After invalidation completes, the device queries 40001000h again and receives R=W=0. For this continuation, platform page management separately confirms that both 40001000h and 40002000h are non-resident and the Function has legitimate Read work. Page non-residence is an additional teaching assumption; R=W=0 alone does not establish its cause.

Under §10.4 request both pages using PASID 21h, R=1, W=0 and PRG (Page Request Group) Index 005h. Only the second Message has Last=1. PRG Response PASID Required=1 in this case, so the successful response must contain the same PASID.

Page Request uses Code 04h, Route to Root Complex; PRG Response uses Code 05h, Route by ID. Both use TC0. Select Non-Flit Figures 10-23/10-27 or Flit Figures 10-24/10-28 for their page, index and response fields rather than treating them as Memory Completions.

What happens to outstanding requests when PASID 21h stops?

Teaching scenario: Reuse PASID 21h and the earlier two-page PRG, but both requests are sent, the final one has L=1, and its PRG Response has not yet arrived. Stopping this PASID does not mean the entire Page Request Interface has stopped.

Section 10.4.1.2 provides two paths. Both stop queuing new requests for 21h and finish any incomplete multi-page group, including its final L=1 request.

How can a trace distinguish a Stop Marker?

Identify the Page Request Message, then consult Figures 10-25 and 10-26. A Stop Marker has L=1, W=0, R=0, Marker Type 00000b, TC0, and Relaxed Ordering=0. Non-Flit Mode uses a PASID Prefix; Flit Mode uses OHC-A1 with PASID.

These fields mark a stop boundary, not a request to load a page without read or write access. The untranslated address and upper PRG Index bits are Reserved; do not interpret them as a page address or group number.

Behavior is undefined, for example, when the Host has no matching PASID stop request or an incomplete group for that PASID has not sent its final L=1 request. Base 6.0 §10.4.1.2.1, Figures 10-25 and 10-26, pp.1509–1510.

What should be checked in a PRG Response?

Use Figure 10-27 or 10-28 for the mode and destination Function, then match the PRG Index to an outstanding group. When a Page Request has a PASID, Status.PRG Response PASID Required determines whether the Response must carry it; incompatible formats can lead to undefined Function behavior.

If one request in a PRG carries a PASID, all requests in that PRG must carry the same PASID; inconsistent values have undefined behavior. A PASID Page Request with Execute Requested set must also set R; W=1 requires explicit write permission because the Host may mark the page dirty. When PRG Response PASID Required=0, Responses do not carry PASID and the Function shares PRG Index values across PASIDs.

Table 10-8 defines Response Code 0000b as group Success, 0001b as Invalid Request, unused 0010b–1110b values as treated like Response Failure, and 1111b as Response Failure. Failure terminates normal page-request service; later PRG Responses are ignored until re-enablement.

An otherwise error-free response with an unexpected PRG Index sets Unexpected Page Request Group Index (UPRGI). Success still requires a new ATS lookup to obtain a translation. Base 6.0 §10.4.1.1, §10.4.2–§10.4.2.2, Table 10-8, pp.1508 and 1511–1513.

How do Enable and Stopped describe stopping the interface?

In an SR-IOV arrangement using one PF Page Request Interface shared with its VFs, the PF implements the capability and its VFs must not. Each Page Request still carries the actual PF or VF Requester ID, and the corresponding PRG Response targets that Function. Base 6.0 §10.5.2, p.1516.

This concerns the whole interface, not the Stop Marker for one PASID. Locate the structure in Figure 10-33 and read Control and Status in Figures 10-35 and 10-36 and Tables 10-14 and 10-15.
