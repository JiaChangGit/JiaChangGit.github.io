ATS (Address Translation Services) obtains mappings and permissions. PRI (Page Request Interface) requests page service, while PASID (Process Address Space ID) adds address-space identity. Follow one case through lookup, data access, invalidation and page groups without treating their responses as equivalent.

Equal PASIDs do not identify an address space across Functions

Under §6.20 combine PASID with Requester ID. RID 0310h using PASID 21h is not thereby the same address space as RID 0300h/PASID 21h. PASID is not a universal OS PID encoding; mapping it to Function work context is device/platform specific.

Figure 6-20/Table 6-15 locates the Non-Flit End-End Prefix. Execute Requested=0, Privileged Mode Requested=0 and PASID=00021h produce bytes 91 00 00 21. Flit Mode uses OHC-A1, a header block carrying PASID and related information. The Translation Request No Write bit also belongs in this block.

Max PASID Width=8 permits values 0–255, including 21h and 0. Hardware must not invent reserved PASID values. Ordinary Completions, including Translation Completions, must not carry PASID. Recover the original query's PASID through Requester ID/Tag context. PRG (Page Request Group) Response is a separately permitted Message type.

With R=W=0 the range still has meaning, but address and specified other fields are undefined. A later invalid-to-valid mapping change need not send invalidation, so the ATC must not retain this entry as a persistent negative cache.

U (Untranslated access only)=1 permits caching the specified permission/range information, not using the returned address in AT10b Requests. A later need to Write with a read-only entry requires a fresh translation and authorization, not editing W in the ATC.

Table 10-2's UR (Unsupported Request) and CA (Completer Abort) are no-data failure responses. UR requires the Function to disable its ATC and stop using translated addresses until the ATC is re-enabled. CA means an error in the TA prevented translation. The RRS retry status is not permitted for Translation Requests and is treated as Malformed TLP when received; the preceding chapter's Configuration RRS conditions do not apply. None of these results alone identifies page non-residence or one failed platform component.

One invalidation can require more than one reply

Suppose the platform changes PASID 21h's mapping for 40001000h–40001FFFh. Use the mode-specific Figures 10-18/10-19 and Figure 10-20's untranslated range. Assume ITag 3, TC0, a 4 KiB range for this PASID only, and no Global Mapping.

New Requests must not use stale translations. Related outstanding Reads must complete or be marked for discard; Posted Writes must be pushed to the TA. Deleting the ATC entry alone is insufficient. Section 10.3.6 also handles an overlapping outstanding Translation Request so a delayed old result does not repopulate the cache after invalidation.

For this multi-TC continuation, assume the Function later needed to Write, requested a new translation, and obtained R=W=1 before issuing relevant Posted Writes on TC0 and TC1. Replies on these two channels provide the required push. Figure 10-5 illustrates multiple Invalidate Completions for one Request. Figures 10-21/10-22 identify the replies as Msg, Code 02h, ID routed, not ordinary Cpl packets. ITag Vector bit 3 identifies ITag 3:

Both carry CC (Completion Count)=2 and vector 00000008h. The first leaves one response outstanding. Only after both arrive can the TA consider this invalidation complete and release ITag. CC encoding 0 means eight messages, not none. ITag, Memory Request Tag and PRI PRG Index are separate mechanisms.

These semantics cover invalidation and push to the TA, not application persistence; memory reclamation needs platform lifecycle coordination. A Function with ATS Capability must accept/complete invalidations even when ATS is disabled, and clearing BME does not remove that duty.

Page service returns to ATS

After invalidation completes, the device queries 40001000h again and receives R=W=0. For this continuation, platform page management separately confirms that both 40001000h and 40002000h are non-resident and the Function has legitimate Read work. Page non-residence is an additional teaching assumption; R=W=0 alone does not establish its cause.

Under §10.4 request both pages using PASID 21h, R=1, W=0 and PRG (Page Request Group) Index 005h. Only the second Message has Last=1. PRG Response PASID Required=1 in this case, so the successful response must contain the same PASID.

Page Request uses Code 04h, Route to Root Complex; PRG Response uses Code 05h, Route by ID. Both use TC0. Select Non-Flit Figures 10-23/10-27 or Flit Figures 10-24/10-28 for their page, index and response fields rather than treating them as Memory Completions.

One group response returns two message allocations and releases the PRG Index. With only one free allocation, do not send the first half of a two-page group while waiting for more. These are not the Link Flow Control Credits in Chapter 17.

Build the next reading route from the packet type

Confirm RID, PASID, mode and platform service, then each Support/Enable. Use Table 10-1 for AT, match Translation Completions to their original Requests, decode size and permissions, and only then form data access. Mapping changes add range, ITag Vector, CC and in-flight Transaction checks; Page Requests add PRG, Last, PASID, allocation and Response Code checks.

Stopping/reusing PASID also needs §6.20.1 and Chapter 10's rules for old Requests, Posted Writes, ATC entries and Page Requests. Reset and ATS Enable changing from 0 to 1 cause implicit invalidation too; a prior snapshot is not a current cache inventory.
