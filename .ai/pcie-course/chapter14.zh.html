收到一段封包資料，要從哪個欄位開始讀？

選擇步驟後，圖中對應的元件與下方解說會加上重點標示。完整圖與所有解說會持續顯示；也可用方向鍵切換步驟。

圖上先分成兩種格式，再接回相同的交易目的。這是封包判讀路線，不代表硬體先後切換兩種模式。

TLP（Transaction Layer Packet，交易層封包）把要求、回覆與訊息送過 PCIe。讀取封包前，先確認 Link 使用 Non-Flit Mode（非 Flit 模式）或 Flit Mode（固定傳輸單元模式）；兩者的 TLP（承載交易的封包）標頭布局不同。本章從這個分岔開始，把格式欄位接到位址、資料長度與有效 byte。

  1. 先確認目前格式

    先從觀察位置確認 Link 模式；不要只憑封包第一個 byte 猜測。

    Non-Flit Mode 先讀 Fmt 與 Type；Flit Mode 先讀 8-bit Type。相同的 byte 值，在兩種格式可能有不同意義。

    Base 6.0 §2.2.1，Figures 2-4–2-6、Tables 2-2–2-5，pp.119–123。

  2. 找出後續欄位的位置

    OHC（Orthogonal Header Content，正交標頭內容）須按 A、B、C、E 的順序出現；需要哪些內容另由封包種類決定。

    非 Flit 格式由 Fmt 說明 3 或 4 DW 標頭及資料是否存在；Flit 格式用 Type 的表列資訊，再加 OHC 與 TS。DW 是 Double Word，等於 4 bytes。

    Base 6.0 §2.2.1.1–§2.2.1.2，pp.119–123、130–132。

  3. 再讀交易內容與 byte 選擇

    Byte Enables 的細節依模式、種類及條件而異；後面的算例限定普通非 Flit Memory Write。

    依已辨識的封包種類，定位位址或目的識別碼，再讀 Length 與 Byte Enables（有效 byte 選擇）。不能把讀取要求的長度解釋成要求本身帶有同樣大小的資料。

    Base 6.0 §2.2.5.1／Figure 2-26，pp.149–150；§2.2.9，p.195。

為什麼不能只背一張標頭圖？

在非 Flit 格式，先用 Figure 2-4 找 byte 0 的 Fmt／Type，再對 Table 2-2、Table 2-3。以 Memory Read 為例，Fmt 可表示 32-bit 或 64-bit 位址布局，要求不帶資料；Memory Write 則帶寫入資料。Type 也會影響路由，因此只看 Length 還不足以找到下一個封包。

換成 Flit 格式時，從 Figure 2-6 與 Table 2-5 重新開始。Type 不再只是舊格式的五個 bits；例如 Table 2-5 的 NOP 是 00h，而 32-bit 位址 Memory Read 是 03h。若沿用非 Flit 的解碼表，第一步就會讀錯。

找到基本標頭後，怎麼走到資料？

OHC（用來補充標頭資訊的擴充內容）由 Figure 2-6 的 OHC 欄位指出。接著讀 p.131 的出現順序，再用 Table 2-6 選擇適用的 A 類布局。例如有明確 Byte Enables 的 Memory Request，要沿 Table 2-6 找到 Figure 2-7 的 OHC-A1。不要固定假設所有 Flit 標頭都是相同長度。

TS 是 Trailer Size，用來指出尾部大小與用途；它與 Length 的資料長度分開計算。非 Flit 格式另有 Prefix（標頭前的擴充內容）與 TD（TLP Digest 存在標記）。判讀工具應先完成整個格式的大小計算，再移到後一包。

Length 和有效 byte 要怎麼一起讀？

作者案例：一個普通非 Flit Memory Write，位址以 4-byte 對齊，Length=2 DW（每 DW 為 4 bytes），First DW BE=1100b，Last DW BE=0011b。先在 Figure 2-26 定位兩個 BE（Byte Enable，有效 byte 選擇）欄位，再按 §2.2.5.1 的規則讀每個 bit。

範圍承載的 byte 位置真正寫入
第一個 DW位址 +0 至 +3+2、+3
最後一個 DW位址 +4 至 +7+4、+5

封包承載兩個 DW 的資料範圍，其中四個 bytes 被選為寫入。Length 沒有改成 1 DW，因為它描述的是封包資料長度。若 Length=1 DW，Last DW BE 必須為 0000b；這個條件在 Figure 2-26 下方，讀圖時要一起看。

封包有回覆時，從哪裡接著讀？

先按 §2.2.9 確認這類要求需要 Completion（完成回覆）。Memory Read 的資料隨完成回覆返回；一般 Posted Memory Write 沒有對應的成功完成回覆。接下來到 Chapter 15，沿接收端的處理流程，確認合法性、能力與回覆結果。
