CAS 回覆成功，目標就一定被換掉了嗎？

不一定。CAS（比較後交換）只在原值等於比較值時寫入交換值；比較不相等也是正常執行結果。要求者要把回傳的原值與自己送出的比較值相比，才能知道這次是否交換。Successful Completion（SC，交易正常完成）本身沒有另設「比較相等」的旗標。

Request 帶 8 bytes，為什麼目標只占 4 bytes？

查 Table 2-15（p.162）時，先選 CAS 這一列，再看 32 Bits 這一欄，得到 Request Length=2 DW，也就是兩個運算值共 8 bytes。目標的讀取、可能的寫回，以及回傳原值，各自仍是單一 32-bit 值。DW（Double Word）為 4 bytes。

接著讀 p.163 的自然對齊與 4-KB 邊界規則。本例地址可被 4 整除，目標範圍為 0x80001FFC–0x80001FFF，剛好占該 4-KB 頁面最後 4 bytes，沒有跨頁。若直接把 Request 的 8-byte Data 長度加到地址上，就會錯把這筆 CAS 判成跨界。CAS 的兩個運算值共同作用於同一個目標，不是寫入兩個相鄰位置。

再看 Completion，哪些欄位要按 AtomicOp 解讀？

用 Figure 2-73（p.196）定位回覆的 Requester ID 與 Tag，核對仍是 0300h／2Ah；配對方法已在 Chapter 5 帶讀。這次成功回覆是 CplD，Length=1 DW，Byte Count=4，Data 為原值 7。Request 帶 2 DW，並不要求 Completion 也回傳 2 DW。

DMWr 的「重試」與 CAS 的「比較不相等」有何不同？

DMWr（Deferrable Memory Write，可由完成端延後接受的非 Posted 寫入）適合共享工作佇列。它有必要的 Completion，但不是用來讀改寫一個比較值。遇到暫時條件時，完成端可回覆 Request Retry Status（RRS，要求重試狀態），並保持目標不變。

【模擬資料】以下資料為教學用途建立，不代表特定硬體或平台。假設另一組路徑與完成端已支援並啟用 DMWr，來源的 DMWr Requester Enable 也為 1。第一次提交工作項目時，共享佇列暫時無法接受，完成端因此回覆 RRS，沒有加入這項工作。要求者稍後可依實作政策重新提交；若新要求成功，才按該佇列的介面接續追蹤工作。成功接受提交與工作內容已執行完畢，仍是不同時點。

如果 CAS 逾時，能把同一筆要求再送一次嗎？

先確認是哪一層的重送。Data Link Replay 由相鄰兩端保護同一次傳輸，接收端會避免重複交付；要求者重新產生一筆 CAS，則會再執行一次操作。兩者的區別見 Chapter 8。

Completion Timeout（完成回覆逾時）是要求者等不到必要回覆時記錄的結果。即使沿用前面的 CAS，也有兩種不同時間線：Request 尚未到達目標；或目標已完成比較與交換，但 Completion 沒有被要求者收到。只有要求者的 Timeout，無法分辨這兩條時間線。

因此，原要求的結果尚未確認時，恢復程式不能把它直接當成「沒有執行」再送一次。應先保存原 Request、Requester ID／Tag、沿途 Trace 與錯誤資料，再依平台或裝置的同步與恢復協定決定後續動作。稍後讀到的記憶體值也可能經過其他處理器或裝置更新，不能替代遺失的 Completion。這是由回覆機制推得的分析邊界；Base 6.0 沒有提供通用的軟體重試演算法。

正常收到 SC 時，也要區分操作種類：CAS 回傳原值，供要求者判斷是否交換；Memory Read 若有多筆 Completion，則須收齊必要回覆才完成。§2.8 的逾時範圍用於偵測異常，不能拿來估計一般服務延遲。若後續 Request 必須等 AtomicOp 被完成端觀察到，§6.15.2 要求先等 AtomicOp Completion，再發出後續 Request。

本章的原子保證針對目標位置的操作。對支援 AtomicOp 的 Root Port，§6.15.3.1 另外要求：代辦主記憶體存取時，須與處理器或裝置對該範圍的存取維持原子性，並保留 CPU 原子操作的原子性。整個同步演算法、其他位置的資料發布順序，以及軟體使用的記憶體屬性，仍須搭配平台與 CPU 文件；不能只靠一次 CAS 推出全部條件都已滿足。

規格閱讀：§2.8 Completion Timeout Mechanism，pp.259–260；§6.15.2，p.774；§6.15.3.1，p.775。Replay 與軟體重試的區別在此作跨章節應用，不重複展開其狀態機。

Locked Transactions 是同一種原子機制嗎？

Locked Transactions（鎖定交易）在 §6.5.1 有不同限制：只有 Root Complex 可發起，PCI Express Endpoint 不得支援鎖定存取，新軟體也不得使用會對 I/O 裝置產生鎖定存取的指令。它不能當成某個 AtomicOp 不支援時，任意改用的替代方案。
