PCIe transmission depends on Link training, receive-buffer credits, and reliable delivery. This chapter uses evidence from both ends of one Link to distinguish supported speeds, the configured limit, and the negotiated result, then separates credit accounting (receive-buffer space) from replay (link-level retransmission).

Link training and Function readiness are separate stages

The Physical Layer Link Training and Status State Machine (LTSSM) establishes receive synchronization, Lane relationships, and Link width. The main initial path is Detect, Polling, Configuration, and L0. Configuration here is a training state, not Base Address Register (BAR) programming. Recovery restores synchronization or changes speed. Its entry reason and subsequent state explain which operation is taking place.

Once the Physical Layer is operational, the Data Link Layer still completes applicable Feature Exchange and Virtual Channel 0 (VC0, the default transmission resource group) Flow Control initialization before DL_Active (the active data-link state). Configuration readiness, BAR (device-resource base address) setup, and Direct Memory Access (DMA) preparation are separate conditions. Data Link Layer Packets (DLLPs) remain between adjacent Link partners; Transaction Layer Packets (TLPs) can traverse Switches to another component.

Credits manage space; replay protects this hop

In Non-Flit Mode, each Virtual Channel separately tracks Header and Data credits for Posted, Non-Posted, and Completion traffic: six classes. One Data credit represents 16 bytes; Headers are accounted separately. An authored VC0 (default Virtual Channel) example starts with finite, unscaled available Posted Header (PH)=2 and Posted Data (PD)=5, without competing traffic. A 64-byte Memory Write (MWr) consumes 1 PH (Posted Header) and 4 PD (Posted Data), leaving 1/1. A following 32-byte MWr (Memory Write) requires 1/2 and waits until available PD increases by 1. This is an available-credit ledger, not a standard software-readable Register or a minimum initial advertisement.

A 256-byte Memory Read (MRd) request has no data Payload and needs only one Non-Posted Header (NPH) credit; its return traffic consumes Completion credits in the opposite direction. Sufficient credits do not guarantee immediate scheduling: ordering and arbitration still apply.

Non-Flit sequence numbers, LCRC (Link Cyclic Redundancy Check, the error-checking code), ACK/NAK (positive/negative acknowledgement), and replay provide adjacent-Link reliability. The transmitter retains copies; a NAK (negative acknowledgement) or acknowledgement timeout can cause replay. The receiver handles duplicate copies, and the Transaction Layer does not charge new credits again for the same TLP (Transaction Layer Packet). An ACK (positive acknowledgement) on one hop is neither a transaction Completion nor device-work completion. Posted MWr has no ordinary Completion but still receives Link-level protection.

Flit Mode uses a fixed transport unit

64 GT/s uses Flit Mode, which can also operate at lower rates. A 256-byte Flit contains 236 bytes for TLPs, 6 for Data Link Layer Payload (DLP), 8 for Cyclic Redundancy Check (CRC), and 6 for Error Correction Code (ECC). TLPs can span Flits, and multiple TLPs can share one Flit; the TLP region is not all application data. Replay operates at Flit granularity. Forward Error Correction (FEC) neither eliminates replay nor corrects every possible error.

Check Flit Mode Supported in PCI Express Capabilities before interpreting Downstream Port Link Status 2. A projection containing only Presence and the Flit bit of 0x4400 means Presence=100b and Flit=1: Link up, with no Device Readiness Status (DRS) received yet. A projection of 0x3400 means negotiation has completed but the Data Link Layer is not active. These are field projections, not full dumps; the Flit bit is meaningful only for Presence=011b, 100b, or 101b.
