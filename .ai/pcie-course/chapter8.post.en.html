PCIe transmission depends on Link training, receive-buffer credits, and reliable delivery. This chapter uses evidence from both ends of one Link to distinguish supported speeds, the configured limit, and the negotiated result, then separates credit accounting from replay.

Version and assumptions

Base 6.0. The authored example connects Switch Downstream Port 02:01.0 to Endpoint 03:00.0, with PCI Express Capability at 0x70, version 2, at both ends. It uses Non-Flit Mode; Flit Mode is compared separately.

Link training and Function readiness are separate stages

The Physical Layer LTSSM establishes receive synchronization, Lane relationships, and Link width. The main initial path is Detect, Polling, Configuration, and L0. Configuration here is a training state, not BAR programming. Recovery can restore synchronization or change speed; observing it alone does not establish a fault.

Once the Physical Layer is operational, the Data Link Layer still completes applicable Feature Exchange and VC0 Flow Control initialization before DL_Active. Configuration readiness, BAR setup, and DMA preparation are separate conditions. DLLPs remain between adjacent Link partners; TLPs can traverse Switches to another component.

Credits manage space; replay protects this hop

In Non-Flit Mode, each Virtual Channel separately tracks Header and Data credits for Posted, Non-Posted, and Completion traffic: six classes. One Data credit represents 16 bytes; Headers are accounted separately. An authored VC0 example starts with finite, unscaled available PH=2 and PD=5, without competing traffic. A 64-byte MWr consumes 1 PH and 4 PD, leaving 1/1. A following 32-byte MWr requires 1/2 and waits until available PD increases by 1. This is an available-credit ledger, not a standard software-readable Register or a minimum initial advertisement.

A 256-byte MRd has no data Payload and needs only 1 NPH; its return traffic consumes Completion credits in the opposite direction. Sufficient credits do not guarantee immediate scheduling: ordering and arbitration still apply.

Non-Flit sequence numbers, LCRC, ACK/NAK, and replay provide adjacent-Link reliability. The transmitter retains copies; a NAK or acknowledgement timeout can cause replay. The receiver handles duplicate copies, and the Transaction Layer does not charge new credits again for the same TLP. An ACK on one hop is neither a transaction Completion nor device-work completion. Posted MWr has no ordinary Completion but still receives Link-level protection.

Flit Mode uses a fixed transport unit

64 GT/s uses Flit Mode, which can also operate at lower rates. A 256-byte Flit contains 236 bytes for TLPs, 6 for DLP, 8 for CRC, and 6 for ECC. TLPs can span Flits, and multiple TLPs can share one Flit; the TLP region is not all application data. Replay operates at Flit granularity. FEC neither eliminates replay nor corrects every possible error.

Check Flit Mode Supported in PCI Express Capabilities before interpreting Downstream Port Link Status 2. A projection containing only Presence and the Flit bit of 0x4400 means Presence=100b and Flit=1: Link up, with no DRS received yet. A projection of 0x3400 means negotiation has completed but the Data Link Layer is not active. These are field projections, not full dumps; the Flit bit is meaningful only for Presence=011b, 100b, or 101b.

Check the boundaries

Does PD=0 prevent an MRd from being sent?

Not necessarily. MRd checks NPH; other transmission conditions still apply. (Table 2-45, p.237.)

Does ACK prove that the CPU has consumed DMA data?

No. Its scope is adjacent-Link delivery. Final visibility, ownership, and work completion depend on their respective interfaces.
