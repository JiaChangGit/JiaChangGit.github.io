D0 是 Function 的工作電源狀態，並沒有單獨決定整張卡可以消耗多少功率。Power Budgeting（功率預算）處理系統供應與裝置需求；DPA（Dynamic Power Allocation，動態功率配置）處理 D0 內的功率子狀態；緊急降載另有用途與優先關係。

要替新插卡預留功率，先查哪裡？

先用 Table 6-10 確認資料的涵蓋範圍，再到 Figure 7-136 找 Data Select 與 Data Register。§7.8.1.2 說明索引從 0 起，寫入索引後，Data Register 顯示對應的功率資料。它的預設索引未定義，因此不能略過選擇步驟就假定讀到第一筆。

Power Budgeting 的部署還受外形規格影響。裝置／插卡在系統配置並啟用之前，須保持在相應機電規格的 configuration power limit 之內；系統也應先妥善安排預算，再啟用插卡。這不等於只要裝置存在，就能取得完整額定功率。

DPA 子狀態能直接當成 D1、D2 嗎？

不能。§6.16 的子狀態在 D0 內運作，從 0 到 Substate_Max 連續編號，後一級的功率配置不得高於前一級。軟體可以直接選擇某級，不必逐級經過。這些子狀態不等同 D1–D3，也不等同 L1.1／L1.2。

作者案例：假設三個已宣告子狀態分別配置 20、15、8 W。軟體把控制從 0 改為 2 時，須再讀狀態確認轉換進度。從高功率轉往低功率期間，Status 仍須表示較高功率狀態，完成後才表示較低狀態；從低轉高時則在轉換期間就表示較高狀態。

若裝置有 SR-IOV（Single Root I/O Virtualization，單根 I/O 虛擬化），VF（Virtual Function，虛擬功能）的 DPA 功率由關聯 PF（Physical Function，實體功能）管理，VF 不得實作 DPA Capability。

緊急降載與一般省電如何接？

§6.24 把 Emergency Power Reduction（緊急功率降低）定義為可選的 fail-safe。它會優先於所述的一般功率控制機制。觸發方式要依 Supported、Initialization Required 與 Table 6-16 的條件，不能看到名稱就假設固定由一個標準 Configuration bit 發起。

SR-IOV 的一般電源狀態另回到 §5.10：PF 必須有電源管理能力，VF 則可選。若 VF 有自己的能力，PF 比 VF 進入更低功耗狀態時，裝置行為未定義；軟體應先降低所有 VF 的電源狀態，再降低其 PF。
