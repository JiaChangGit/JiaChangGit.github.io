Separate function and link power before configuration

Function D-states and link L-states describe different objects. A function in D0 can use a link that enters power saving through ASPM (Active State Power Management) when the required conditions hold.

Specification route: Tables 5-1/5-2 → PM and link fields → L1 PM Substates in Figures 7-146–7-150 → latency tolerance and exit timing.

PCIe power management spans Functions, Links, and the platform. D-states, ASPM, L1 Substates, and wake each have distinct controls and evidence; an Enable bit alone does not establish current state. PMCSR and L1.2 examples connect discovery, configuration, and recovery.

Versions and assumptions

PCIe follows Base 6.0; platform background uses ACPI 6.6. All numeric examples are authored. PMCSR concerns ordinary Endpoint 03:00.0. The separate L1.2 Link has the necessary capabilities at both ends, LTR, CLKREQ#, and suitable timing design. Neither example includes SR-IOV or adds undeclared features to earlier examples.

Function D-states and Link L-states are separate

D0 is the normal Function state, but ASPM can save Link power during idle periods in D0. D1/D2 are optional. D3hot retains main power; D3cold lacks main power but may retain auxiliary power for wake. D0uninitialized after reset does not establish readiness of the work interface.

L0 supports transmission. L0s can operate independently by direction, but is unsupported in Flit Mode, with Retimers, or under specified independent-SSC clock conditions. L0p is Flit-only and idles some Lanes while retaining at least one active Lane in each direction. L1 can have L1.0/L1.1/L1.2 substates. L2/L3 follow main-power removal and differ by the presence of Vaux.

Read PM capabilities, then construct the D0 write correctly

Conventional Capability ID=0x01 identifies PM. An authored full-DWORD read at 0x40 returns 0xC8035001: ID=0x01, Next=0x50, Version=3, no D1/D2 support. PME_Support=(value >> 27) & 0x1F = 0x19 allows PME from D0, D3hot, and D3cold. Assume no optional Data Register, Aux_Current=0 using self-power, and necessary power availability. This is capability evidence, not proof of a complete wake path.

ASPM enablement needs capabilities and a latency policy

ASPM manages an idle Link in D0; PCI-PM uses software-directed D-state changes. An ordinary non-ARI multifunction device must have all Functions outside D0 before initiating L1 on behalf of PCI-PM.

Inspect both Link Capabilities ASPM Support fields, then Link Control ASPM Control. Enablement does not report current L1 residency. Compare Link Capabilities L1 Exit Latency with Endpoint Device Capabilities L1 Acceptable Latency across the path. Exits can overlap across Links, so adding every Port's latency is incorrect; Figure 5-8's example finishes at T+34 μs.

The same Enable can produce different entry decisions

Control 1 threshold Value=128, Scale=2 gives 128 × 1024 ns=131072 ns (131.072 μs). Assume ASPM L1.0, deasserted CLKREQ#, and all other entry conditions satisfied. Latest valid snoop/no-snoop LTR requirements of 204800/102400 ns fail because no-snoop is below threshold. Changing them to 204800/153600 ns satisfies both, requiring entry under these assumptions.

No requirement for a traffic class is a separate branch, not Requirement=1 with Value=0; the latter requests the best possible service. These are latest valid reports, not Max Latency Register limits. LTR is also not a hard Root Complex latency guarantee. L1.1 is not enabled here, so it is not an assumed fallback. Before enabling Endpoint LTR, the Root Complex and intervening Switches must support it, with devices closest to the Root Port enabled first.

Wake restores communication before identifying the source

L2 cannot carry ordinary TLPs. The device uses form-factor-appropriate WAKE# or Beacon to request power, clock, and Link restoration, then sends PM_PME with its Requester ID. PME_En, auxiliary power, and platform routing must cooperate. (§5.3.3.1–§5.3.3.2, pp.615–616.)

Check whether the conditions are sufficient

Does No_Soft_Reset=1 preserve all state through D3cold?

No. It applies to the specified software D3hot-to-D0 transition.

Can only the Endpoint enable L1.2 when its partner lacks support?

No. Both capabilities, configuration order, LTR, and timing conditions must hold.
