Sharing one Switch does not settle a packet's path. Follow ACS (Access Control Services) decisions at the ingress, then a four-window Multicast case with two outputs, address Overlay and ECRC handling.

Locate the ingress ACS controls before following A to B

A enters the Switch through DP1; normal address decoding selects DP2 toward B. DP1 is the Ingress Port and DP2 the candidate Egress Port. Read the ingress DP1 ACS (Access Control Services) controls for this P2P (Peer-to-Peer) Request.

Simulated data: UP0 has Port Number 0; DP1/DP2/DP3 have Numbers 1/2/3. A/B/C use Requester IDs 0300h/0400h/0500h. DP1 has Secondary and Subordinate Bus Number 03h, without FPB. B's BAR covers 90000000h–90000FFFh; C's covers A0000000h–A0000FFFh. Required resources, Windows, Memory Space Enable, Bus Master Enable and Link transport are ready. Packet examples use Non-Flit Mode, without Reset or Replay events.

Connect capability, control and the destination vector bit

Walk the capability list for ID 000Dh, Version 1, and use Figure 7-131. With DP1's base A, A+04h is ACS Capability, A+06h ACS Control and A+08h the Egress Control Vector.

Capability 087Fh advertises the first seven controls, no ACS Enhanced Capability, and eight vector bits. Control 001Dh enables Source Validation, P2P Request Redirect, P2P Completion Redirect and Upstream Forwarding. Translation Blocking, P2P Egress Control and Direct Translated P2P are disabled.

For selective control toward B, use DP2's Port Number 2. Equation 7-4 gives offset 08h+(2 div 32)×4=08h, bit 2, mask 00000004h. The index is not B's Bus Number, Function Number or analyzer channel. Egress Control Enable determines whether that vector participates.

Vector Size 00h means 256 bits when Egress Control is supported. Without that capability, Size is undefined and the vector need not exist.

Continue through the RC, return traffic and error handling

Return to Control 001Dh. Required ACS Upstream Forwarding along the redirection path must be effective, and the RC must implement Redirected Request Validation. Upstream Forwarding handles traffic that would otherwise return through the receiving Downstream Port's own egress; relevant handling is undefined when it is disabled. A single-Function Switch Upstream Port does not thereby require its own ACS Capability.

RC validation decides whether a Request is reflected Downstream or blocked as ACS Violation. Its algorithms and specific controls are platform defined. Root Port Redirect capability does not imply any level of RC P2P support. For the normal example, additionally assume RC validation permits reflection through the Root Port, Switch UP0 and DP2 toward B. Downstream Ports do not redirect that Downstream Request back Upstream. B's internal write result still needs observation.

Separately consider B's Completion for an earlier Memory Read from A. It enters DP2, so read DP2's Completion Redirect control. When enabled, a peer Completion with RO (Relaxed Ordering)=0 redirects Upstream; RO=1 routes normally. Request Redirect, Egress Control and Translation Blocking do not affect Completions.

Completion redirection prevents a direct non-RO Completion from effectively passing a redirected Posted Request. Mixed paths need §6.12.6's ordering analysis; fewer hops alone do not establish legality. Full Passing rules are in Chapter 15.

An ACS Violation on a Non-Posted Request requires a CA (Completer Abort) Completion; a Posted Write has no such ordinary reply. The handling component logs ACS Violation, not Completer Abort Error merely because it sent CA. Section 6.12.5 also specifies target-abort status and reporting. Continue AER handling in Chapter 12.

Select a group before copying the Write to B and C

Multicast copies one Posted Request to configured outputs. Read Figure 6-14's windows, then §6.14.1's hit conditions, then membership. Only Memory Writes and Address Routed Messages can hit. A Non-Posted Memory Read inside the same address window remains unicast.

This separate simulated configuration gives all applicable Switch structures identical MC_Enable, MC_Num_Group, MC_Base_Address and MC_Index_Position. Deliver copies to ordinary BARs without hiding ECRC errors

DP2/DP3 apply MC_Overlay, an egress address replacement. Figure 7-280/Table 7-250 decode raw 000000009000000Ch as base 90000000h and MC_Overlay_Size=12; DP3 uses base A0000000h. Size below 6 disables Overlay; zero does not specify a one-byte aperture.

Equation 6-1 preserves address bits 11:0 and replaces the rest from each egress Overlay base. Address 80002500h becomes 90000500h at DP2 and A0000500h at DP3, inside their preconfigured BARs. Overlay acts on exit, not on ingress, and does not allocate the Endpoint BARs.
