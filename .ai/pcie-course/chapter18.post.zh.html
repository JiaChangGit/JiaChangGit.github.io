前章已分清 credit、Ack 與交易完成。本章把 TLP（交易層封包）放進 Flit（固定大小的傳輸單元），再沿 Lane 追到接收端。先看正常的配置與檢查，再用 Selective Replay 案例說明 DLP 與 TLP 的不同處理。

先認出模式，再選線路編碼

64.0 GT/s 使用 PAM4（Pulse Amplitude Modulation 4-levels，四階脈衝振幅調變）及 Flit Mode；較低速率也可以使用 Flit Mode。讀 Trace 時，先確認觀察的是哪條 Link、哪個方向、當時的速率和模式，再選對應的解碼方式。

p.309 的模式識別說明可以連回三個位置：PCI Express Capabilities Register 的 Flit Mode Supported 表示支援能力；Link Control Register 的 Flit Mode Disable 是控制；Link Status 2 Register 的 Flit Mode Status 表示 Link 正在或將以 Flit Mode 運作。訓練期間的宣告與成功協商的變數 Flit_Mode_Enabled 也在這裡說明；它們不是同一項資訊。

正常接收時，FEC 與 CRC 怎麼接力？

PAM4（每個訊號間隔以四階電壓表示 2 bits）提高每個訊號間隔可表達的資訊量，但較小的眼高與眼寬使錯誤更容易發生。FEC（Forward Error Correction，前向錯誤更正）先嘗試更正，再用 Flit CRC 檢查；兩者負責的工作不同。

把 Figure 4-22 與 Figure 4-23 放在一起讀：傳送端先對 236-byte TLP 區域加 6-byte DLP 產生 8-byte CRC，再產生 ECC，然後分配到各 Lane。接收端先完成適用的 Lane 解碼與解擾，把資料合回 Flit，接著做 FEC 解碼／更正，最後檢查 CRC。圖中的寬度是概念示意，並沒有要求硬體使用相同內部資料寬度。

沿用前面的 x4 情境，假設某次接收出現一個可更正的 byte 錯誤；FEC 更正後沒有 ECC group 回報不可更正，CRC 也通過，Flit Usage 與 Flit_Status 均為合法值。依 §4.2.3.4.2，這是有效 Flit。接收端仍須依序號、重送狀態與 TLP 格式處理，才能把適當的 TLP 內容交給上層；CRC 通過本身沒有證明 Request 已完成。

Table 4-12 的顏色代表三個 ECC groups，不是三條 Lane。每個 group 可更正一個 byte 錯誤；錯誤分布到哪個 group，會影響能否更正。因此，不能只數整個 Flit 有幾個錯誤 byte，就宣稱都在更正能力內。若 CRC 失敗或某個 group 回報不可更正，Flit 不符合有效條件，後續要依接收與 Replay 規則處理。

收到 Nak 後，重送的 Flit 要逐 byte 相同嗎？

TLP 內容會重送，DLP 則使用當下的管理資訊。§4.2.3.3 明確說明，DLP 不進入 Link Layer Retry Buffer；重送時重新帶入最新 DLP。由於 CRC 包含 DLP，傳送端也要對這次的內容重新產生 CRC 與 ECC。

再讀反方向的 Selective Nak

Endpoint 收到該 Flit 時，FEC 處理後的 CRC 仍失敗。假設後續接收資訊足以確認受損者為 Payload Flit，Endpoint 有足夠的 RX Retry Buffer 保存後續資料，並選用 Selective Nak（只要求重送指定 Flit 的通知）。其中一個有效的反方向 NOP Flit 帶有 1D 29 80 00 00 00；本例該方向前一個 Flit 也是 NOP，因此 Prior Flit was Payload 為零。
