前章已分清交易完成與 Link 重送。現在再往下看：TLP（Transaction Layer Packet，交易層封包）先裝入 Flit（固定大小的傳輸單元），再依速率編碼送上 Lane。這三個層次各自處理不同範圍，不能把「一個 Flit」理解成「一筆交易」。

同樣叫 Flit，低速與高速的差別在哪？

先讀 p.309 的模式識別說明，分清 Supported（硬體能力）、Disable（控制設定）、Enabled（協商結果）與 Status（目前或即將使用的狀態）。硬體宣告支援 Flit，不代表這條 Link 已成功協商使用。

要追一個 byte，該先看哪張表？

先從 §4.2.3.3 的 256-byte 分配定位用途，再到 Tables 4-10–4-14 依 Link 寬度追蹤 byte 如何分散到各 Lane。DLP（承載鏈結層資訊的區域）位於 bytes 236–241；bytes 242–249 是 CRC，250–255 是更正碼。

作者算例：只比較固定 Flit 區域的比例，TLP 區域占 236/256＝92.1875%。這還沒扣交易標頭、填充、控制交換與等待，所以不是裝置的有效讀寫率。要估算應用吞吐量，還要接到 Chapter 37 的工作負載。

更正、檢查與重送怎麼配合？

PAM4（每個訊號間隔使用四階電壓的調變）提高每次傳送的位元數，但相鄰電壓間隔變小，對雜訊與突發錯誤更敏感。FEC（以冗餘碼更正部分錯誤）先提供更正能力，Flit 層 CRC 檢查再搭配 Link 重送。這裡的目的，是看懂三種手段為什麼同時存在。

若要核對演算法輸出，Appendix J 先提供 alpha power 與編解碼器的檔案對應；§J.2 的 84-to-86-byte 編碼器可用來追蹤資料、check 與 parity 的關係。Appendix K 則提供 CRC generator matrix 的對應檔案。它們是演算法核對入口，不能把範例 RTL 的內部結構當成所有硬體必須採用的實作。

附錄 B、C 又在哪裡用？

Appendix B 的 Table B-1 按資料 byte 與 Running Disparity（累積位元不平衡狀態）選擇 8b/10b 代碼；它不是 Flit 的 byte 配置表。Appendix C 則示範資料擾碼的演算法。§C.1 明確說明可以使用其他實作，但必須產生相同輸出。先分清查的是線路代碼、擾碼結果或 Flit 區域，才會走到正確附錄。
