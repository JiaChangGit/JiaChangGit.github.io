ATS（Address Translation Services，位址轉譯服務）讓裝置向平台查詢轉譯並快取。ATC（Address Translation Cache，位址轉譯快取）保存結果，TA（Translation Agent，轉譯代理）處理轉譯與保護資訊。接著必須安排失效通知，才不會繼續使用舊映射。

想教一筆 DMA 存取，為何先看 Figure 10-1？

DMA（Direct Memory Access，裝置直接記憶體存取）的位址可涉及平台轉譯。先用 Figure 10-1 確認 ATC（裝置保存的轉譯快取）與轉譯代理的位置，再沿 Figure 10-2 看 Translation Request／Completion。代理會檢查該功能是否已配置可發轉譯要求，及是否有對應存取權。

本章只使用 Base 6.0 Chapter 10 的協定與角色。平台的頁表格式、特定 IOMMU（Input/Output Memory Management Unit，I/O 記憶體管理單元）暫存器與作業系統介面，另有其規格，不能由這張圖自行補成所有平台都相同的實作。

同一頁換了映射，快取可以繼續用嗎？

作者情境：裝置可能快取某頁的舊轉譯，平台準備改變映射。§10.3 要求代理與軟體透過失效要求維持一致性。先看 Figures 10-18／10-19 選對模式的要求格式，再回 Figure 10-5 看一筆失效要求可能對應多個完成回覆的情境。

這裡的完成回覆是失效協調的一部分，不是應用資料讀取完成。後續是否可回收或重新使用記憶體，必須同時滿足失效、在途要求與平台生命週期規則；單憑已修改頁表不能推出裝置停止使用舊映射。

同一個 Function 有多個位址空間，怎麼區分？

PASID（用來區分程序位址空間的識別碼）與 Requester ID 合在一起才形成要求的上下文；各 Function 的 PASID 值彼此無關。非 Flit 模式放在 PASID Prefix，Flit 模式則位於 OHC-A1。使用前還須檢查 Enable；帶 PASID 的已轉譯要求另有 Translated Requests with PASID Enable 條件。

頁面尚未可用時，PRI 接在哪裡？

PRI（Page Request Interface，頁面要求介面）讓裝置要求平台準備所需頁面；它不是 ATS 回覆的另一個名稱。沿 §10.4 的模型，先送頁面要求與 PRG（Page Request Group，頁面要求群組）索引，平台回覆群組結果後，裝置才可再透過轉譯服務取得對應資訊。

PRI（提出頁面需求的介面）有自己的要求額度；每個 Page Request 消耗額度，不是每個群組只算一次。Page Request 與群組回覆使用 TC0，各群組也不保證依發送順序完成。
