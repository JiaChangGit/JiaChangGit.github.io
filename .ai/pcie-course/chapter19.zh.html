升速時，再沿 Recovery 追到 Equalization

初次 Link 先以 2.5 GT/s 到 L0，即使兩端都支援更高速率也是如此；之後可從 L0 進 Recovery 改變速度。Polling 中宣告的高速度能力，不代表當時已用該速度傳輸。§4.2.7.2.4 也明確指出 Polling.Speed 不可達，不要把它補進初次升速路徑。

Equalization（等化，調整每條 Lane 的發送與接收設定以補償通道影響）有速率相關的流程。§4.2.4 要求第一次切換到各個 8.0 GT/s 以上速率時執行適用程序，但另定義了所有元件共同支援與宣告後可採用的略過機制。這裡先分清一般程序、略過到最高 NRZ 速率，以及 No Equalization Needed；不可因某端宣告一個 bit，就替整條路徑省略訓練。

升速紀錄需要接起「哪一端提出變更、進了哪些 Recovery 子狀態、適用的等化流程、最後速度與寬度」。Chapter 8 的雙端 Register 與狀態帶讀可作查詢入口。經過 Recovery 也不等於重新列舉或清掉所有 Data Link 狀態，須按實際的 LinkUp 與 Reset 歷史判斷。

接著查 §4.3.2 的模式：Forwarding mode 轉送適用的符號及 Electrical Idle；Execution mode 則在 Polling.Compliance、等化 Phase 2／3 等指定情境參與協定。追查某一段的等化結果時，要標明 Pseudo Port 與方向，不能用 Root Port 的整體狀態替每一段補出相同結果。

Base 6.0 允許同一條 Link 最多兩個 Retimers，外形規格仍可能加上限制。這些元件對 Data Link 與 Transaction Layer 透明；不能替它們各配置一組 Bridge Bus Number，也不能把分段等化當成多組獨立的 TLP Ack／Replay。電氣品質是否合格，還需要 Chapter 8 的適用要求與實際量測。

低功耗與測試分支，另外確認目的與條件

L0p（L0 內部分 Lane 省電的機制）只用於 Flit Mode，保持對稱的目標寬度，且每方向至少有一條活動 Lane。它不是讓整條 Link 先離開 L0 再重建；轉換期間兩側也可能短暫處於不同寬度。相對地，L0s 是另一種快速省電狀態，在 Flit Mode、有 Retimer，或使用獨立 SSC（Spread Spectrum Clocking，展頻時鐘）的分離參考時鐘時，不得支援與宣告。

Polling.Compliance 用於測試；Loopback 的 Lead 發起測試，Follower 負責回送資料；Hot Reset 用 in-band 訊號重設配置好的 Link 與相關下游裝置。它們在 Figure 4-48 都有各自的分支。分析工具若只留下「沒有 TLP」，仍要補上具體狀態與進入條件，才能分清訓練、低功耗或測試。L1、Function 電源狀態與平台政策則接到 Chapter 9。

Link 從 x8 變成 x4，是降寬故障嗎？

教學假設：同一條 Link 連接 Switch Downstream Port A 與 Endpoint Upstream Port B；它已配置為 x8，正在 Flit Mode 運作。兩端的 Receiver L0p Supported 和 Remote L0p Supported 均有效，L0p Enable 為 1，Port A 的 Hardware Autonomous Width Disable 為 0。這些是作者設定的條件，不是實機量測。

先看 Device 3 Extended Capability 的 Figure 7-120：Capabilities 3 的 Receiver L0p Supported（接收端支援 L0p）描述本端能力；Status 3 的 Remote L0p Supported 描述對端支援資訊；Control 3 的 L0p Enable 則控制本 Port 能否發出要求及回覆 Ack。兩端支援且允許使用，是本案例開始前的條件，並不表示 Link 此刻已縮至 x4。

接著查 Table 7-109：在 L0p Enable=1 的條件下，向 Port A 的 Target Link Width 寫入 010b，會發起目標 x4 的 directed L0p 寬度變更。這個欄位只描述要求；實際是否完成，要看後續交換及 Lane 狀態。

Port B 回覆 Ack 後，兩端各自依下一個排定的 SKP 時機，讓要關閉的 Lane 送出 EIOSQ（進入電氣閒置的 Ordered Set），再進入 Electrical Idle；保留的 Lane 繼續傳送 Flit。這個示範是正常降寬流程；若看到 Nak、逾時、不同步或 Recovery，則需回到 §4.2.6.7 的對應分支。

配置時停用的 Lane 不能靠 L0p 開回來；進入 Recovery 時，Link 會回到最近進入 L0 時配置的寬度。因此，觀察到 x4 應先確認是 L0p 暫時縮減，還是配置或訓練得到的結果。Base 6.0 §4.2.6.7、§5.4.1.2、§7.7.9.2–§7.7.9.4，pp.445–447、626、1073–1077。

兩端回報的退出延遲，如何合併？

教學假設：Port A 的 Port L0p Exit Latency=010b（2 至小於 4 µs），關聯 Retimer L0p Exit Latency=001b（1 至小於 2 µs）；Data Link Feature Status 的 Remote Data Link Feature Supported Valid=1，Remote L0p Exit Latency=011b（4 至小於 8 µs）。

先看 Table 7-108：Port A 的 Local L0p Exit Latency 取 Port 與關聯 Retimer 較大者，因此是 010b。再查 Tables 7-64／7-65：本端與對端值經 Data Link Feature 交換；確認 Remote 資訊有效後，Link 的有效退出延遲取 Local 與 Remote 較大者，這裡落在 011b 的區間。
