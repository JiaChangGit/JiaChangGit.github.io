RN（Readiness Notifications，就緒通知）讓軟體在裝置或Function已可接受設定要求時得知消息。DRS（Device Readiness Status，裝置就緒狀態）與FRS（Function Readiness Status，功能就緒狀態）對應不同事件與範圍。先找事件與對象，再讀通知或等待條件。

看到 DRS 後，下一筆設定讀取怎麼理解？

§6.22.1說明DRS涵蓋的Configuration-Ready範圍。裝置送出通知後，所指示的非VF功能不得再對設定要求回RRS，直到又發生後續適用事件。Switch的就緒範圍另有明確規則，不能把通知擴大到所有物理整合在下方的裝置。

作者情境：重設後Link已啟動，管理者正在等待裝置就緒。若收到適用DRS，就依規則繼續設定；若尚未收到，應依支援狀態選擇適用的等待流程；§6.22 的 DRS-only 與 hybrid 建議各有前提。這裡的分支是不同就緒依據，不是「沒通知就永久無法使用」。

很多 Function 同時就緒，如何避免漏消息？

Root Port或RCEC若支援FRS，必須提供FRS Queueing。訊息依收到順序排隊；讀到最舊項目後，以規定的寫入操作移出。佇列滿時，丟棄新訊息並設Overflow，原有內容保留。這些是§6.22.3的明確行為，不能把Overflow當成佇列自動換成最新快照。

非同步拔除與外殼管理，還缺哪一塊？

先把Chapter 11–13的Hot-Plug、DPC與控制權接回來，再讀Appendix I。參考模型先確認管理者與所選機制，再處理插卡存在、就緒與中斷。DPC是建議機制，但整個參考流程本身不是強制規範。

NPEM（Native PCIe Enclosure Management，原生PCIe外殼管理）提供狀態燈等控制，可位於下游Port或Endpoint，位置要用Figures 6-35、6-36辨識。SFI（System Firmware Intermediary，系統韌體中介）另讓韌體介入部分事件；不要把LED狀態、裝置就緒與OS控制權混成一個bit。

重設後，要從哪裡開始等？

先確認發生的是裝置層級事件，還是特定 Function 的事件。DRS 對應裝置層級的就緒通知；FRS 對應特定 Function 的就緒通知。收到通知後，仍要確認它所涵蓋的對象，以及通知之後是否又發生新的適用事件。

手機閱讀時，可左右滑動表格查看完整內容。

作者情境先讀哪個線索接下來怎麼判斷
下游裝置的 Link 從 DL_Down 轉為 DL_UpDownstream Port 的 DRS Supported 與 DRS Message Received；再看 §6.22.1核對收到的 DRS 是否涵蓋目標非 VF Function。Switch Upstream Port 的 DRS 有自己的就緒範圍；Switch 下方物理整合裝置不由該 DRS 表示就緒。
某個 Function 執行 FLR若實作 FRS，檢查訊息的 Requester ID 與 FRS Reason；再看 §6.22.2確認訊息對應哪個 Function、哪一次事件。其他 Function 不能只憑這筆訊息判定就緒。
尚未收到通知看適用的等待機制及 §7.9.16 的 Valid規格提供多個入口；應先確認各自適用條件。已確認兩端 DRS 支援時，§6.22 的建議 DRS-only 流程與支援未知時的 hybrid 流程不同。

Configuration-Ready 指可依規則處理 Configuration Request；它本身不證明 BAR、驅動程式或裝置內部功能已完成初始化。上述情境為教學假設，並非實機資料。

FRS Queue 滿了，軟體還能知道什麼？

教學情境：假設 Root Port 的 Queue 已滿，內容依序為 A、B，此時新的 FRS 訊息 C 抵達。§6.22.3 規定保留 A、B，丟棄 C，並設置 FRS Message Overflow；讀 Queue Register 時先看到 A，寫入該 Register 才移除最舊項目，接著才能讀取 B。

FRS Message Received 或 Overflow 從 0 變成 1 時，若中斷已啟用則產生中斷。Overflow 告訴軟體曾有訊息未被排入，現存佇列無法補回 C 的內容。Reset 後 Queue 為空；Root Port 的 Link 轉為 DL_Down 時也會清空。RCEC 的 Queue 對應它自身或所關聯 RCiEP 產生的訊息，判讀前先辨識接收者。

裝置就緒、指示燈與熱插拔管理如何接起來？

Appendix I 的 Figure 與流程是非規範性的參考模型：先確認 OS 與系統韌體各自掌握哪些控制權，再選擇 Hot-Plug Surprise 或 DPC（Downstream Port Containment，下游連接埠隔離）；該模型建議有 DPC 時使用 DPC，但不代表所有平台都必須採用同一流程。

外殼指示另由 NPEM 處理。Figures 6-35、6-36 分別展示能力位於 Downstream Port 或 SSD 端的例子；Figure 6-37 再接到寫入 NPEM Control 與 command completed。命令完成表示介面回報完成，外殼接線、燈數及閃爍模式不在 Base 6.0 定義範圍內。燈號也不能代替 DRS 或 FRS 判斷 Configuration-Ready。

AF 的 FLR 可以直接套用一般 PCIe Function 嗎？

AF（Conventional PCI Advanced Features，傳統PCI進階功能）針對符合條件、整合在Root Complex內的傳統PCI裝置。§6.29限定其FLR與Transactions Pending的使用前提。一般PCIe Function仍讀自己的能力與Chapter 9流程；名稱相似，不代表暫存器位置與適用對象相同。
