基本責任

Switch 的 Downstream Port（下游連接埠）是面向下游裝置的連接埠。交換器再向上游轉送時，會使用另一條連線的傳遞機制。

1. 建立連線，再準備交易

一條 Lane（通道）提供兩個方向各自的傳輸路徑；多條通道可以組成一條 Link（連線）。×4 表示四條通道，GT/s 則是每秒十億次傳輸的速率單位。Physical Layer（實體層）先辨識兩端、取得接收同步，再將各通道組成連線。這個過程由 Link Training and Status State Machine（LTSSM，連線訓練與狀態機）管理。

接著，Data Link Layer（資料連結層）管理相鄰兩端的連線狀態與可靠傳遞；Transaction Layer（交易層）處理 TLP（Transaction Layer Packet，交易層封包）、路由及交易。DLLP（Data Link Layer Packet，資料連結層封包）在相鄰兩端交換；交易封包則可穿越交換器到達另一個元件。下表將實體層、資料連結層與軟體準備工作分開列出。

同一句「準備好了」，可能指三種不同事情
觀察對象此時解決的問題後續另需處理

2. 沿 LTSSM 訓練狀態建立連線

LTSSM（連線訓練狀態機）先找出可用通道，再建立同步與通道編號。下面保留初次建立連線的主要路徑；Configuration 在此負責組成連線。完整狀態機還包含逾時、重試、測試及省電分支。

3. 兩端支援 16 GT/s，為什麼現在只有 8 GT/s ×4？

查詢對象是同一條連線兩端的 Downstream Port（下游連接埠）與 Endpoint（階層末端裝置）。以下假設兩端 PCI Express Capability（PCIe 能力與控制結構）都已定位於 0x70、版本為 2。表中先只列相關欄位；Maximum Link Width 的值是解碼後的 Lane 數，其餘標成十六進位者是完整 Register 讀值。

再看 Downstream Port 的 Figure 7-39／Table 7-36：0x0003 & 0xF = 3，Target Link Speed（目標速率）對應 8 GT/s，設定下游連接埠正常運作速率的上限。實際訓練結果接著由狀態欄位確認。最後依 Figure 7-29／Table 7-26，0x2043 & 0xF = 3、(0x2043 >> 4) & 0x3F = 4，目前確實為 8 GT/s ×4。

本例另外假設 Downstream Port 的 Data Link Layer Link Active Reporting Capable=1，因此 Status bit 13=1 可用來確認 DL_Active；Endpoint 未實作該回報，因此 bit 13 固定為零；本例使用連接埠的回報確認狀態。Link 不在 up 狀態時，Current Link Speed 與 Negotiated Link Width 的值未定義。

因此，本例的 8 GT/s 符合設定的上限，×4 也符合 Endpoint 的能力。Downstream Port 宣告 ×8，並不保證實際連線布了八條 Lane。依這組讀值，實際結果與設定和能力相符。

4. 經過 Recovery，哪些狀態需要重新建立？

已在 DL_Active 的連線進入 Recovery 後，可以保留資料連結狀態，再回到 L0。若後續路徑使 Physical LinkUp 降為零，資料連結層才會轉到 DL_Inactive，清除舊狀態並在連線恢復後重新初始化。判讀時要把實體層與資料連結層的紀錄放在同一條時間線上。

5. 依封包種類檢查接收空間

接收端透過 FC（流量控制）資訊告知可用額度，發送端依交易種類檢查 credit（接收緩衝額度）。Non-Flit Mode 下，每個 VC 分開記錄 Posted、Non-Posted、Completion 的 Header 與 Data，合計六類：PH／PD 是 Posted 的標頭／資料額度，NPH／NPD 是 Non-Posted 的標頭／資料額度，CplH／CplD 是完成回覆的標頭／資料額度。Data credit 的單位是 4 DW（每個 Doubleword 為 4 bytes），也就是 16 bytes；Header（標頭）額度則依封包標頭另計。

6. 確認接收與必要時的重送

在本例模式中，資料連結層為封包加入 sequence number（序號）與 LCRC（Link Cyclic Redundancy Check，連線錯誤檢查碼）。接收端檢查後，以 ACK（正向確認）／NAK（要求重送的負向確認）等機制回覆發送端。發送端保留 replay（重送）所需的副本；收到適當的正向確認後才釋放。NAK（負向確認）或確認逾時可以引發 replay。先看 Figure 3-17 的序號與 LCRC（連線檢查碼），再看 Figure 3-22 的接收流程與 Figure 3-21 的確認處理。

假設 Endpoint 的 MWr（記憶體寫入）要穿越 Switch。第一條連線收到 ACK（正向確認），發送端便可按規則處理這一跳的副本。CPU 存取資料與裝置工作的完成，仍由後續的記憶體及裝置介面處理。Switch 再往上游傳送時，使用的是另一條 Link 的確認與重送機制。ACK 也不是 Chapter 5 的 Completion：Posted MWr 沒有一般 Completion，仍然有 Link 層的可靠傳遞。

接收端的 sequence 檢查也處理 replay 可能帶來的重複封包，避免把已接受的副本再次交給 Transaction Layer。這些動作由相鄰兩端的硬體執行；驅動程式仍在處理原先提交的工作。

7. PCIe 6.0 的 Flit 改變了什麼？

在 64 GT/s 運作時使用 Flit Mode（固定區塊傳遞模式），較低速率也可使用。當前模式需由本節稍後的模式欄位確認。Flit 是固定 256 bytes 的傳輸單位，TLP 可以跨越多個 Flit，一個 Flit 也不必只容納一個 TLP。

一個 Flit 的 256 bytes 分配
Byte 範圍大小用途
0–235236 bytesTLP 區，包含 TLP Header 等內容，不能全算成應用資料。
236–2416 bytesDLP（Data Link Layer Payload，資料連結層承載內容）。
242–2498 bytesCRC（Cyclic Redundancy Check，循環冗餘檢查碼），供錯誤檢查。
250–2556 bytesECC（Error Correction Code，錯誤修正碼），支援 Forward Error Correction（FEC，前向錯誤更正）。

Flit Mode 的可靠傳遞以 Flit 為 replay 單位，配合 CRC（錯誤檢查碼）、FEC（前向錯誤更正）與序號機制。可更正的錯誤由更正機制處理，其餘情況仍可能需要重送；格式與前面的個別封包模式不同。

要查目前模式，先確認 PCI Express Capabilities 的 Flit Mode Supported（Figure 7-23／Table 7-19 bit 15），再查 Downstream Port 的 Link Status 2。Flit Mode Status 在 bit 10，但只有 Downstream Component Presence 為 011b、100b 或 101b 時才有意義。若只擷取這兩個欄位得到 0x4400，則 Presence=100b、Flit=1：Link 已 up、尚未收到 DRS（Device Readiness Status，裝置就緒通知），模式為 Flit。若是 0x3400，Presence=011b，雖已協商 Flit，Data Link Layer 尚未 active。這兩個數字是欄位投影，不是完整 Register dump。
