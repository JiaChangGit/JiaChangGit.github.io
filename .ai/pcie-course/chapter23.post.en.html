D0 is a function power state, not the complete card power budget. Power Budgeting relates supply and consumption; DPA (Dynamic Power Allocation) manages power substates within D0; emergency reduction is a separate fail-safe mechanism.

Read consumption data before enabling a card

Use Table 6-10 to establish whether records cover a function, device, or card. Figure 7-136 then locates Data Select and Data Register. The index starts at zero, but its default is undefined, so explicitly select the intended record. Devices/cards must remain within the applicable configuration power limit until configured and enabled; the system should budget power before enabling an adapter.

Track a DPA transition within D0

DPA substates exist within D0. They are contiguous from 0 through Substate_Max, with non-increasing allocations; software may select a substate directly. They are distinct from D1–D3 and L1 PM substates. In an author example with 20/15/8 W substates, selecting substate 2 requires checking status. A high-to-low transition reports the higher allocation until complete; a low-to-high transition reports the higher allocation during the transition. VF DPA power is managed through its associated PF; VFs must not implement DPA Capability.

Keep emergency reduction and PF/VF power rules separate

Emergency Power Reduction is an optional fail-safe that overrides the described normal power controls. Table 6-16 ties allowed triggers to support and initialization fields; no universal configuration trigger should be invented. Section 5.10 separately defines PF/VF power management. When a VF implements PM capability, placing the PF in a lower power state than that VF has undefined device behavior; software should lower all VFs first.
