先看本章的角色與路徑

熱插拔把實體插入、供電、Link 建立與軟體配置接成一個受管理的過程。讀到插入狀態後，管理軟體還要依插槽能力完成後續準備。

前情提要：Chapter 3／4 的枚舉與資源配置會在新裝置加入時再次用到；Chapter 8／9 提供連線與重設後等待條件。

規格路線：Slot Implemented／Hot-Plug 能力 → Figures 7-30–7-32 的能力、控制、狀態 → §6.7.3 的操作與通知 → 枚舉及資源。

PCIe Hot-Plug 要把實體插槽的變化轉成一致的軟體狀態。能力、通知、供電、Link 就緒與資源配置各有不同的證據；其中任何一步成立，都不能代替其餘步驟。本篇先用插入案例說明查詢路線，再帶讀由按鈕發起的正常移除及取消分支。

依據與假設

依 PCIe Base 6.0 與 PCI Firmware 3.3，保留兩者的版本邊界。所有數值、時間與容量是作者案例，另設 Hot-Plug 插槽於 Switch Downstream Port 02:01.0，下游為 03:00.0。假設 OS 已取得 native Hot-Plug 控制權、沒有 SFI 介入，不使用提早就緒通知。

0x0162 表示 Version=2、Type=6、Slot Implemented=1。Slot Capabilities bits 0–4 全為 1，具備按鈕、電源控制器、MRL 扣具感測器與兩種指示燈；bit 6=1 支援 Hot-Plug，bit 18=0 支援 Command Completed。bits 31:19 為實體插槽 5，不是 Device Number；Power Limit Value=75、Scale=0，得到 75 W 上限，不是目前耗電量。

HPS bit 5=0，因此本例只示範有秩序流程。不能把這個 bit 當成所有非同步移除方案的唯一判定；Base 6.0 已不建議以舊 HPS 機制支援 async hot-plug，而建議 DPC。SFI 也可能抑制 HPS 讀值。

狀態、事件與通知分開解讀

Slot Status=0x0048 同時表示 Presence Detect State bit 6=1，以及 Presence Detect Changed bit 3=1。前者是目前偵測結果，後者是待處理事件。相同 Slot Event 尚未清除時，後續同類事件會被忽略，所以一個 bit 不能表示變化次數或完整順序。

本例主電源關閉時仍由 out-of-band 機制偵測插入。一般在 In-Band PD Disable=0 時，Presence 是 in-band 與適用 out-of-band 的 OR；in-band 需要供電。Presence=1 仍不證明 Link Active。

0x17F8 已開啟 Presence Changed、Command Completed、DLL State Changed 的通知及 Hot-Plug Interrupt Enable，但事件紀錄與實際收到中斷不同。後者還需符合 INTx 或 MSI／MSI-X 的啟用、向量與路由條件。

命令完成不等於可以立刻枚舉

確認扣具關閉、功率預算足夠且沒有前一筆未完成命令後，本例寫 Slot Control=0x12F8：Power On、Power Indicator Blink、Attention Indicator Off，保留原通知設定。任何 Slot Control 寫入都是 Hot-Plug 命令；本例支援 Command Completed，須等前一筆完成才發下一筆。一秒未完成時，規格允許重送或發下一筆，不能據此假定供電成功。

可存取設定空間之後，仍要有可用資源

假設目前路徑只剩 0x80080000–0x800FFFFF，共 0x80000 bytes（512 KiB），新 BAR 需要 0x100000 bytes（1 MiB）且依大小對齊。即使 Configuration Request 成功，這段空間仍放不下。BAR 寫到視窗外不會讓 Bridge 自動轉送。

事先預留 Bus Numbers 與位址範圍可降低配置困難；不足時能否搬移其他配置，取決於 Host Bridge 資源、沿途視窗及軟體協調。這是作者的系統推演，不是規格保證每張熱插入卡都有空間。詳細枚舉與 BAR 計算連回 Chapters 3–4。

按下按鈕後，什麼時候可以拔卡？

Attention Button 是提出熱插拔要求的按鈕。軟體接受移除要求後，先以 Power Indicator（電源指示燈）閃爍回應使用者，保留取消機會；接著協調裝置停止工作、關電並完成等待，最後才讓使用者取出卡片。

【模擬資料】以下情境為教學用途建立，不代表特定硬體或平台。續用管理插槽的 Switch Downstream Port 02:01.0 與下游 Endpoint 03:00.0。假設先前插入已完成，裝置正常工作、指示燈常亮，沒有電源故障；軟體具有管理權。MRL 扣具維持關閉，直到流程允許實體移除。本例有獨立的插卡偵測來源，因此主電源關閉後，只要卡片仍在，Presence Detect State 仍為 1。

先前插入快照中的 Attention Button Pressed Enable 為 0。本次先在 02:01.0 的 Slot Control 將這個 bit 與 Hot-Plug Interrupt Enable 設為 1，並完成該筆命令的處理；Port 的中斷機制也已正確啟用。下圖由上往下讀，右側是取消分支。螢幕較窄時，可左右滑動查看完整流程。

先處理按鈕事件，才接得住第二次按下

查 Figure 7-32／Table 7-29，Attention Button Pressed 位於 Slot Status bit 0，屬於 RW1C（寫入 1 清除）。假設此時 Slot Status 讀值為 0x0041，卡片存在、按鈕事件為 1，其餘欄位為 0。本例先保存事件，再以 16-bit 寫入 0x0001 到 0x8A，只清這個事件。§6.7.3.1 說明，同類事件在前一筆仍待處理時會被忽略；若一直保留第一次按鈕事件，第二次按下就無法成為新的事件紀錄。

接著讀 §6.7.1.5：軟體接受要求，讓 Power Indicator（電源指示燈）開始閃爍後，才開始五秒取消窗口。使用者在這段時間再次按下，就取消這次操作。本例的取消分支保留裝置供電，再依命令完成規則將指示燈恢復常亮。五秒從實際開始閃爍起算；中斷送達或軟體讀到 Status 的時間，都不是這個起點。

取消窗口結束後，先讓裝置停止工作

本例選擇在五秒內未取消後，才停止接受新工作，並協調驅動程式與裝置處理尚未完成的讀寫、DMA 傳輸及中斷。這一段是作者安排的系統流程：各類裝置如何停止佇列、取消工作或保存資料，要查裝置與軟體文件。若停止條件尚未滿足，就留在這一步，維持禁止拔卡的狀態。

例如，將 Bus Master Enable 清為 0，限制的是 Function 後續發起的相關 Request；先前送出的 Memory Read、已進入路徑的 Posted Write，以及應用程式要保存的資料，仍需各自的完成證據。這些停止與保存要求，無法只靠 Slot Status 判斷。

關電命令完成後，指示燈也不能立刻熄滅

沿 Figure 7-31／Table 7-28 找到 Power Controller Control：寫入 1 要求 Power Off；Power Indicator Control 的 10b 讓指示燈維持閃爍。這兩項可放在同一筆 Slot Control 寫入，但各動作的執行順序未由規格指定；本例開始關電前，指示燈就已經在閃爍。

本插槽支援 Command Completed，因此軟體依 §6.7.3.2 等候上一筆命令完成後，才發下一筆 Slot Control 命令。再讀 §6.7.1.8：關電後必須等待至少一秒，才可做任何依賴電源已移除的動作；等待結束前，不得關閉 Power Indicator，也不得重新要求上電。Command Completed 只表示控制器可接下一筆命令；這段等待仍要遵守。Control 讀回值也只是最後寫入的要求，並非電壓量測。

待關電等待及適用的移除條件都成立，軟體才以 Power Indicator Control=11b 關閉指示燈。回到 Table 6-9 Power Indicator States：閃爍表示操作進行中，尚不允許插拔；Off 才表示允許插入或移除。實際要移除哪些電源與訊號，仍須符合插槽的 form factor（機構與電氣形式）規格，部分輔助電源或訊號可能繼續存在。

用兩個問題檢查判讀

Presence Changed=1、Presence=0，是否代表從未插入？

不能。Changed 是待處理事件，Presence 是目前結果，兩者不能還原完整歷史。依據：§6.7.3.1、Table 7-29。

Command Completed 與 Power Fault 同時存在，是否互相矛盾？

不矛盾。命令介面可以接收下一筆，不保證供電成功；仍須處理電源故障。依據：Tables 7-28／7-29。
