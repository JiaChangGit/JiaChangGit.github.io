先看本章的角色與路徑

熱插拔把實體插入、供電、Link 建立與軟體配置接成一個受管理的過程。讀到插入狀態後，管理軟體還要依插槽能力完成後續準備。

前情提要：Chapter 3／4 的枚舉與資源配置會在新裝置加入時再次用到；Chapter 8／9 提供連線與重設後等待條件。

規格路線：Slot Implemented／Hot-Plug 能力 → Figures 7-30–7-32 的能力、控制、狀態 → §6.7.3 的操作與通知 → 枚舉及資源。

PCIe Hot-Plug 要把實體插槽的變化轉成一致的軟體狀態。能力、通知、供電、Link 就緒與資源配置各有不同的證據；其中任何一步成立，都不能代替其餘步驟。本篇用一個插入案例說明查詢路線，最後比較有秩序移除與非同步移除。

依據與假設

依 PCIe Base 6.0 與 PCI Firmware 3.3，保留兩者的版本邊界。所有數值、時間與容量是作者案例，另設 Hot-Plug 插槽於 Switch Downstream Port 02:01.0，下游為 03:00.0。假設 OS 已取得 native Hot-Plug 控制權、沒有 SFI 介入，不使用提早就緒通知。

能力查詢從管理插槽的 Port 開始

在 02:01.0 找到 PCI Express Capability base=0x70 後，先讀 Figure 7-23 的 Port Type 與 Slot Implemented，再看 Figure 7-30 的 Slot Capabilities。不能到 Endpoint 尋找所屬插槽的控制器。實體元件的配置仍取決於 form factor，Base 不要求每種插槽都有相同的按鈕、扣具與指示燈。

0x0162 表示 Version=2、Type=6、Slot Implemented=1。Slot Capabilities bits 0–4 全為 1，具備按鈕、電源控制器、MRL 扣具感測器與兩種指示燈；bit 6=1 支援 Hot-Plug，bit 18=0 支援 Command Completed。bits 31:19 為實體插槽 5，不是 Device Number；Power Limit Value=75、Scale=0，得到 75 W 上限，不是目前耗電量。

HPS bit 5=0，因此本例只示範有秩序流程。不能把這個 bit 當成所有非同步移除方案的唯一判定；Base 6.0 已不建議以舊 HPS 機制支援 async hot-plug，而建議 DPC。SFI 也可能抑制 HPS 讀值。

狀態、事件與通知分開解讀

Slot Status=0x0048 同時表示 Presence Detect State bit 6=1，以及 Presence Detect Changed bit 3=1。前者是目前偵測結果，後者是待處理事件。相同 Slot Event 尚未清除時，後續同類事件會被忽略，所以一個 bit 不能表示變化次數或完整順序。

本例主電源關閉時仍由 out-of-band 機制偵測插入。一般在 In-Band PD Disable=0 時，Presence 是 in-band 與適用 out-of-band 的 OR；in-band 需要供電。Presence=1 仍不證明 Link Active。

0x17F8 已開啟 Presence Changed、Command Completed、DLL State Changed 的通知及 Hot-Plug Interrupt Enable，但事件紀錄與實際收到中斷不同。後者還需符合 INTx 或 MSI／MSI-X 的啟用、向量與路由條件。

命令完成不等於可以立刻枚舉

確認扣具關閉、功率預算足夠且沒有前一筆未完成命令後，本例寫 Slot Control=0x12F8：Power On、Power Indicator Blink、Attention Indicator Off，保留原通知設定。任何 Slot Control 寫入都是 Hot-Plug 命令；本例支援 Command Completed，須等前一筆完成才發下一筆。一秒未完成時，規格允許重送或發下一筆，不能據此假定供電成功。

Power Controller Control 的讀回值也不是電源量測；故障可能阻止供電。DLL State Changed 後，必須讀 Link Active，不能只憑 Changed bit 發設定存取。Hot-Add 的 DLL 變化一秒期限從本例的 Power On 寫入起算；判定已 Active 卻無 Successful Configuration Completion 的裝置損壞，則須從 Active 起允許至少一秒。兩個期限不同。

可存取設定空間之後，仍要有可用資源

假設目前路徑只剩 0x80080000–0x800FFFFF，共 0x80000 bytes（512 KiB），新 BAR 需要 0x100000 bytes（1 MiB）且依大小對齊。即使 Configuration Request 成功，這段空間仍放不下。BAR 寫到視窗外不會讓 Bridge 自動轉送。

事先預留 Bus Numbers 與位址範圍可降低配置困難；不足時能否搬移其他配置，取決於 Host Bridge 資源、沿途視窗及軟體協調。這是作者的系統推演，不是規格保證每張熱插入卡都有空間。詳細枚舉與 BAR 計算連回 Chapters 3–4。

移除模式決定軟體是否來得及協調

Orderly removal 有機會先停止新工作，依裝置協定處理在途工作，再完成供電、指示燈與移除流程。清 BME 不等於舊交易或應用工作都完成。Async removal 則可能在軟體協調前已失去裝置，必須處理失效狀態與未完成工作，不能再向消失的裝置要求完成證據。

這是作者整理的系統流程；各類裝置的停止、取消與保存方法不由 PCIe 統一定義。DPC 限制下游錯誤擴散，並不判定應用工作成功；其狀態與恢復條件見 Chapter 12。管理權則見 Chapter 13。依據：Base §6.7、§6.7.6（pp.727、741–742）、§6.2.11（pp.694–697）；Firmware §4.5。

用兩個問題檢查判讀

Presence Changed=1、Presence=0，是否代表從未插入？

不能。Changed 是待處理事件，Presence 是目前結果，兩者不能還原完整歷史。依據：§6.7.3.1、Table 7-29。

Command Completed 與 Power Fault 同時存在，是否互相矛盾？

不矛盾。命令介面可以接收下一筆，不保證供電成功；仍須處理電源故障。依據：Tables 7-28／7-29。
