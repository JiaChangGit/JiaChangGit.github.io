A TLP (Transaction Layer Packet) carries a request, completion, or message. First establish whether the link uses Non-Flit Mode or Flit Mode: their TLP (transaction packet) header layouts differ. We follow that choice into address, identity, length, and byte selection.

Why start with the format?

In Non-Flit Mode, locate Fmt/Type in Figure 2-4, then consult Tables 2-2 and 2-3. Fmt distinguishes header size and data presence; Type also determines routing. A Memory Read requests data without carrying that read data in its request.

For Flit Mode, restart with Figure 2-6 and Table 2-5. The eight-bit Type is a different encoding: NOP is 00h, while a 32-bit-address Memory Read is 03h. Reusing the Non-Flit decoding table misidentifies the packet.

How do extensions affect the data position?

OHC (Orthogonal Header Content, optional header extensions) is indicated in Figure 2-6. Read the presence/order rules on p.131, then Table 2-6 for the applicable A format. A Memory Request with explicit Byte Enables uses OHC-A1 in Figure 2-7. OHC follows the Header Base in A-B-C-E order.

TS (Trailer Size) describes the trailer separately from Length. Non-Flit Mode instead has its own prefix and TD (TLP Digest presence) rules. Determine the entire packet size before locating the next packet.

Read Length and Byte Enables together

Author example: a normal Non-Flit Memory Write uses a 4-byte-aligned address, Length=2 DW (Double Words, four bytes each), First DW BE=1100b, and Last DW BE=0011b. Figure 2-26 locates BE (Byte Enable) fields. The first field selects offsets +2 and +3; the last selects +4 and +5. The payload still spans eight bytes, with four selected for writing. For a one-DW request, Last DW BE must be zero.

Continue into receiver handling

Section 2.2.9 identifies requests requiring a Completion (transaction response). A Memory Read receives data in its completion; a normal posted Memory Write has no corresponding successful completion. Chapter 15 follows receiver checks and the resulting response.
