A TLP (Transaction Layer Packet) carries a request, completion, or message. First establish whether the link uses Non-Flit Mode or Flit Mode: their TLP (transaction packet) header layouts differ. We follow that choice into address, identity, length, and byte selection.

Why start with the format?

In Non-Flit Mode, locate Fmt/Type in Figure 2-4, then consult Tables 2-2 and 2-3. Fmt distinguishes header size and data presence; Type also determines routing. A Memory Read requests data without carrying that read data in its request. For example, a separate Non-Flit 32-bit-address Memory Read with Length=2 and no Prefix or Digest has only a 12-byte Request Header; its data returns in Completion packets. The Type/format determines whether Length describes data present in this packet.

For Flit Mode, restart with Figure 2-6 and Table 2-5. The eight-bit Type is a different encoding: NOP is 00h, while a 32-bit-address Memory Read is 03h. Reusing the Non-Flit decoding table misidentifies the packet.

How do extensions affect the data position?

OHC (Orthogonal Header Content, optional header extensions) is indicated in Figure 2-6. Read the presence/order rules on p.131, then Table 2-6 for the applicable A format. A Memory Request with explicit Byte Enables uses OHC-A1 in Figure 2-7. OHC follows the Header Base in A-B-C-E order.

TS (Trailer Size) describes the trailer separately from Length. Non-Flit Mode instead has its own prefix and TD (TLP Digest presence) rules. Determine the entire packet size before locating the next packet.

Follow the same write intent through both formats

Simulated data: this teaching scenario does not represent a particular device or platform. Two independent traces each contain a Memory Write from configured Endpoint 03:00.0 to 0x80001000. Assume the address and path are usable, device-initiated access is permitted, and no Prefix, IDE or TPH is present. Reserved and otherwise unused fields are zero. External evidence identifies each Link mode, and the complete logical TLP has already been recovered.

Both payloads are A0 A1 A2 A3 B0 B1 B2 B3, with Length=2 DW (Double Words, four bytes each), but only the middle four bytes are selected. First DW BE=1100b and Last DW BE=0011b. The Flit example starts after TLP reassembly; it is not a complete FLIT. Hex below follows the figures' byte 0, byte 1 order, with four bytes per line, rather than CPU DWORD read values.

Decode the 20-byte Non-Flit TLP

40 00 00 02
03 00 00 3C
80 00 10 00
A0 A1 A2 A3
B0 B1 B2 B3

Figure 2-4 splits the first byte, 0x40, into Fmt=010b and Type=00000b. Tables 2-2/2-3 identify their combination as a Memory Write with a three-DWORD Header and data. Figure 2-5 then gives Length=2 and TD=0: 12 bytes of Header, eight bytes of Data Payload and no Digest, totaling 20 bytes.

Next, Figure 2-31 locates Requester ID 03 00 in bytes 4–5, or 0x0300, corresponding to 03:00.0 here. Bytes 8–11 give address 0x80001000. Figure 2-26 and Table 2-10 locate Header byte 7=0x3C: its high nibble is Last DW BE=0011b, and its low nibble is First DW BE=1100b. The Header ends at byte 11; data starts at byte 12.

Decode the 24-byte Flit-format TLP

40 01 00 02
03 00 00 00
80 00 10 00
00 00 00 3C
A0 A1 A2 A3
B0 B1 B2 B3

Start again with Figure 2-6: the entire first byte, 0x40, is Type. Entry #64 in Table 2-5 identifies a 32-bit-address Memory Write, a three-DWORD Header Base, and Data Payload determined by Length. Its first byte happens to match the preceding example, so that byte alone does not identify the Link mode.

Byte 1 has OHC=00001b, indicating OHC-A. Byte 2 has TS=000b, indicating no Trailer; Length remains 2. Figure 2-40 locates the 12-byte Header Base. Table 2-6 selects OHC-A1 for this Memory Request, and Figure 2-7 shows its one-DWORD layout. The BE fields are in byte 3 relative to that OHC block: overall TLP byte 12+3=byte 15, containing 0x3C.

Data therefore starts at byte 16, and the TLP totals 12+4+8=24 bytes. PV=0 in this OHC-A1 means no valid Process Address Space ID (PASID); the other unused fields are zero. OHC-A1 supplies partial-write byte selection without increasing the data payload length.

Section 2.2.5.2 explains why the extension is needed for this intent: without OHC-A1, a two-DWORD Memory Request implies First and Last DW BE=1111b. All eight bytes would be enabled, changing the intended middle-four-byte write. OHC presence affects the access performed by the receiver.

A Non-Flit decoder applied to the second trace could misread byte 7=0x00 as both BE fields and mistake OHC bytes 00 00 00 3C for the payload start, shifting data by four bytes. Correct the analyzer mode first; these artifacts do not establish that an erroneous packet actually appeared on the Link.

Why do eight payload bytes update only four bytes?

Continue the same simulated writes. Section 2.2.5.1 and Table 2-10 map each BE bit to a data byte: First DW BE bit 0 selects the lowest-address byte in the first DW; Last DW BE bit 0 selects the lowest-address byte in the last DW. First=1100b selects offsets +2 and +3; Last=0011b selects +4 and +5.

The selected range is 0x80001002–0x80001005, totaling four bytes, while each TLP still carries eight payload bytes. Length remains 2 DW; disabled bytes are not removed from the packet. This example stays within a 4-KB boundary and selects contiguous bytes. Other lengths, alignments or non-contiguous patterns require the full §2.2.5.1 rules.

In the Non-Flit example, changing to a one-DWORD Request requires Last DW BE= 0000b; the example's 0011b cannot simply be retained. Read the conditions following Figure 2-26 together with the field locations.
