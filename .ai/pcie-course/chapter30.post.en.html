Vendor/Device IDs identify a device type, serial data and VPD (Vital Product Data) describe product information, and Root Complex declarations describe internal relationships. Choose the query’s purpose before choosing its capability.

Distinguish type from an individual unit

Use Vendor/Device IDs from Chapter 3 for type identification, then supported Device Serial Number or product data for unit information. Table 7-222 defines the 64-bit serial field and byte mapping. VPD can provide part/serial information. Keep the source of each identifier rather than treating a type ID as a unique card identity.

Read a product name through the VPD interface

VPD (Vital Product Data) stores product and service information. Walk the ordinary Capability List, then use Figure 7-328 to locate Address at capability offset 02h and Data at 04h. VPD Address identifies a byte in the storage component; it is not a Configuration Space offset.

Table 7-289 requires a DWORD-aligned byte address. Table 7-290 places the byte at that address in Data's least-significant byte and requires Byte Enable 1111b. Read the first four bytes only after F=1, then start the second transfer. Writing Address or Data before a read completes, or requesting an address outside the storage range, has undefined behavior.

In Table 6-20, 82h is a Large Resource tag with item name 02h, the Identifier String. The next two bytes 05 00 give little-endian length 5. The five ASCII bytes 43 41 52 44 31 form CARD1. The remaining VPD, its end tag and VPD-R checksum require further reads.

For a write, first place four bytes in Data, then write Address and F=1 together and wait for hardware to clear F to 0. Writing Address or Data while the write is incomplete makes the storage result unpredictable. The device and platform define the writable area and maintenance procedure; stored VPD does not directly control device operations.

Interpret RCEC association for integrated endpoints

A Root Complex may expose an opaque model or visible logical components and RCRBs (Root Complex Register Blocks). Figure 6-11 illustrates one visible component; a Link Declaration describes software-visible relationships and does not by itself reveal all physical wiring.

An RCEC (Root Complex Event Collector) uses Endpoint Association to describe associated RCiEPs (Root Complex Integrated Endpoints). Figure 7-269 locates the bitmap; Capability Version 2 includes the additional Associated Bus Numbers Register.

Simulated data: an RCEC at Bus 10h, Device 2 reports Association Bitmap=00000024h. Bit 2 is required for the RCEC's own Device Number. If Device 5 on that same Bus is an RCiEP, bit 5 associates it with this RCEC. The bitmap indexes Device Numbers, not Function Numbers.

Assume Version 2 with RCEC Next Bus=20h and Last Bus=22h. The range can contain additional associated RCiEPs; Root Ports within it are not thereby associated, and the bus range does not indicate association with VFs. If all associated devices are on the RCEC's own Bus, Next Bus=FFh and Last Bus=00h. Association describes event collection; each Function's identity and resources still need their own records.
