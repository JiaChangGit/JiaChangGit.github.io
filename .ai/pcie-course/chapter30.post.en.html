Vendor/Device IDs identify a device type, serial data and VPD (Vital Product Data) describe product information, and Root Complex declarations describe internal relationships. Choose the query’s purpose before choosing its capability.

Distinguish type from an individual unit

Use Vendor/Device IDs from Chapter 3 for type identification, then supported Device Serial Number or product data for unit information. Table 7-222 defines the 64-bit serial field and byte mapping. VPD can provide part/serial information. Keep the source of each identifier rather than treating a type ID as a unique card identity.

Read product data through its handshake

Figure 7-328 locates Address/Data; Figure 7-329 locates F. For a read, issue one address write with F=0, wait for hardware to set F=1, then read four data bytes. Writing Address/Data before completion has undefined behavior. In the author scenario of two valid addresses, finish the first before issuing the second. Parse returned small/large resource tags and lengths using Tables 6-19 through 6-21. VPD writes use a different handshake; stored VPD does not directly control device operation.

Qualify vendor-specific data before decoding

VSEC (Vendor-Specific Extended Capability) combines standard headers with vendor-defined registers. Qualify Vendor ID before VSEC ID/revision/length. VSEC (the vendor extension structure) has no universal cross-vendor register semantics. DVSEC (Designated Vendor-Specific Extended Capability) has its own designated identity and layout in Figure 7-248; its private definitions require the matching vendor specification.

Use topology declarations for their own purpose

Root Complex models may expose internal links, an RCRB (Root Complex Register Block), and topology declarations, or remain opaque. An RCEC (Root Complex Event Collector) Endpoint Association declares the integrated endpoints it supports. These connect component and event responsibility rather than replacing function identity or resource configuration.
