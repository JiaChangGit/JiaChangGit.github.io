PCIe 電源管理同時涉及 Function、Link 與平台。D-state、ASPM、L1 Substates 與喚醒各有不同的控制與證據，不能只憑一個 Enable 推論目前狀態。本章用 PMCSR 與 L1.2 算例串起查詢、設定及恢復條件。

版本與假設

PCIe 採 Base 6.0，平台補充採 ACPI 6.6。數字均為作者假設。PMCSR 使用普通 Endpoint 03:00.0；L1.2 另採已具備雙端能力、LTR、CLKREQ# 與合適時序設計的 Link，不含 SR-IOV，也不替前例追加未宣告功能。

Function 的 D-state 與 Link 的 L-state 分開管理

D0 是 Function 正常工作狀態，但 ASPM 可在 D0 閒置期間降低 Link 耗電。D1、D2 是可選狀態；D3hot 保有主電源，D3cold 沒有主電源，仍可能由輔助電源支持喚醒。Reset 後的 D0uninitialized 也不等於工作介面已準備完成。

L0 可傳輸；L0s 可分方向省電，但 Flit Mode、有 Retimer、或指定的獨立 SSC 時脈條件不支援 L0s。L0p 只用於 Flit Mode，讓部分 Lane 閒置，雙向仍各至少有一條 active Lane。L1 可再細分 L1.0、L1.1、L1.2；L2／L3 則是主電源移除後，以是否有 Vaux 區分的狀態。

讀 PM 能力，再以正確的寫值回 D0

傳統 Capability ID=0x01 指向 PM 結構。作者假設在 0x40 讀完整 DWORD=0xC8035001：ID=0x01、Next=0x50、Version=3，D1／D2 不支援；PME_Support=(value >> 27) & 0x1F = 0x19，支援從 D0、D3hot、D3cold 發出 PME。假設無可選 Data Register、Aux_Current=0 採自供電且必要供電可用。這是能力，不是完整喚醒路徑已就緒的證明。

ASPM Enable 需要能力與延遲政策支持

ASPM 在 D0 期間由硬體管理閒置 Link；PCI-PM 則由軟體改變 D-state。普通非 ARI 多 Function 裝置，必須所有 Functions 都離開 D0，才可代表 PCI-PM 發起進 L1。

先查兩端 Link Capabilities 的 ASPM Support，再看 Link Control 的 ASPM Control；Enable 不代表當下已在 L1。Link Capabilities 的 L1 Exit Latency 與 Endpoint Device Capabilities 的 L1 Acceptable Latency 要配合整條路徑判斷。多段退出可以重疊，不能直接把所有 Port 延遲相加：Figure 5-8 的例子最後在 T+34 μs 完成。

各自走訪 Extended 清單後，假設剛好在 0x200 找到 ID=0x001E、Version=1、Next=0；版本 1 沒有 +0x10 Status。兩端低五個 capability bits 都是 0x1F，支援四種 Substates 與總支援標記。宣告 T_POWER_ON 分別為 10／100 μs、common-mode 恢復為 10／20 μs；已設定 Control 2 的 Value=10、Scale=1，得到 100 μs。Control 1 只開 bit 2 的 ASPM L1.2。Common_Mode_Restore_Time 在 Downstream Port 設 20 μs，在 Upstream Port 是 RsvdP。

平台已確認此快照適合連接設計，不把兩端宣告值取最大值當成通用演算法。啟用前必須兩端都支援；ASPM Substate 設定期間先停用 ASPM L1，PCI-PM Substate 則在 D0 設定。先完成適用的時間與相同 LTR threshold，再依 Downstream Port、Upstream Port 順序開對應 Enable；停用順序相反。修改時間欄位須先清相應 L1.2 Enable，最後依政策恢復 ASPM L1。

相同 Enable，仍可能有不同的進入結果

Control 1 的 threshold Value=128、Scale=2，為 128 × 1024 ns=131072 ns（131.072 μs）。假設已在 ASPM L1.0、CLKREQ# 已 deassert、其他條件成立，最新有效 snoop／no-snoop LTR 需求若為 204800／102400 ns，後者不足，不能進 L1.2；改為 204800／153600 ns 後，兩者皆達 threshold，在上述條件下應進入。

某一類「無需求」可走另一判斷分支，不等於 Requirement=1、Value=0；後者要求盡可能低的延遲。這些是最近的有效回報，不是 Max Latency Register 上限。LTR 也不是 Root Complex 的硬性延遲承諾。本例未開 L1.1，不能假設不足時必然退到 L1.1。啟用 Endpoint LTR 前，Root Complex 與沿途 Switch 都須支援，並由靠近 Root Port 者先啟用。

喚醒先恢復通路，再辨識事件來源

L2 不能傳一般 TLP。裝置依 form factor 用 WAKE# 或 Beacon 請平台恢復電源、時脈與 Link，再送含 Requester ID 的 PM_PME。因此仍需 PME_En、輔助供電與平台路徑配合。（§5.3.3.1–§5.3.3.2，pp.615–616。）

檢查條件是否足夠

No_Soft_Reset=1 能保證 D3cold 後保留全部狀態嗎？

不能；它只適用指定 D3hot→D0 軟體轉換。

只有 Endpoint 支援 L1.2，可以只開一端嗎？

不可以。兩端對應能力、設定順序、LTR 與時序條件都要成立。
