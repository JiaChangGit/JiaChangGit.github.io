IDE (Integrity and Data Encryption) protects traffic between two partner ports with confidentiality, integrity, and replay protection. Draw the terminal boundaries first, then trace stream configuration and state. Internal data, key protection, and isolation remain separate responsibilities.

Draw the stream endpoints

Figure 6-48 distinguishes Link IDE on a link from Selective IDE for a selected stream, including applicable paths through a switch. They can coexist between directly connected ports. In the author scenario of an endpoint behind a switch, hop-by-hop Link IDE still needs protection inside the switch; a selective stream instead requires checking its terminal ports and associations. One link enable bit does not describe the whole protection boundary.

Separate key management from stream controls

Locate IDE Capability with section 7.9.26/Figure 7-370, then read the relevant stream capabilities, controls, and associations. IDE_KM (IDE Key Management) in 6.33.3 builds on SPDM/Secured-SPDM and supports multiple transports. IDE_KM (the partner-key coordination protocol) is separate from configuration stream controls. Function 0 manages an Upstream Port, and the bridge function provides a Downstream Port’s capability; Root Port interfaces need their own check.

Keep Ready distinct from secure operation

Ready in Figure 6-49 is a conceptual substate of Insecure, tracked by firmware/software when setup is complete. Secure operation still needs establishment/triggering. Disable or a detected compromise returns the stream to Insecure. A TEE (Trusted Execution Environment) using required streams also coordinates Locked/Not Locked in Figure 6-50 and prevents insecure fallback for traffic requiring protection. Trust policy and internal isolation are not fully defined by IDE.
