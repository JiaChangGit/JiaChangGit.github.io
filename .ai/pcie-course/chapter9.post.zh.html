只想重建 03:00.0 的工作環境時，先查它是否支援 FLR（Function Level Reset，以單一功能為範圍的重設）。軟體先停止新工作、處理舊交易，再觸發重設；等到設定就緒且舊交易的等待條件已滿足，才恢復設定並重新開放工作。

版本與案例

採 Base 6.0。03:00.0 與 03:00.1 是普通多 Function Endpoint，共用通往 02:01.0 的 Link，不含 SR-IOV（Single Root I/O Virtualization，單一根系統的 I/O 虛擬化）。讀值與時間點是作者假設；PCI Express Capability 在 0x70。

沿正常流程走一次

Chapter 6–8 已建立記憶體存取、中斷與連線。本章保留這條連線，重新建立目標 Function（可獨立設定的功能單位）的工作環境。閱讀順序隨軟體的需求安排：Figure 7-24 查能力，Figure 7-26 查未完成交易，Figure 7-25 找觸發控制，再接到 §6.6.2 的等待與恢復。

  1. 讀 Device Capabilities（裝置能力暫存器）bit 28，確認支援 FLR（單一功能重設）。
  2. 協調其他存取者，停止新工作並處理舊請求。p.727 的實作說明以清除 Command、查看 Transactions Pending（未完成交易指示）示範一種安排；此位只追蹤需要完成回覆的 Non-Posted Requests。
  3. 對 Device Control（裝置控制暫存器）的 Initiate FLR 寫 1。裝置先回覆這筆設定寫入，再開始重設。
  4. 本例先等 100 ms，再進行設定存取。若後續初始化仍需時間，RRS（Request Retry Status，要求稍後重試）會讓軟體繼續等待；恢復前也須滿足舊交易的等待條件。
  5. 按欄位屬性恢復設定，重建裝置工作與通知路徑，再開放新工作。

停止新 Request，不代表舊 Completion 已消失

BME（裝置發送許可）=0 不會收回先前送出的 Request。Transactions Pending 只反映此 Function 發出的 Non-Posted Requests；它們可能已完成或被 timeout 終止，這個 bit 不涵蓋所有 Posted Writes、CPU 存取或外部工作，且 FLR 完成時本身就必須清零。

作者情境中，Tag（交易識別標記）=0x13 的舊 MRd（Memory Read，記憶體讀取） 尚未回覆便發生 FLR。若立即重新使用該 Tag，遲到的 Completion 可能被誤配給新交易。軟體應先協調其他存取者、停止裝置新工作及 DMA（Direct Memory Access，直接記憶體存取）／中斷，再處理未完成交易。p.727 的 Implementation Note 提供清 Command、輪詢 Pending 或等待足夠時間後才發 FLR 的範例演算法；它不能取代裝置特有的停工程序。

FLR 完成、設定就緒與舊交易等待須分開確認

觸發 FLR 的 Configuration Write 必須先取得 Completion，再開始 FLR。Function 必須在 100 ms 內完成 FLR，但特有的後續初始化可能更久；超過此時限仍需初始化時，必須以 RRS（要求稍後重試）回覆 Configuration Request。回過非 RRS Completion 後，下次 Reset 前不得再回 RRS。

若觸發時 Transactions Pending=1，初始化前仍須容許舊 Completion 到達，或合理確信不會再到達；規格建議依 FLR 前的 Completion Timeout 等待。若當時 timeout 停用，時間由系統決定但不得少於 100 ms。FRS（Function Readiness Status，功能就緒狀態通知）的 Configuration-Ready 可提早允許 Configuration 存取，仍不保證先前 Requests 全部完成。FLR 進行中 Request 可被靜默丟棄，不能任意用 MMIO（Memory-Mapped I/O，記憶體映射 I/O）輪詢當作完成通知。

Conventional Reset 的起點又不同。在無 DRS（Device Readiness Status，裝置就緒狀態通知）／其他提早就緒例外的分支，支援高於 5 GT/s 的 Downstream Port 要從 Link training 完成後等至少 100 ms。作者例：Reset 於 t=0 ms 結束，training 於 t=40 ms 完成，首次 Configuration Request 最早為 t=140 ms。只支援到 5 GT/s 的對應分支從 Reset 結束計時。未使用 Readiness Notifications 時，Conventional Reset 結束後至少容許 1 s，才可因尚無 Successful Completion 判定故障；這不是首次可存取時間。

按欄位恢復，不整份寫回 dump

FLR 清除 BME、MSI（Message Signaled Interrupts，訊息式中斷）Enable 等發送許可，但保留明列的 Max_Payload_Size（最大承載資料大小）、ASPM Control（連線自動省電控制）、RCB（Read Completion Boundary，讀取回覆邊界）、HwInit（硬體初始化）與 sticky（具狀態保留屬性）欄位；Link 狀態機與 VC0（預設虛擬通道）不被重設。完整例外見 §6.6.2，Flit-capable 實作另有要求。Sticky 也不代表所有斷電／Reset 都永久保留。

恢復時需分清 RO（唯讀）、RW1C（寫 1 清除）、觸發控制與可寫設定，重新建立必要的資源、裝置工作介面、中斷與 DMA 條件後才開放工作。FLR 不會替軟體清除主機 buffer，PCIe Base 也不定義每張卡的 queue 重建方式。

回到這次重設的範圍

FLR 沒有讓 Link 重訓，是否代表失敗？

不是。FLR 不得影響 Link；應查 Function 的重設與恢復條件。

FLR 後 Pending=0，就能回收所有 DMA buffer 嗎？

不能。還需要舊交易等待、裝置停工、其他軟體存取協調及平台 DMA 生命週期條件。
