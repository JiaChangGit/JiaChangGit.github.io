PMUX (Protocol Multiplexing) carries PCIe and multiplexed-protocol packets on a shared link. Alternate Protocol discovery/negotiation has its own capability. Identify the mechanism and packet type before applying resource, reliability, or control rules.

Read the queue view before the layer view

Figure G-2 locates queues, arbitration, and demultiplexing; Figure G-3 places PMUX in its protocol-specific layer and simplified Data Link Layer. PMUX retains integrity checking without PCIe TLP sequence/ack reliability. In the author scenario, a missing multiplexed-protocol response must be diagnosed under that protocol; waiting for a TLP Ack does not prove PMUX delivery. PMUX also does not define general addressing/routing.

Check lifecycle interactions

Tables G-1/G-2 describe interactions. DL_Down, Hot Reset, and PERST# disable channels; an FLR to Upstream Port Function 0 also disables all PMUX channels on the link. Rate/width changes require protocol support checks. Section G.4 starts channels disabled and requires explicit enablement at both ends. Recovery must restore valid conditions, not merely rewrite Enable.

Read indexed alternate-protocol data

Locate the Alternate Protocol capability in Figure 7-336, then Count and selective-enable support in Figure 7-338/Table 7-296. Select an index and read Data 1/Data 2. Disabled entries may retain their index and return Vendor ID FFFFh. Alternate Protocol Count includes mandatory PCIe support and is at least one; presence does not establish active use or define the other protocol’s semantics.
