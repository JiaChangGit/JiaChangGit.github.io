## 為什麼這樣安排

課程從「裝置如何被系統使用」開始，先讓讀者知道每個步驟要解決的問題。接著才教系統如何識別 Function、如何讀取設定資料，以及如何配置能使用的位址。讀者能辨識交易的來源與目標後，再討論要求、回覆、資料順序與中斷；Link、Reset、電源及錯誤則用來解釋這些操作成立的條件。

Chapter 1 保留拓樸與識別方式，但不重新介紹 Chapter 0 的每個角色。它要解決新的問題：一張卡不等於一個 Function，BDF 也不是永久身分。這些觀念是走訪設定空間與枚舉前的必要基礎。Chapter 2 再正式建立通用的 Capability 查詢方法，將 Chapter 0 的單一示範延伸到不同 Header、清單及 Function 類型。

後半部依工作領域分支。讀者不必先讀完安全與實體訊號，才能理解韌體接管；也不必先讀 Option ROM，才能學 SR-IOV。表中的先備章節用來表達知識依賴，而不是強迫逐頁閱讀的順序。各章的 `prerequisites` 列直接需要的主要章節，較早的依賴由這些章節往前追溯。

## 每個情境如何寫成可學會的解答

先提出讀者真的需要解決的問題，再交代查詢對象與已知條件。例如，不直接問「Link Status 有哪些欄位」，而是問「這個 Port 支援哪些速率？目前連線又使用哪一個？」這樣才知道為什麼要查兩種資料。

能力查詢題通常依下列步驟編寫，但不強迫所有主題套用同一個段落模板：

1. **把問題說清楚。** 指定查詢的是哪個 Function、Port、Link 或 Slot，以及目前是否具備必要的可存取條件。
2. **找到進入規格的入口。** 說明設定空間、Header、Capability、Table 或平台介面如何把讀者帶到目標結構。
3. **交代閱讀次序。** 每張 Figure、每張 Table 與條文都有明確用途：定位、辨識欄位、確認編碼或檢查限制。依推理順序閱讀，不依圖號排序。
4. **提供教學資料。** 先給完整、可自洽的拓樸、版本、位址及讀值，再讓讀者自行判斷。缺少的資料就明說，不能在解答中突然補入關鍵條件。
5. **逐步推導。** 把相對位移和實際位址分開，列清楚讀取寬度、Mask、Shift、單位及編碼。數值以運算驗證，並檢查讀值是否落在適用範圍。
6. **收束到證據範圍。** 明確說明已能確認、尚不能確認，以及若要回答下一個問題還缺什麼資料。
7. **換一個條件檢查理解。** 只改一兩個會影響結論的前提，讓讀者判斷原推論是否仍成立；不以同義改寫湊題數。

涉及流程時，問題應要求讀者說明下一步的依據；涉及錯誤時，先辨識證據再推論原因。此階段專注規格、欄位與流程，不加入 `lspci`、實機操作或工具安裝教學。

## 規格版本與來源規則

本次的基準來源是使用者提供的 PCI Express Base Specification Revision 6.0，以及 PCI Firmware Specification Revision 3.3。正式版本、封面日期、檔案雜湊與定位資料以來源登記為準；檔名本身不構成版本證據。兩份 PDF 僅供閱讀與核對，不加入公開儲存庫或教材輸出。

`curriculum.json` 的 `PCIE-BASE-6.0` 與 `PCI-FW-3.3` 是上述文件的課程來源標識。後續章節列出的 `TO-SELECT` 或 `TO-VERIFY` 是待辦項目，不是已確認的規格版本，也不是該章已具備來源證據。撰寫相應章節前，必須先將這些項目替換成登記完成的來源。

需要擴充來源時，以 PCI-SIG、UEFI Forum、DMTF，以及相關處理器或平台供應商的正式規格、勘誤與官方文件為優先。常見的候選來源包括 UEFI、ACPI、CEM、IOMMU 及記憶體模型文件；採用版本必須明列，不用「最新版本」代替。

版本與證據的處理方式：

- 同一個欄位的 Figure、Table、Section 必須出自同一份已登記版本。搜尋結果或其他版本的同名表不能直接補進來。
- 規格以外的官方文件可以解釋特定平台，但不能把某家平台的行為提升為所有 PCIe 裝置的義務。
- 若採用後於 Base 6.0 的文件或 ECN，先交代差異與適用版本，再決定是否另設補充內容；不將新定義無聲套回 6.0。
- 原文要求強度必須保留。shall、should、may、Reserved、Undefined 與 Implementation Specific 不可互換。
- 一項機制在文件中存在，不表示所有版本、所有 Function 類型及所有裝置都必須支援。判讀前必須檢查其適用條件。
- 精確引用至少包含來源名稱、Revision、Section；涉及欄位時加上 Figure、Table、文件頁與 PDF 頁。跨頁表格記錄實際使用的欄位頁，不能只填表頭頁。
- 教材中的來源連結先指向合法的官方入口；使用者提供 PDF 的檔名與雜湊保留在內部來源紀錄，不將整份 PDF 公開。
- 來源互相衝突時，記錄衝突與無法確定的部分。未確認前不靠推測補出單一答案。

## 教學假設、推演與背景如何標示

規格定義、教學資料及推論需在讀者使用它們之前區分清楚。

| 標記 | 用途 | 寫法要求 |
|---|---|---|
| 規格依據 | 規格明確定義的欄位、編碼、流程與限制 | 就近附來源定位；若是摘要，仍保留條件和規範強度。 |
| 教學假設 | 作者設計的拓樸、位址、Capability 位置、暫存器讀值或工作負載 | 明說不是實機量測，也不是規格指定的固定值。 |
| 案例推演 | 根據已標示的假設與規格規則逐步得到的結果 | 顯示推導；結論只涵蓋已給定的條件。 |
| 必要背景 | 為理解 PCIe 而補充的 CPU、OS、記憶體、IOMMU 或訊號概念 | 說明它支援哪個問題；有平台差異時明列平台與來源。 |

例子可以自行設計，但數值及行為仍需符合指定版本。若是刻意設計不成立的案例，題目要標明「檢查此假設是否成立」，不能先把矛盾資料當作合法硬體回傳，再用它教授正常行為。

## 圖表與中文校閱

圖表由教學目的決定。拓樸圖顯示元件與路徑；欄位圖顯示位元位置；比較表顯示讀者需要區分的對象；流程圖顯示真正的先後、等待與條件分支。沒有新增理解價值時就用文字，不設定每章圖數，也不要求每張規格 Figure 都重新繪製。

自製圖要標示為教學示意，圖內略去的元件或條件須就近說明。互斥分支不可畫成依序執行；簡化的啟動圖也不能讓讀者誤以為 PCIe 規格定義了所有平台唯一的開機順序。表格旁不重貼逐列相同解說，只有需要推導的部分才展開說明。

中文依整段語意校閱，不只替換詞彙：

- 先交代主詞、動作與對象，再說條件及結果。切換 Port、Function、韌體或 OS 時，重新寫明對象。
- 「因此」只用於有因果關係的句子；「但」只用於實際轉折；條件用「若」或「當」交代清楚。
- 「它」、「此時」及「這個值」必須能從前一句找到唯一的指涉。必要時多寫一句，不為縮短篇幅省略推理。
- 首次介紹術語時保留正式英文名稱並解釋用途。後文穩定使用同一譯名，不以英文縮寫或斜線代替完整句子。
- 避免「輕鬆掌握」、「全面解析」等宣傳語，也不以口號或生硬對仗取代具體說明。
- 讀完一段後，應能說出「目前知道什麼、接下來為何查這裡」。若答案只剩一串名詞，就需要改寫。

## 後續逐章編寫與驗證

後續每章先檢查章節目標是否已在現有內容完整教過。若只是換裝置名稱或換數值，優先改進原章案例；若增加新的判斷條件，再決定放入原章或獨立成節。

每次新增章節，依序完成以下工作：

1. 從本計畫選定學習問題、先備章節及完成後可做的判斷，避免邊讀邊無限擴張主題。
2. 核對來源版本，補齊來源登記與技術主張；先讀必要條文，再核對圖表和欄位，不能只憑圖示下結論。
3. 設計自洽的教學假設，驗證位址加法、位移、Mask、欄位編碼與邊界條件，保留能否得出結論的限制。
4. 撰寫中文教學正文，再整理中英文內容對等的報告文章。英文不能新增中文沒有的結論，也不能刪掉會改變判讀的前提。
5. 檢查章內及跨章重複、先備連結、來源定位與假設標記。需要補充外部知識時，登記用途及版本。
6. 產生教材後檢查來源連結、章節導覽、數值、折疊答案、離線閱讀及明暗模式。以實際窄螢幕與桌面畫面確認沒有截字、遮蔽及整頁橫向溢出。
7. 完成內容與版面驗證後，再將該章從 `planned` 改為 `ready`。維護計畫與來源紀錄反映實際完成範圍，不提前宣告後續章節已完成。

技術內容的可靠度取決於可追查的來源和推導，不取決於引用數量或篇幅。案例要讓讀者學會從需求走到可證明的結論；遇到證據不足時，也能具體說出缺少哪一項資料。
