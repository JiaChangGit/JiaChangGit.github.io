# PCIe 與指定 NVMe 教材修訂

本次已由使用者確認共用 skill 並授權開始修改。來源與教學決策保存於 `.ai/spec-teaching/`。公開 GitHub Pages 只包含核准教材與必要的網站資源；來源 PDF、擷取物、私人資料及檢查產物保留在公開儲存庫外。

## 範圍

- PCIe：全部既有章節，並依 Base 6.0 Chapters 1–10 與 Appendices A–L 補足主題。Chapter 10 原生包含 ATS／PRI 等位址轉譯內容。
- NVMe：Q1–Q328／27 冊、七冊圖表情境／45 情境／117 圖，以及 Transport 1.4、NVM Command Set 1.3 兩篇專篇，各保留三版本與原網址。
- 其餘 NVMe 專篇不改寫。兩篇專篇透過限定 report 的產生流程處理；共用樣式以明確標記的文章範圍套用。

## 已整合的共用方式

PCIe 藍色、NVMe 綠色，實際規格仍以名稱與版本辨識。完整教學先用適合主題的圖定位，再給重點與必要前情，沿正常路徑帶讀來源，最後補充相關條件。問題直接接解說；主解說預設顯示，延伸背景及完整來源可收合。

既有 PCIe 章節增加不同圖種的逐步總覽；Chapter 0–2 另接回原先核對的圖解草稿。中英文文章保留核心圖及主線。七冊 NVMe 圖表系列各選一個既有情境開場，提供 Figure 閱讀目的與跨冊連結，沒有複製第二份答案。題庫先給本冊必要背景，再依各題目的安排解說。

## 全規格對照

`.ai/pcie-course/base6-coverage.json` 保存 1,324 個目錄定位及規劃章節。Chapter 0–37 現在各有三版主題教學，新增章節包含封包格式、實體層、電氣量測、進階能力、虛擬化、轉譯、安全、管理及附錄的相關讀法。

目前 158 個定位標為已帶讀，1,166 個子項仍待逐項核對；既有 claim 命中只列為查證候選，不代表該段所有細節已教過。主題導讀完成與全文逐條涵蓋是兩種狀態，不因新增章數就將整份 Base 6.0 標成完成。後續依子項缺口補充原章，避免另開相似文章。

## 發布檢查

`validate_public_teaching.py` 檢查來源邊界、可能的憑證簽章、主要教材的本機個人路徑，以及離線教材中的主動元素、事件屬性與外部資源。Jekyll 後使用 `--site-dir` 檢查實際發布目錄。錯誤訊息只報檔名及類型，不列出憑證內容。

CI 安裝的 Ruby 依賴位於 `vendor/bundle`；該目錄與 `.bundle` 同時由 Git 忽略並由 Jekyll 明確排除。已追蹤的檔案仍會掃描，不因忽略規則而略過；實際站點也獨立檢查憑證簽章，並禁止依賴目錄出現。回歸案例涵蓋套件內未追蹤的測試資料、誤強制加入 Git 的金鑰，以及建置目錄中的洩漏。

來源、數值及產物以原有驗證器檢查。瀏覽器分別驗證 PCIe 導圖互動與 NVMe 的預設解說、配色、版面、來源展開、搜尋輸入及列印。實際截圖仍需校閱；測試通過不表示取得真人學習成效。

新增 `validate_pcie_examples.py` 從作者假設重算八組欄位與單位模型，再核對三版可見結果。`spec_terms.py` 在前兩次使用處補上可見名詞說明；具有多種含義的縮寫仍須由作者按上下文解釋，不以字典替代技術校閱。

兩篇 NVMe 專篇的標題與圖表說明改寫也會同步更新對應 claim 的呈現文字；未變更其餘專篇的 claim 內容。完整 builder 在隔離副本重跑，另外比對範圍外 60 份產物，確認共用程式沒有改寫它們。
