熱插拔與拓樸變動

從插槽能力、事件通知與插入時序，判讀熱插拔的資源與移除條件。

裝置插入後，系統不只要發現它，還要確認供電、Link、設定存取與位址資源都已準備好。裝置移除時則反過來：先讓軟體停止使用，才有機會有秩序地收回資源。本章從插槽的一組讀值出發，把這些步驟接起來。

版本與案例邊界

硬體行為依 PCI Express Base 6.0，控制權與韌體交接依 PCI Firmware 3.3。兩份規格的版次分開使用。本章所有讀值、時間與資源配置都是作者假設；延用 02:01.0 → 03:00.0 的位置，但另設一個具備 Hot-Plug 的插槽案例。假設 OS 已取得原生 Hot-Plug 控制權，沒有 SFI 介入，採一般有秩序插入流程，也不使用提早就緒通知。

1. 有插槽，就一定能在運作中拔插嗎？

不一定。PCIe 的 Native Hot-Plug 定義了一組可搭配使用的機制；按鈕、指示燈、電源控制器、固定扣具與偵測器是否存在，還要看實際 form factor。Base 規格不替所有連接器指定相同的拔插方式。

2. 如果要查這個插槽能做什麼，依序看哪幾張圖？

先在控制插槽的 Downstream Port 02:01.0 找 PCI Express Capability，不能到新插入的 Endpoint 尋找插槽控制器。本例 Capability base=0x70。先讀 Figure 7-23 的 Port Type 與 Slot Implemented，再讀 Figure 7-30 的 Slot Capabilities；有了能力前提，才解讀 Figures 7-31、7-32 的 Control 與 Status。

(0x0162 >> 4) & 0xF = 6 表示 Switch Downstream Port；bit 8=1 才讓插槽欄位具有本節所需的意義。若 Slot Implemented=0，不能繼續把整個 Slot Register 區都當成有效插槽資料；Data Link Layer State Changed 等欄位另有明確例外。

Slot Capabilities 的 bits 0–4 都是 1：Attention Button、Power Controller、MRL Sensor、Attention Indicator、Power Indicator 均存在。MRL 是 Manually-operated Retention Latch，也就是手動固定扣具。bit 6=1 表示 Hot-Plug Capable；bit 18=0 表示支援 Command Completed 通知。0x002825DF >> 19 = 5 是實體插槽編號，不是 Device Number。

功率欄位也要分開算：Value=(0x002825DF >> 7) & 0xFF = 75，Scale=0，因此本例上限為 75 W。這是插槽所提供的上限資訊，不是裝置當下量到的耗電量。本例沒有使用 Value 大於 0xEF 時的特殊編碼。

Hot-Plug Surprise bit 5=0。本例只示範有秩序流程；不能由此推斷其他平台完全無法處理非同步移除。Base 6.0 已不建議以舊 HPS 機制支援 async hot-plug，而建議使用 DPC。若有 SFI，讀到的 HPS 還可能受 SFI HPS Suppress 影響。

3. Presence=1 與 Presence Changed=1，有什麼差別？

0x0048 的 bit 6 是目前狀態，bit 3 是待處理事件。前者說「現在偵測到裝置」，後者說「存在狀態曾經改變」。事件 bit 不記錄變化次數，也不保存每次變化方向；同類 Slot Event 尚未清除時，後續同類事件會被忽略。因此軟體不能把 Changed=1 解成「剛好插入一次」。

本例有主電源控制器，也有符合 form factor 的 out-of-band presence detect，因此主電源關閉時仍能偵測插入。一般而言，In-Band PD Disable=0 時 Presence Detect State 是 in-band 與適用 out-of-band 偵測的 OR；in-band 偵測需要裝置已有供電。若兩種偵測來源不同步，只看這一個 bit 不能還原完整的物理過程。

通知又是另一層。Slot Control=0x17F8 開啟 PDC Enable bit 3、Command Completed Interrupt Enable bit 4、Hot-Plug Interrupt Enable bit 5，以及 Data Link Layer State Changed Enable bit 12。存在事件 bit 可以在通知停用時設起來；而要收到中斷，還必須符合所選 INTx 或 MSI／MSI-X 機制的條件。

4. 寫入 Power On 後，什麼時候可以開始枚舉？

本例先處理插入事件、確認扣具關閉與功率預算足夠，再向 Slot Control 寫入 0x12F8。這個值保留通知設定，讓 Power Controller Control bit 10=0（Power On），Power Indicator bits 9:8=10b（Blink），Attention Indicator bits 7:6=11b（Off）。假設沒有前一個未完成的 Hot-Plug 命令。

對 Hot-Plug Capable Port 的 Slot Control 寫入就是一個 Hot-Plug 命令，即使只改通知設定也一樣。本例支援 Command Completed，所以必須等前一個命令完成後才發下一個；若一秒後仍未回報完成，規格允許重送或發下一個命令。這是命令介面的規則，不是「逾時就能假定供電成功」。

Command Completed 只保證控制器已處理前一個命令、可以接收下一個命令，不保證命令對應的實際動作已完成。同樣地，Power Controller Control 讀回 0，只是最近寫入的設定；電源故障等狀況仍可能阻止實際供電。

之後收到 Data Link Layer State Changed，須再讀 Link Status 的 Data Link Layer Link Active，確認為 1。本例在 t=40 ms 讀到 Link Status=0x2043，其中 bit 13=1；沒有適用的提早就緒機制，所以從這次讀到 Active 起等 100 ms，t=140 ms 才開始 Configuration Request。不能把 100 ms 從 t=0 或 Command Completed 起算。

§6.7.3.3 另規定：Hot-Add 啟動後，一秒內應出現 Data Link Layer State Changed；有 Power Controller 時，本例起點就是 t=0 的供電寫入。對已 Active 但尚未回 Successful Completion 的裝置，軟體又須允許從 Active 起至少一秒，才可認定裝置損壞。這兩個一秒處理不同問題；RRS 與 Reset 的等待例外回看 Chapter 9。

5. Link 已起來，為什麼新裝置仍可能不能使用？

接下來要完成 枚舉與 資源配置。這不是重跑兩章的所有細節，而是檢查新增裝置能否放進目前仍在使用的拓樸。

作者資源案例：假設某條下游路徑只剩 0x80080000–0x800FFFFF 可用，共 0x80000 bytes，也就是 512 KiB。新裝置的一個 BAR 需要 0x100000 bytes（1 MiB），且依大小對齊。即使裝置已能回 Configuration Completion，這段空間仍放不下 BAR；把 BAR 寫到視窗外也不會讓上游自動轉送。

平台可以在最初配置時預留適當的 Bus Numbers 與 Memory／I/O 範圍。若預留不足，是否能重新配置，要看上游視窗、Host Bridge 可提供資源，以及其他驅動是否能配合暫停與搬移。這是平台與 OS 的配置政策，不能把「支援 Hot-Plug」寫成「保證任何新卡都裝得下」。

資源範圍與推演邊界

PCI Firmware 3.3 §3.5（pp.34–37）、§4.3.2（p.47）說明 Host Bridge 資源及 OS 配置邊界；Bridge/BAR 欄位沿用 Chapter 4 的來源。本例剩餘空間與容量比較是作者推演，不是規格指定的保留大小或重新配置演算法。

7. 換一個情境，還能判斷嗎？

Presence Changed=1，但 Presence=0，是否能說從未插入過裝置？

不能。前者保留事件，後者是目前狀態；中間可能有多次變動。應以當前狀態決定處理方向，不能把單一事件 bit 當成歷史清單。依據：§6.7.3.1、Table 7-29。

控制權已授予 OS、Link 也 Active，還差哪種證據才能開始裝置工作？

至少還要通過首次設定存取的等待條件、完成枚舉與資源配置，並完成驅動要求的初始化。每一步回答的問題不同，不能用 Active 取代。依據：§6.7.3.3、PCI Firmware 3.3 §3.5。

Command Completed=1 後又讀到 Power Fault，哪個紀錄優先相信？

兩者不矛盾。前者說明命令介面可接受下一個命令；後者記錄電源故障。必須處理故障並重新確認硬體狀態，不能用命令完成覆蓋掉故障證據。依據：Table 7-28、Table 7-29。
