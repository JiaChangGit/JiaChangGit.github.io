選擇步驟後，圖中對應的元件與下方解說會加上重點標示。完整圖與所有解說會持續顯示；也可用方向鍵切換步驟。

圖是查詢資料的共同思路，不代表所有能力都有相同的資料傳送協定。

Vendor／Device ID 協助辨識裝置類型；序號與 VPD（Vital Product Data，重要產品資料）描述個別產品；Root Complex 的連結宣告則描述系統內部關係。先確定要查什麼，再選能力結構，才能避免把型號、個體與拓樸混在一起。

  1. 先選資料用途

    Root Complex可以把內部結構隱藏成opaque模型，軟體不一定能看到每一段實體設計。

    查內部關係時看Root Complex的可見拓樸與Link Declaration；查產品資料時走序號或VPD（產品識別與維護資料）。

    VPD
    Vital Product Data，產品識別與描述資料

    Base 6.0 §6.10、§6.27，pp.748、830–831。

  2. 依該能力的介面讀取

    VPD的讀寫完成旗標方向不同；不能只複製一個polling條件到兩種操作。

    VPD有Address／Data及F旗標交握；vendor-specific能力則先核對廠商、ID、版本與長度。

    Base 6.0 §7.9.18，pp.1274–1275；§7.9.4–§7.9.6，pp.1207–1210。

  3. 把結果連回正確對象

    標準能力標頭可讀，不表示Base定義了廠商私有資料區的每個bit。

    記錄資料來自哪個Function、代表哪個產品或元件，以及哪些欄位由廠商定義。

    Base 6.0 §7.9.4–§7.9.6，pp.1207–1210。

想確認是同型號的哪一張卡，下一步查什麼？

先沿 Chapter 3 的 Vendor／Device ID 確認類型，再依裝置實作查看 Device Serial Number（裝置序號）或產品資料。Table 7-222 定義 64-bit 裝置序號及其 byte 對應；VPD 則可包含 part number、serial number 等維護資訊。兩種資料應保留其來源，不能把型號ID直接當成個別卡的唯一身分。

要讀一段產品資料，圖表怎麼串？

先用 Figure 7-328 找Address／Data，Figure 7-329 找F旗標，再按 §7.9.18 的讀取程序：把地址與F=0以單次寫入送入，等硬體將F設為1，最後讀4 bytes Data。若在完成前又寫Address或Data，行為未定義。

作者情境：軟體要連續讀兩個合法地址。第一筆必須等F=1並取走資料，再發第二筆；不能在第一筆仍執行時直接覆寫地址。取回資料後，用 Tables 6-19–6-21 分清Small／Large Resource的標籤與長度，再找到識別字串及唯讀／可寫區。VPD寫入採不同交握，而且資料不直接控制裝置操作。

找到 VSEC／DVSEC，可以直接照別家晶片的表讀嗎？

VSEC
Vendor-Specific Extended Capability，廠商專屬擴充能力
DVSEC
Designated Vendor-Specific Extended Capability，指定廠商專屬擴充能力

VSEC（Vendor-Specific Extended Capability，廠商特定延伸能力）由通用標頭加上廠商特定標頭與暫存器構成。先核對Vendor ID，再解讀VSEC ID、Revision與Length。VSEC（以廠商定義內容擴充的結構）的資料區並沒有跨廠商共通的bit語意。

DVSEC（Designated Vendor-Specific Extended Capability，指定廠商特定延伸能力）另有自己的廠商與結構識別。讀者先用 Figure 7-248 定位，再依實際指定來源解讀；Base 只教會你找到資料與辨識定義者，私有語意須另外取得對應文件。

Root Complex 的關係資料又接在哪裡？

Root Complex可提供內部連結、RCRB（Root Complex Register Block，根複合體暫存器區塊）及拓樸宣告，也可以呈現不透明模型。RCEC（Root Complex Event Collector，根複合體事件收集器）的Endpoint Association則宣告它處理哪些整合端點。這些資訊用來連接元件與事件責任，並不取代每個Function的身分或資源設定。
