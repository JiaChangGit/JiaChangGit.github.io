看到 TS1 或 TS2，還差哪些條件才能前進？

一次收到正確序列，只代表那次接收有效；轉換條件還包含連續接收、傳送數量與 Lane 範圍。TS1、TS2 是 Training Sequence Ordered Sets（訓練用的有序符號組），兩端各自送出，也各自檢查收到的內容。

【模擬資料】以下資料為教學用途建立，不代表特定硬體或平台。Root Port 00:01.0 與 Endpoint 01:00.0 直接相連，沒有 Retimer。本次觀察 Root Port 的 LTSSM 與收發紀錄，初次訓練使用 2.5 GT/s、8b/10b；Detect 已在兩條候選 Lane 上偵測到 Receiver。以下暫稱 Lane A、Lane B，它們是工具已配對的接線通道，尚不是 Configuration 分配完成的 Logical Lane Number。

假設 Enter Compliance=0，沒有 Loopback 或 Compliance 測試要求。接收的 TS1 均以 PAD 填入 Link Number 與 Lane Number，Compliance Receive=0；本例也不涉及極性反轉。PAD 是尚未指派編號時使用的填充值，不是 Lane 0。所有下列觀察都在所屬子狀態的 Timeout 到期之前。

第一步：Polling.Active 同時看本端傳送量與每條 Lane 的接收

Root Port 在 Polling.Active 持續送出 TS1。依 p.457 的正常轉換路徑，至少要送出 1024 組 TS1，而且 Detect 曾偵測到 Receiver 的所有 Lane，都須連續收到八組符合條件的訓練序列。這裡的 1024 是本端傳送量，八組則是各 Lane 的接收條件，不能把兩個方向的數量相加。

第二步：Polling.Configuration 的傳送計數有新的起點

Root Port 進入 Polling.Configuration 後改送 TS2，Link Number 與 Lane Number 仍為 PAD。接著查 §4.2.7.2.3：在 Detect 曾偵測到 Receiver 的 Lane 上，收到八組連續 TS2，並且從收到第一組 TS2 之後，再送出 16 組 TS2，才能前進到 Configuration。本例 Lane A、Lane B 都已連續收到八組，接收條件成立；接著核對首次接收後的傳送數量。

到了 Configuration，哪些工作仍未完成？

B1 只把本端推進 Configuration。後續還要依 Figure 4-51（p.482）的 Linkwidth 與 Lanenum 子狀態建立 Link Number、Logical Lane Number 與寬度，並完成後續訓練，才會到 L0。兩條候選 Lane 都通過 Polling，也還沒有直接決定最後必為 x2。先前的 Chapter 8 說明了 Link 能力與目前結果如何分開；L0 之後的 Data Link 與 Flow Control 初始化則接到 Chapter 17。

等待超時後，並非一律返回 Detect

先前的案例只走正常轉換。若遲遲無法前進，就要分開查每個子狀態的 Timeout 規則，不能沿用一個共同的「失敗」箭頭。

§4.2.6 的通則給 LTSSM Timeout「不得提早、最多延後 50%」的容許範圍，除非該處另有明文。因此，24 ms 與 48 ms 是規格標稱值，對應上限分別為 36 ms 與 72 ms；不能要求所有實作都恰好在第 24.000 ms 或 48.000 ms 轉移。分析前仍要確認 Timer 的起點、觀察時間及資料是否連續。

Polling.Active 的 Timeout 分支使用「至少一條」及 implementation-specific 的預定 Lane 集合，和正常路徑的「所有偵測成功 Lane」不同。這是規格容許進一步訓練的分支，不足以指出哪條 Lane 已損壞。Polling.Compliance 則還可能由 Enter Compliance 或指定的訓練控制條件觸發；實際進入原因要回查控制與序列內容。

為什麼正在 Polling，Link Training 卻是零？

Link Status Register 的 Link Training bit 只描述特定狀態，並不是完整 LTSSM 的縮寫。本例讀 Root Port 的這個 bit；Endpoint、Switch Upstream Port 與 PCI Express to PCI/PCI-X Bridge 的此欄位不適用，必須固定為零。

升速時，再沿 Recovery 追到 Equalization

初次 Link 先以 2.5 GT/s 到 L0，即使兩端都支援更高速率也是如此；之後可從 L0 進 Recovery 改變速度。Polling 中宣告的高速度能力，不代表當時已用該速度傳輸。§4.2.7.2.4 也明確指出 Polling.Speed 不可達，不要把它補進初次升速路徑。

Equalization（等化，調整每條 Lane 的發送與接收設定以補償通道影響）有速率相關的流程。§4.2.4 要求第一次切換到各個 8.0 GT/s 以上速率時執行適用程序，但另定義了所有元件共同支援與宣告後可採用的略過機制。這裡先分清一般程序、略過到最高 NRZ 速率，以及 No Equalization Needed；不可因某端宣告一個 bit，就替整條路徑省略訓練。

NRZ
Non-Return-to-Zero，不歸零編碼

升速紀錄需要接起「哪一端提出變更、進了哪些 Recovery 子狀態、適用的等化流程、最後速度與寬度」。Chapter 8 的雙端 Register 與狀態帶讀可作查詢入口。經過 Recovery 也不等於重新列舉或清掉所有 Data Link 狀態，須按實際的 LinkUp 與 Reset 歷史判斷。

Base 6.0 §4.2.6.4（p.445）；§4.2.7.2.4 與 p.464 的 Support for Higher Data Rates Than 2.5 GT/s 說明；§4.2.4 Link Equalization Procedure for 8.0 GT/s and Higher Data Rates（pp.392–393）。

有 Retimer 時，一條 Link 與電氣區段怎麼分？

Retimer（重定時器）理解 Physical Layer 協定，並重新建立訊號時序。Figure 4-61 先畫出整條 Link，再把 Retimer 兩側標為 Link Segments。每個 Retimer 有兩個 Pseudo Ports（偽連接埠），朝向會在 Configuration 期間動態確定。

示意路徑：Root Port → 一個 Retimer → Endpoint角色分析位置
Root Port 到 RetimerRoot Port 的 Downstream Port 對向 Retimer 的 Upstream Pseudo Port第一段電氣通道
Retimer 到 EndpointRetimer 的 Downstream Pseudo Port 對向 Endpoint 的 Upstream Port第二段電氣通道
Root Port 到 Endpoint 整體仍是一條 PCIe LinkData Link 與 Transaction 不因 Retimer 多出一層 Switch

接著查 §4.3.2 的模式：Forwarding mode 轉送適用的符號及 Electrical Idle；Execution mode 則在 Polling.Compliance、等化 Phase 2／3 等指定情境參與協定。追查某一段的等化結果時，要標明 Pseudo Port 與方向，不能用 Root Port 的整體狀態替每一段補出相同結果。

Base 6.0 允許同一條 Link 最多兩個 Retimers，外形規格仍可能加上限制。這些元件對 Data Link 與 Transaction Layer 透明；不能替它們各配置一組 Bridge Bus Number，也不能把分段等化當成多組獨立的 TLP Ack／Replay。電氣品質是否合格，還需要 Chapter 8 的適用要求與實際量測。

TLP
Transaction Layer Packet，交易層封包

低功耗與測試分支，另外確認目的與條件

L0p（L0 內部分 Lane 省電的機制）只用於 Flit Mode，保持對稱的目標寬度，且每方向至少有一條活動 Lane。它不是讓整條 Link 先離開 L0 再重建；轉換期間兩側也可能短暫處於不同寬度。相對地，L0s 是另一種快速省電狀態，在 Flit Mode、有 Retimer，或使用獨立 SSC（Spread Spectrum Clocking，展頻時鐘）的分離參考時鐘時，不得支援與宣告。

Polling.Compliance 用於測試；Loopback 的 Lead 發起測試，Follower 負責回送資料；Hot Reset 用 in-band 訊號重設配置好的 Link 與相關下游裝置。它們在 Figure 4-48 都有各自的分支。分析工具若只留下「沒有 TLP」，仍要補上具體狀態與進入條件，才能分清訓練、低功耗或測試。L1、Function 電源狀態與平台政策則接到 Chapter 9。
