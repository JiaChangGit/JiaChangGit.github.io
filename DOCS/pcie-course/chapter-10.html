1. 裝置在 D0，Link 還能省電嗎？

可以。D-state 描述 Function 的電源管理狀態，L-state 描述 Link 的狀態。D0 是 Function 的正常工作狀態，但在沒有傳輸需求時，啟用的 Active State Power Management（ASPM）仍可讓 Link 進入較省電的狀態。新流量出現時，Link 再恢復傳輸。

先分清楚誰進入低功耗
狀態管理對象與用途恢復時要注意
D0／D1／D2／D3hot／D3coldFunction。D1、D2 可選；D3hot 仍有主電源，D3cold 沒有主電源。D3hot 可透過 PMCSR 回 D0；D3cold 需要平台恢復電源與相應 Reset。
L0Link 正常傳輸；Flit Mode 的 L0p 可讓部分 Lane 閒置。L0p 仍至少保留雙向各一條 active Lane，不是整條 Link 停止傳輸。
L0s低恢復延遲的 Link 省電狀態，可分方向進入。Flit Mode 不支援；有 Retimer 或指定的獨立 SSC 時脈條件時，也不得宣告支援。
L1、L1.1、L1.2Link 降低耗電；Substates 可進一步處理時脈與電氣狀態。是否能用，取決於雙端能力、控制、時序與進入條件。
L2／L3主電源已移除的 Link 狀態；是否有 Vaux 區分 L2 與 L3。L2 不傳一般封包，要先喚醒電源／時脈與 Link。

Vaux 指輔助電源，實際供應方式取決於 form factor。D3cold 不是「完全沒有任何電源」的同義詞：若要在主電源移除後偵測喚醒事件，仍需適當的輔助供電。

此外，D0 還分 uninitialized 與 active。剛完成 Conventional Reset 或 FLR 的 Function 回到 D0uninitialized，不能只因 PowerState=00b 就假定裝置工作介面已可使用。

PME
Power Management Event，電源管理事件

PME 是 Power Management Event。PME_En=1 表示允許發出通知，PME_Status=1 則記錄符合條件的事件；Status 的設定不受 Enable 值影響。因此「有事件」與「允許送通知」仍然要分開。

PMCSR 的 PowerState 只有 00b=D0、01b=D1、10b=D2、11b=D3hot，沒有「再寫一個值就進 D3cold」的編碼。寫入不支援的可選 D1／D2 時，寫入本身正常完成，但資料被丟棄，狀態不改變。

3. 從 D3hot 回 D0，要不要重新初始化？

先讀 No_Soft_Reset。若為 1，透過 PowerState 寫入從 D3hot 回 D0，必須保留內部 Function 狀態，回到 D0active；若為 0，內部狀態未定義，軟體必須完整重新初始化。後者也不保證舊資料都已清除，所以 D3hot→D0 不能取代 FLR 的用途。

FLR
Function Level Reset，以功能為範圍的重設

本例 PMCSR=0x810B，想回到 D0 且暫時保留 PME_Status 供後續處理。除了清 PowerState bits 1:0，還要在寫值中將 RW1CS 的 bit 15 寫零；否則把讀到的 1 原樣寫回，就會提前清掉事件。

進入 D3hot 前，驅動程式必須處理仍等待 Completion 的交易，並準備可能因主電源移除而遺失的狀態。若是經 Fundamental Reset 回 D0，或曾進入 L2/L3 Ready 而產生 DL_Down，不能沿用本例的狀態保存結論。

4. ASPM 與把 Function 寫成 D3hot，有什麼不同？

ASPM 讓硬體在允許的條件下，於 D0 閒置時管理 Link。PCI-PM 軟體電源管理則先改變 Function 的 D-state，再由相關規則協調 Link。例如普通非 ARI 多 Function 裝置，不能只因其中一個 Function 離開 D0，就代表其他 Function 也都停止工作；其 Upstream Port 必須等所有 Functions 都離開 D0，才可代表 PCI-PM 發起進 L1。

ARI
Alternative Routing-ID Interpretation，替代路由識別碼解讀

查 ASPM 時，先讀兩端 Link Capabilities 的 ASPM Support，再查 Link Control 的 ASPM Control。前者宣告可用機制，後者表示軟體開放哪些機制；Enable 不是「這一刻已經在 L1」的狀態回報。

接著要比對恢復延遲：Link Capabilities 的 L1 Exit Latency 是 Port 恢復需要多久；Endpoint 的 Device Capabilities 則提供 Endpoint L1 Acceptable Latency，表示它可容忍多少延遲。兩者名字相近，卻不在同一個 Register。若經過多個 Switch，必須考慮整條路徑。

5. 已支援 L1，是否就能直接開 L1.2？

還不行。L1 PM Substates 是另一個 Extended Capability，ID=0x001E。L1.0 對應原本的 L1；L1.1 保持 Link common-mode 電壓，L1.2 不要求保持；兩者以 CLKREQ# 協調進出。ASPM L1.2 還需要 Latency Tolerance Reporting（LTR）支援，讓裝置回報可容忍的服務延遲。

以下換成一條獨立的作者假設 Link：兩端都支援 L1 Substates 與所需 LTR，平台已確認 CLKREQ#、時脈及時序設計可用。走訪各自的 Extended Capability 清單後，剛好都在 0x200 找到這個結構；不能把 0x200 當成固定標準位址。

6. 這組 Enable 值應該如何建立？

上表是設定後快照，不是四個 DWORD 可以任意順序寫入。§5.5.4 要求先確認兩端對應的 Supported bit 都為 1；否則啟用的行為未定義。實際安排還要符合下列順序。

  1. 設定 ASPM L1 Substates 前，兩端先停用 ASPM L1；若要設定 PCI-PM Substates，則須在 D0 進行。
  2. 啟用 L1.2 前，先設定適用的 T_POWER_ON、Common_Mode_Restore_Time，以及 ASPM L1.2 的 LTR threshold。修改時間欄位時，相應的 L1.2 Enable 必須保持清除。
  3. 兩端 LTR threshold 必須相同。先在 Downstream Port 設定所需的 Substate Enable，才可在 Upstream Port 設定對應 bit。
  4. 完成設定後，依 ASPM 與延遲政策恢復所需的 ASPM L1。將來停用 Substate 時順序相反：先清 Upstream Port，再清 Downstream Port。

「位於拓樸上游的元件」與「Upstream Port」不是同一句話：在 Endpoint 與 Switch 之間，Endpoint 的 Upstream Port 位於 Link 的下游端。設定順序要認 Port 類型，不能只憑中文的上下游方向猜。

7. Enable 已經是 1，為什麼還不能進 L1.2？

先看 Control 1 的 threshold：Value 在 bits 25:16，Scale 在 bits 31:29。因此 (0x40801404 >> 16) & 0x3FF = 128，Scale=2；依 Figure 6-15，scale 2 的單位是 1024 ns，得到 131072 ns，也就是 131.072 μs。Upstream Port 的 threshold 相同。

假設已在 ASPM L1.0、CLKREQ# 已 deassert，其他進入條件都成立。兩種服務需求仍須分別檢查；不能只看 snoop 那一欄。本例的 LTR 數字是已解碼的最近有效回報，不是 Max Latency Register 的上限。

同一個 threshold 下的兩次判斷
情境Snoop 需求No-snoop 需求ASPM L1.2 條件
A204800 ns102400 nsNo-snoop 小於 131072 ns，不滿足進入條件。
B204800 ns153600 ns兩者皆大於或等於 threshold；在上述前提下應進入 L1.2。

若某一類沒有服務延遲需求，該類可用「無需求」的分支判斷；這不等於 Requirement=1、Value=0。後者代表任何延遲都會影響裝置，要求盡可能快的服務。LTR 是裝置回報的容忍度，也不是 Root Complex 保證一定做到的硬性延遲承諾。

在情境 A，若另外開了 ASPM L1.1，還可以依規則進 L1.1；本例的 bit 3=0，因此不能假設有這個退路。只看到 L1.2 Enable=1，既不能證明正在 L1.2，也不能證明設定失敗。

進入條件與 LTR 單位

§5.5.1（p.644）要求兩類 LTR 分別滿足；Figure 6-15、§6.18（pp.781–782）定義 Requirement 與 Scale。啟用 Endpoint LTR 前，Root Complex 與所有中間 Switch 必須支援，且由靠近 Root Port 者先啟用（p.781）。Control 1 threshold 的兩端一致性見 p.650。

8. 主電源已移除，裝置如何通知系統醒來？

先分兩步：恢復能傳輸的環境，再送出辨識事件來源的 PM_PME Message。L2 中不能直接傳一般 TLP；支援喚醒的裝置必須利用適用的 WAKE# 或 Beacon 機制，讓平台恢復電源、時脈與 Link。具體使用哪一種，取決於 form factor。Link 重新可用後，PM_PME 帶著 Requester ID 向 Root Complex 傳遞來源。

TLP
Transaction Layer Packet，交易層封包

因此，PME_Support=1 只是其中一項證據。還要有 PME_En、必要的輔助供電、平台喚醒路徑，以及沿途元件的配合。這也說明為什麼 PMCSR 的 D3hot 設定不能單獨代表整個平台已完成 D3cold 電源切換。

補充背景：ACPI 的分工

ACPI 6.6 的 _PR0／_PR3 描述裝置在 D0／D3hot 所需的電源資源。_PR3 雖然與 D3cold 決策相關，名稱中的 3 並不表示它是「D3cold Register」；它也不是 PCIe Configuration Space 裡的一個欄位。作業系統還需依平台協調條件管理這些資源。

來源：ACPI 6.6 §7.3.8–§7.3.11，文件 pp.497–498／PDF pp.568–569。本節只補充平台分工，不展開 AML 程式或假設特定主機的電源接線。

喚醒的兩個階段

Base 6.0 §5.3.3.1–§5.3.3.2（pp.615–616）；D3cold 的供電與保存狀態見 §5.3.1.4.2（pp.608–609）。WAKE# 不是可不分插槽形式任意套用的通用接線指令。

9. 沿條件判讀省電行為

No_Soft_Reset=1，但裝置經歷 D3cold 再上電，還能直接沿用原先狀態嗎？

不能。No_Soft_Reset 保證的是指定的 D3hot→D0 軟體轉換；從 D3cold 恢復需要電源與 Fundamental Reset，回到 D0uninitialized，再建立工作狀態。（§5.3.1.4，pp.606–608。）

只有 Endpoint 支援 ASPM L1.2，上游 Port 不支援，可以只開 Endpoint 嗎？

不可以。對應能力必須兩端都支援才可啟用，否則行為未定義；還要遵守雙端設定順序與 LTR／時序前提。（§5.5.4，p.650。）
