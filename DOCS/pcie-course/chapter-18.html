Flit、編碼與錯誤更正，怎麼放在同一張圖裡？

選擇步驟後，圖中對應的元件與下方解說會加上重點標示。完整圖與所有解說會持續顯示；也可用方向鍵切換步驟。

由上往下看資料包裝層次；這張圖不是接收端逐時脈實作，也不指定一個封包必須佔幾個 Flit。

TLP
Transaction Layer Packet，交易層封包
PAM4
Pulse Amplitude Modulation with 4 levels，四階脈衝振幅調變

前章已分清交易完成與 Link 重送。現在再往下看：TLP（Transaction Layer Packet，交易層封包）先裝入 Flit（固定大小的傳輸單元），再依速率編碼送上 Lane。這三個層次各自處理不同範圍，不能把「一個 Flit」理解成「一筆交易」。

  1. 先確認速率與模式

    較低速率也能使用 Flit 模式，所以不能把 Flit 模式直接當成 64 GT/s 的同義詞。

    8b/10b 用於 2.5、5.0 GT/s；128b/130b 用於 8.0、16.0、32.0 GT/s。64.0 GT/s 使用 Flit 模式與 PAM4 訊號。

    PAM4
    Pulse Amplitude Modulation with 4 levels，四階脈衝振幅調變

    Base 6.0 §4.2.1、§4.2.2、§4.2.3.1，pp.309、318、340。

  2. 拆開固定單元的用途

    236 bytes 是 TLP 區域，仍包括交易標頭等開銷，不能全部當成應用資料。

    Flit（256-byte 固定單元）內含交易內容、DLP（Data Link Layer Payload，資料鏈結層負載）與檢查／更正資訊。先到 §4.2.3.3 讀 byte 分配，再選符合 Link 寬度的配置表。

    Base 6.0 §4.2.3.3，p.351。

  3. 沿編碼與保護規則追到線路

    更正能力有限；不能把存在 FEC 解讀成任何損壞都能修好。

    FEC
    Forward Error Correction，前向錯誤更正

    PAM4（四階脈衝振幅調變）每個訊號間隔表達兩個 bits；FEC（Forward Error Correction，前向錯誤更正）、CRC 與重送一起處理可靠性。

    Base 6.0 §4.2.3.1.1，p.343。

同樣叫 Flit，低速與高速的差別在哪？

先讀 p.309 的模式識別說明，分清 Supported（硬體能力）、Disable（控制設定）、Enabled（協商結果）與 Status（目前或即將使用的狀態）。硬體宣告支援 Flit，不代表這條 Link 已成功協商使用。

速率編碼／訊號重點閱讀位置
2.5、5.0 GT/s8b/10b：8-bit 資料角色編成 10-bit Symbol§4.2.1、Appendix B
8.0、16.0、32.0 GT/s128b/130b：128-bit 負載加同步標頭§4.2.2
64.0 GT/s1b/1b、PAM4，使用 Flit 模式§4.2.3.1

128b/130b 可承載 Flit 模式的資料流；其每 Lane 的同步區塊仍存在。模式描述封包如何包裝，編碼則描述線路如何承載，閱讀時要保留這兩層。

要追一個 byte，該先看哪張表？

先從 §4.2.3.3 的 256-byte 分配定位用途，再到 Tables 4-10–4-14 依 Link 寬度追蹤 byte 如何分散到各 Lane。DLP（承載鏈結層資訊的區域）位於 bytes 236–241；bytes 242–249 是 CRC，250–255 是更正碼。

作者算例：只比較固定 Flit 區域的比例，TLP 區域占 236/256＝92.1875%。這還沒扣交易標頭、填充、控制交換與等待，所以不是裝置的有效讀寫率。要估算應用吞吐量，還要接到 Chapter 37 的工作負載。

更正、檢查與重送怎麼配合？

PAM4（每個訊號間隔使用四階電壓的調變）提高每次傳送的位元數，但相鄰電壓間隔變小，對雜訊與突發錯誤更敏感。FEC（以冗餘碼更正部分錯誤）先提供更正能力，Flit 層 CRC 檢查再搭配 Link 重送。這裡的目的，是看懂三種手段為什麼同時存在。

若要核對演算法輸出，Appendix J 先提供 alpha power 與編解碼器的檔案對應；§J.2 的 84-to-86-byte 編碼器可用來追蹤資料、check 與 parity 的關係。Appendix K 則提供 CRC generator matrix 的對應檔案。它們是演算法核對入口，不能把範例 RTL 的內部結構當成所有硬體必須採用的實作。

附錄 B、C 又在哪裡用？

Appendix B 的 Table B-1 按資料 byte 與 Running Disparity（累積位元不平衡狀態）選擇 8b/10b 代碼；它不是 Flit 的 byte 配置表。Appendix C 則示範資料擾碼的演算法。§C.1 明確說明可以使用其他實作，但必須產生相同輸出。先分清查的是線路代碼、擾碼結果或 Flit 區域，才會走到正確附錄。
