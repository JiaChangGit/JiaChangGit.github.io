NVMe 圖表速查 01 · 初始化、佇列與 PCIe

先確認位址與能力，再看啟用狀態、佇列位置與中斷。PCIe link 和錯誤暫存器用來區分傳輸問題與命令回覆。

每張原圖都有用途、欄位和判讀例子。例子中的數值用於說明，不代表你的裝置設定；原文另有條件時，依該欄位與命令定義判斷。

用瀏覽器「在頁面中尋找」搜尋欄位、FID、LID、CNS 或 Figure。bit／byte 位置沿用原圖：bit 是位元，byte 是 8 bits，Dword 是 4 bytes；index 是第幾筆，offset 是相對起點的偏移，須看當處使用的單位。

FID（Feature Identifier）選擇功能；LID（Log Page Identifier）選擇紀錄頁；CNS（Controller or Namespace Structure）選擇 Identify 回傳的資料結構。

01Doorbell 在記憶體映射中的位置

Base 2.4 · Figure 34 · Memory-Based Property Definition

§3.1.4 · 文件頁 54 · PDF 80

01.1 · 用途查 controller properties 後面的空間怎麼排列時，用這張表找傳輸專用區的起點。PCIe 的 doorbell 區從 offset 1000h 開始；這是相對暫存器基底的位置，不是主機實體位址 1000h。

01.2 · 欄位與關係表的 OFST 是位元組偏移，Size 是佔用大小，T 表示由傳輸規格定義。Variable 表示大小隨配置而變，不能假設整區只佔 4 KiB；個別 SQ／CQ doorbell 位址還要用 CAP.DSTRD 計算。

01.3 · 判讀與例子例如 BAR 映射基底為 80000000h，doorbell 區起點就是 80001000h。要找 queue 2 的 doorbell，繼續查 PCIe Figures 5、6，不能直接在這個起點寫入 queue ID。

02CAP：設定前先查硬體能力

Base 2.4 · Figure 36 · Offset 0h: CAP – Controller Capabilities

§3.1.4.1 · 文件頁 55–58 · PDF 81–84

02.1 · 用途建立佇列、選記憶體頁大小或判斷 ready timeout 前，先查 CAP。它是能力回報，不是目前 CC 的設定值；讀到某能力不代表主機已啟用它。

02.2 · 欄位與關係常查的群組是 MQES bits15:0（最大 queue entries 減 1）、CQR bit16（I/O queue 連續記憶體要求）、DSTRD bits35:32（doorbell 間距 2^(2+DSTRD) bytes）、MPSMIN／MPSMAX bits51:48／55:52（頁大小指數）。CSS bits44:37、NSSRS bit36、CRMS bits60:59 分別查命令集、subsystem reset 與 ready 模式；TO bits31:24 以 500 ms 計。

02.3 · 判讀與例子例如 MQES=03FFh 是最多 1024 entries，DSTRD=1 是間距 8 bytes；兩個值都不能直接當 bytes 使用。選頁大小時還要核對 CC.MPS，等待 ready 則搭配 CC.CRIME、CRTO 與啟用流程。

搜尋詞：CAP · MQES · MPSMIN · MPSMAX · DSTRD · TO · CRMS · CSS

03CC：主機實際選了什麼

Base 2.4 · Figure 41 · Offset 14h: CC – Controller Configuration

§3.1.4.5 · 文件頁 60–63 · PDF 86–89

03.1 · 用途當能力看來足夠，controller 卻無法正常啟用，查 CC 可核對主機真正寫入的設定。它同時包含啟用、命令集、頁大小、佇列項目大小和 shutdown 通知。

03.2 · 欄位與關係EN bit0 控制啟用；CSS bits6:4 選命令集；MPS bits10:7 指定 2^(12+MPS) bytes；AMS bits13:11 選排程；SHN bits15:14 發 shutdown 通知。IOSQES bits19:16／IOCQES bits23:20 是每項 bytes 的 2 次方指數，CRIME bit24 決定啟用時的 ready 模式。

03.3 · 判讀與例子IOSQES=6、IOCQES=4 分別是 64-byte SQE、16-byte CQE，不是 queue 深度。EN 由 1 清為 0 會引發 Controller Reset；MPS、CSS 等設定有停用時才能修改的條件，不能把這個暫存器當任意時點都能重寫的設定表。

搜尋詞：CC · EN · MPS · IOSQES · IOCQES · SHN · CRIME

04CSTS：啟用與關機進度回報

Base 2.4 · Figure 42 · Offset 1Ch: CSTS – Controller Status

§3.1.4.6 · 文件頁 63–65 · PDF 89–91

04.1 · 用途CC 表示主機要求什麼，CSTS 表示控制器回報什麼。啟用卡住、命令無完成結果或 shutdown 尚未結束時，先把這兩邊對起來。

04.2 · 欄位與關係RDY bit0 表示已準備處理 submission entries；CFS bit1 表示無法由適當 CQ 回報的致命錯誤；SHST bits3:2 區分未開始、進行中與完成；ST bit6 區分 controller 與 subsystem shutdown。NSSRO bit4、PP bit5 另提供 reset 發生與處理暫停資訊。

04.3 · 判讀與例子SHST=10b 表示 shutdown 完成，不是一般 I/O 成功。RDY=1 的可用範圍還受 ready 模式影響；在 media-independent 模式下，不能據此假設所有 namespace 的媒體都已就緒。

搜尋詞：CSTS · RDY · CFS · SHST · ST

05NSSR：辨識 subsystem reset 要求

Base 2.4 · Figure 43 · Offset 20h: NSSR – NVM Subsystem Reset

§3.1.4.7 · 文件頁 66 · PDF 92

05.1 · 用途分析重設紀錄時，這張表用來辨識是否要求了整個 NVM subsystem reset。支援由 CAP.NSSRS 回報，與只清除單一 controller 的 CC.EN 不同。

05.2 · 欄位與關係offset20h 的 NSSRC bits31:0 只有寫入 4E564D65h 才啟動此 reset；其他值沒有這個功能效果。讀回固定為 0，不能靠讀值找回主機最後寫入的要求。

05.3 · 判讀與例子若 trace 顯示曾寫入 4E564D65h，之後讀 NSSR 得 0 是規格定義行為，不能據此認為寫入沒發生。確認重設完成與影響範圍，仍要搭配狀態與 §3.7.1 的流程。

06AQA：Admin 佇列深度

Base 2.4 · Figure 44 · Offset 24h: AQA – Admin Queue Attributes

§3.1.4.8 · 文件頁 66 · PDF 92

06.1 · 用途Admin commands 一開始就無法提交或回收時，用 AQA 核對兩個 Admin queues 的大小。這裡記的是 entry 數量，不是記憶體容量。

06.2 · 欄位與關係ASQS bits11:0 與 ACQS bits27:16 分別是 submission／completion 深度減 1；中間與高位保留。每個 queue 至少 2、最多 4096 entries，啟用時把其中一個欄位留為 0 會產生未定義結果。

06.3 · 判讀與例子要配置兩個各 64 entries 的 Admin queues，ASQS=63、ACQS=63，AQA=003F003Fh。SQ 與 CQ 的 entry 大小不同，所以相同深度不代表相同 buffer bytes。

07ASQ：Admin 命令佇列基底

Base 2.4 · Figure 45 · Offset 28h: ASQ – Admin Submission Queue Base Address

§3.1.4.9 · 文件頁 66 · PDF 92

07.1 · 用途這張表回答 controller 要從哪裡取 Admin 命令。ASQ 是 Admin Submission Queue 的基底，不是目前待執行命令的地址，也不是 SQ tail。

07.2 · 欄位與關係ASQB bits63:12 保存實體位址的高 52 bits；bits11:0 保留為 0。完整地址還必須依 CC.MPS 的頁大小對齊，因此最低 12 bits 為 0 只是最低要求。

07.3 · 判讀與例子例如 CC.MPS=1 代表 8 KiB pages；地址 00101000h 雖然 4 KiB 對齊，仍不符合這個設定。先核對 AQA 的深度和實際配置範圍，再比較 SQ doorbell 更新。

08ACQ：Admin 完成佇列基底

Base 2.4 · Figure 46 · Offset 30h: ACQ – Admin Completion Queue Base Address

§3.1.4.10 · 文件頁 67 · PDF 93

08.1 · 用途Admin 命令已被取走，但主機在錯誤位置等完成結果時，查 ACQ。所有經 Admin SQ 提交的命令，其完成項目都送到這個 Admin CQ。

08.2 · 欄位與關係ACQB bits63:12 是地址高位，低 12 bits 保留；地址按 CC.MPS 對齊。Admin CQ 固定關聯 interrupt vector0，不能把任意 I/O CQ 的向量設定套用過來。

09CRTO：控制器與媒體就緒的等待時間

Base 2.4 · Figure 57 · Offset 68h: CRTO – Controller Ready Timeouts

§3.1.4.21 · 文件頁 73 · PDF 99

09.1 · 用途這張表用來區分「先能處理不依賴媒體的命令」與「全部必要媒體就緒」兩種等待目標。排查初始化慢，先確定自己正在等待哪一件事。

09.2 · 欄位與關係CRIMT bits31:16 與 CRWMT bits15:0 均以 500 ms 計。前者在支援並啟用 media-independent ready 模式時使用；CRWMT 描述 controller 及必要媒體全部就緒的最長等待時間，且不得小於 CRIMT。

10SQ doorbell：告知新的提交位置

PCIe Transport 1.4 · Figure 5 · Offset (1000h + ((2y) * (4 << CAP.DSTRD))): SQyTDBL – Submission Queue y Tail Doorbell

§3.1.2.1 · 文件頁 10 · PDF 10

10.1 · 用途主機把命令放入 SQ 後，用此 doorbell 告知新的 tail。表內的 y 是 queue ID；offset 從 controller register base 起算，不是 SQ buffer 起算。

10.2 · 欄位與關係地址公式為 1000h+(2y)×(4<<CAP.DSTRD)，SQT 在 bits15:0，bits31:16 保留。寫入的是環形佇列的新索引，新增命令數要由前後 tail 差值並考慮回繞計算。

10.3 · 判讀與例子DSTRD=1、y=2 時，offset=1020h。深度 64 的 SQ 若 tail 從 62 走到 1，新增的是 3 項；寫 1 不代表只新增 1 項。

11CQ doorbell：歸還已讀取的位置

PCIe Transport 1.4 · Figure 6 · Offset (1000h + ((2y + 1) * (4 << CAP.DSTRD))): CQyHDBL – Completion Queue y Head Doorbell

§3.1.2.2 · 文件頁 10–11 · PDF 10–11

11.1 · 用途主機讀完 CQE 後，更新 CQ head doorbell，告知哪些位置可供 controller 重用。這個動作不是提交新命令，也不是讀取目前 CQ head。

11.2 · 欄位與關係offset=1000h+(2y+1)×(4<<CAP.DSTRD)，CQH 位於 bits15:0，高位保留。寫入新 head，前後差值需考慮環形回繞；doorbell 讀回值由廠商定義，不適合作為狀態查詢。

11.3 · 判讀與例子DSTRD=1、queue2 的 CQ doorbell 在 1028h，與 SQ 的 1020h 相隔 8 bytes。若只處理完成項目卻沒適時歸還空間，controller 可能沒有可重用的 CQ 位置。

12PCI CMD：MMIO 與 Bus Master 的入口

PCIe Transport 1.4 · Figure 12 · Offset 04h: CMD - Command

§3.8.1.2 · 文件頁 17 · PDF 17

12.1 · 用途PCIe 裝置可被枚舉，卻不能正常存取暫存器或搬移主機資料時，這張 PCI configuration 表是起點。這裡的 CMD 不是 NVMe command，也不是 NVMe CC。

12.2 · 欄位與關係常查 BME bit2（Bus Master Enable，允許裝置主動發起存取）、MSE bit1（Memory Space Enable，記憶體空間存取啟用）及 IOSE bit0。bit10 為 Interrupt Disable，其餘欄位依 PCI 用途分開判讀。

13BAR0：暫存器基底的低位與屬性

PCIe Transport 1.4 · Figure 20 · Offset 10h: MLBAR (BAR0) – Memory Register Base Address, lower 32-bits

§3.8.1.10 · 文件頁 19 · PDF 19

13.1 · 用途從 PCI configuration 找到 NVMe 暫存器映射時，先讀 BAR0 的位址與類型，再判斷是否需要 BAR1 高位。此表也說明位址低位不是全部都能當地址使用。

13.2 · 欄位與關係BA bits31:14 保存低 32-bit 地址中的可設定部分；bits13:4 保留。PF bit3 說明不允許 prefetch，TP bits2:1 表示映射類型，RTE bit0 表示 memory space。更大的映射空間可以使更多地址位唯讀。

14BAR1：64-bit 暫存器地址的高位

15MSI-X：總開關、遮罩與向量數

16MSI-X Table：先找 BAR，再加 offset

PCIe Transport 1.4 · Figure 45 · Offset MSIXCAP + 4h: MTAB – MSI-X Table Offset / Table BIR

§3.8.4.3 · 文件頁 25 · PDF 25

16.1 · 用途要定位 MSI-X table 以核對向量配置，先由這張表找 BAR，再加 table offset。BAR index 和位址偏移是兩個欄位。

16.2 · 欄位與關係TBIR bits2:0 選 BAR；TO bits31:3 保存 8-byte 對齊的偏移。形成 offset 時清除低 3bits，不能把整個 32-bit 值直接加到 BAR 基底。64-bit BAR 以低 Dword 的 BAR 識別。

16.3 · 判讀與例子若 MTAB=00002004h，TBIR=4、offset=2000h，表示 BAR4 所映射基底加 2000h，而不是 BAR0 加 2004h。可用 BIR 編碼須依本表判斷。

17MSI-X PBA：待處理中斷的資料位置

PCIe Transport 1.4 · Figure 46 · Offset MSIXCAP + 8h: MPBA – MSI-X PBA Offset / PBA BIR

§3.8.4.4 · 文件頁 25 · PDF 25

17.1 · 用途這張表定位 Pending Bit Array，讓你檢查向量是否有待處理的中斷狀態。PBA 與 MSI-X table 是不同結構，不能因為都屬 MSI-X 就使用同一個 offset。

17.2 · 欄位與關係PBIR bits2:0 選 BAR，PBAO bits31:3 給 8-byte 對齊的偏移；算法類似 MTAB，但欄位內容可以不同。這裡描述的是 PBA 位置，並不是各 vector 的 pending bits 本身。

17.3 · 判讀與例子MPBA=00003000h 表示由 BAR0 映射基底加 3000h 取得 PBA。是否已出現 CQE 仍要讀 CQ；一個 pending bit 不能代替 CQ 裡每筆命令的 status。

PCIe Transport 1.4 · Figure 60 · Offset AERCAP + 4: AERUCES – AER Uncorrectable Error Status Register

§3.8.6.2 · 文件頁 31–32 · PDF 31–32

19.1 · 用途查 PCIe 交易或連結異常時，這張表列出不可更正錯誤狀態。這裡 AER 是 Advanced Error Reporting，不是 NVMe 的 Asynchronous Event Request。
