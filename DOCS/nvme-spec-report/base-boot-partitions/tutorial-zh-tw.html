01 Boot 的兩條讀取路徑

將開機映像讀進主機記憶體

先認出讀取對象

01.01.Boot Partition 是開機映像的儲存空間，不是一般 I/O 命令用 NSID 選取的 namespace。讀取前要知道控制器支援的路徑、目標分割區及大小；目前啟用的分割區編號與這次想讀的目標編號可以不同。

namespace
namespace，主機透過 controller 存取的一份已格式化非揮發性容量。
NSID
Namespace Identifier，controller 用來指向 namespace 的數值 handle；identifier 不等於 namespace 物件本身。

沿 Properties 路徑組合要求

01.02.CAP.BPS 用於確認支援，BPINFO 提供大小、啟用資訊及讀取狀態。BPRSEL 的 BPID、BPROF、BPRSZ 分別選目標、起點及長度；BPMBL 的 BMBBA 指向主機接收記憶體。把來源範圍與目的位址分開畫，才不會把映像 offset 填到主機位址欄位。

offset
offset；從指定起點算出的位移。它回答「離起點多遠」，不等於 index。
BMBBA
Boot Memory Buffer Base Address；BPMBL bits 63:12，低 12 bits 保留。
BPROF
Boot Partition Read Offset；BPRSEL bits 29:10，以 4 KiB 為單位；bit 30 保留。
BPRSZ
Boot Partition Read Size；以 4 KiB 為單位，不能套用 BPSZ 的單位。
BPID
Boot Partition Identifier；選取 0 或 1，與目前 active partition 分開。
CAP
Controller Capabilities，offset 00h 的 controller property，回報 queue、page size、timeout 與其他能力。

沿 log 路徑先讀表頭

01.03.使用 LID 15h 時，先以對應的 BPID 選分割區，再讀 header 中的 BPINFO。Boot Partition Data 接在 log 的表頭後面；log 內的位移與映像本身的位移有不同起點。計畫分段讀取時，先把兩個起點標在同一張資料配置圖上。

LID
Log Page Identifier；指定要讀取哪一種 log page 的編號。

確認資料已經可用

01.04.Properties 路徑依 BRS 等狀態判斷讀取是否完成；Get Log Page 路徑則由該命令的 CQE 判斷結果。主機已配置好 buffer，只代表有接收位置，不能據此認定內容已完成更新。

BRS
Boot Read Status；00b 未請求、01b 進行中、10b 成功、11b 錯誤。
CQE
Completion Queue Entry，CQ 中的一筆完成結果資料結構。

01.05.一次讀取要能指出來源分割區、來源範圍、目的記憶體與完成依據，四項缺一就無法完整解釋資料如何到達主機。

02 映像更新、啟用與寫入保護

更新 BP1 時，同時追蹤內容與保護狀態

把四件事分開記錄

02.01.假設目前使用 BP0，準備更新 BP1。下載新映像只把映像交給控制器；Firmware Commit 才依動作與 BPID 寫入目標；選擇 active partition 又是另一個動作。寫入保護決定目標是否允許被修改，並不直接表示哪個映像正在啟用。

用 FID 85h 只解鎖目標

02.02.假設目前由 Set Features 控制保護，且 BP1 的狀態允許變更。BP1WPS 在 bits 5:3，填 001b 要求解鎖；BP0WPS 填 000b 表示不要求改變 BP0。CDW11=(1<<3)=08h。Get Features 回覆 BP0 時會給真實狀態，不會回傳這個「不改變」要求值。

BP0WPS
Boot Partition 0 Write Protection State；FID 85h 的 bits 2:0。
BP1WPS
Boot Partition 1 Write Protection State；FID 85h 的 bits 5:3。

比較重設與斷電

02.03.在這套機制下，解鎖狀態可跨 Controller Level Reset 保留，power cycle 後回到 Write Locked。若先前設成 Write Locked Until Power Cycle，要求改變保護狀態的 Set Features 命令會被拒絕；要等 power cycle 才離開該狀態，重新上電後仍是鎖定，還需要明確解鎖才能改寫。

共享分割區要再檢查裝置配置

02.04.若 multi-domain NVM subsystem 的控制器 A、B 共享 BP0，將 BP0 設為 Write Locked Until Power Cycle 的要求會以 Feature Not Changeable 結束。這個限制針對特定狀態設定；共享分割區本身並未因此變成不可讀。解除該狀態牽涉共享控制器的同時 power cycle，不能只由其中一個控制器的重設來理解。

NVM subsystem
NVM subsystem，包含 controller、port、namespace 與非揮發性儲存資源的 NVMe 系統邊界。
NVM
Non-Volatile Memory，斷電後仍能保存資料的記憶體。

RPMB 啟用後改走另一套控制流程

02.05.RPMB 是 Replay Protected Memory Block，提供有驗證的操作。啟用其 Boot 保護後，FID 85h 的 Get 回報 100b，保護狀態改由 RPMB 的設定操作控制。解鎖的分割區遇 Controller Level Reset 或 power cycle 會重新鎖定。保護機制不能被停用，與各分割區仍可依規定鎖定或解鎖，是兩個不同層次。

FID
Feature Identifier；指定要讀取或設定哪一項 Feature 的編號。

02.06.更新完成後，分別確認映像內容、active partition 與寫入保護；單一成功回覆不能同時證明這三件事。

從下載片段走到指定 Boot Partition

03.08.這裡只使用 Firmware Download／Commit 與 Boot 更新有關的分支。下載的來源記憶體、完整映像中的位置、目標分割區與啟用選擇是不同座標。

一起判讀的欄位或標示如何共同決定操作或結果帶入情境後怎麼讀
DPTR／NUMD／OFST資料指標指本次主機 buffer；NUMD 是傳輸 Dword 數減 1；OFST 是完整映像中的 Dword 位移。傳 4096 bytes 用 NUMD=1023，接續下一段的 OFST 增加 1024。

Dword

OFST

MUD

查能力、讀取值與寫入值的區別

03.09.FID 指功能，Get 的 SEL 指要查哪一種資訊，Set 的 SV 指是否要求保存。支援能力回覆的 bits 與功能值是不同結構。

SEL
Select，Get Features 用來選 current、default、saved 或 supported-capabilities view 的欄位。
SV
Save，Set Features 要求 controller 同時保存所設定 value 的 bit。
一起判讀的欄位或標示如何共同決定操作或結果帶入情境後怎麼讀
FID／UIDX／DPTRFID 選功能，必要時 UIDX 協助選 UUID，DPTR 傳輸該功能所需的資料結構。不是每個 Feature 都只靠 CQE DW0 回覆；有 buffer 的功能還需讀其資料格式。
SEL=000b／001b／010b／011b分別要求目前值、預設值、保存值、支援能力。要確認裝置現在採用什麼值，應讀目前值；保存值不等於正在使用的值。
CHANG／NSSPEC／SVBL → SV能力分別指出可變更、是否與 namespace 有關、可否保存；SV 是主機的保存要求。SVBL=0 時提出保存要求可能被拒絕；Set 成功也不能一律推論跨 power cycle 保留。
NSSPEC
Namespace Specific，指出 Feature 是否具有 per-namespace scope 的 capability bit。
CHANG
Changeable，指出 Feature value 是否可由 Set Features 變更的 capability bit。
SVBL
Saveable，supported-capabilities result 中指出 Feature 是否可保存的 bit。
UUID
Universally Unique Identifier，128-bit identifier；其實際關聯範圍仍由使用它的資料結構決定。

1. 新 boot image 已寫入 partition，下一次使用的 active partition 就已改變了嗎？
