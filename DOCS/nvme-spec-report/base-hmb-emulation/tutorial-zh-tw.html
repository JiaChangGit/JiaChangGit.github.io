01 HMB 記憶體的提供、使用與收回

01.01.HMB 是主機提供給控制器使用的記憶體。主機先配置區域和描述子，再以 Feature 將它交給控制器；啟用期間，主機必須維持這些記憶體有效，不能當成一般空閒記憶體重新分配。配置者仍是主機，但可使用的時機受 HMB 規則限制。

01.02.停用要求已提交與停用命令已完成，是兩個不同時刻。在中間這段時間，控制器仍可能取回必要資料，因此主機不能提前收回區域。只有到規格定義的交接完成點，才可以修改或回收；這也是 HMB 的完成狀態與背景測試啟動成功不同之處。

來源：Base 2.4 §5.2.14.2.1, 8.2.4 · Base 2.4 §5.2.30.2.3, 8.2.4 · Base 2.4 §5.2.30.2.3 · Base 2.4 §8.2.4

01.04.HMB 是 host 配置、controller 專用的記憶體租約。Set Features enable 成功後，host 必須（shall）停止寫入 descriptor list 與所有描述的 memory ranges，直到 disable command 完成；這是 ownership transfer，不只是 performance hint。

01.05.HMB 已 enable 時再次送 EHM=1 必須以 Command Sequence Error 中止；尚未 enable 時送 EHM=0 則成功但不做事。disable completion 前 controller 應取回所需資料；CQE 被 posted 後才表示 host 可安全修改或回收 buffer。

01.06.使用 HMB 時發生 surprise removal，controller 必須（shall）確保不造成 data loss 或 data corruption。這不代表 HMB 內容本身具有持久性，而是裝置不得把內部正確性依賴在 host 一定能先走正常 release 流程。

02 HMB 的描述子、大小與位址

02.01.HMB 的能力值與實際配置值不是全部使用同一單位。HMPRE、HMMIN 使用 4 KiB 單位；HSIZE、BSIZE 使用 CC.MPS 所指定的記憶體頁大小。計算總量時，先把每種欄位換成 bytes，再比較建議值、下限及實際提供量。

BSIZE
Buffer Size，HMB descriptor 中以 CC.MPS pages 表示的連續範圍長度。
HSIZE
Host Memory Buffer Size，以 CC.MPS memory-page units 表示的 HMB 總大小。
MPS
Memory Page Size，controller 使用的 memory page 大小設定；影響 queue address 與 PRP 對齊。
CC
Controller Configuration，host 用來選擇設定並啟用或停用 controller 的 property。

02.02.描述子清單列出每個區域的起點與大小。清單本身有自己的位址及對齊要求，清單內的記憶體區域也有另外的對齊要求。兩個 BSIZE=32 的區域，在 page size=4096 bytes 時各有 128 KiB，合計 256 KiB；這個加總再與 HSIZE 對照。

03 HMB 在電源轉換與 Reset 後的狀態

03.01.電源轉換與重設後，主機需要確認原本提供的 HMB 是否仍符合再次使用的條件。設定的限制政策與目前限制是否生效，分別由不同欄位表示；控制器處於不同電源狀態時，兩者的數值可能不同，而不代表設定被遺失。

03.02.MR=1 表示交回符合規格要求的原有 HMB，不只是「容量一樣」。記憶體範圍、描述子清單位置和內容等都要符合相同條件。若提供了一份新配置，即使大小相等，也不能直接用原有記憶體的方式宣告，因為控制器需要重新建立對其內容的理解。

來源：Base 2.4 §5.2.30.2.3 · Base 2.4 §8.2.4

來源：NVME-BASE-2.4, Rev. 2.4, §5.2.30.2.3, 文件頁 516-519, PDF 頁 542-545

來源：NVME-BASE-2.4, Rev. 2.4, §8.2.4, 文件頁 744, PDF 頁 770

03.03.HMNARE 只有 Identify.CTRATT.HMBR=1 時可啟用。HMNARE 是 policy，HMNAR 是 controller 此刻是否真的因 non-operational state 而被限制；Admin commands 與其啟動的 background operations 有明文例外。NOPPME 不改變這項 HMB restriction。

NOPPME
Non-Operational Power State Permissive Mode Enable，控制 controller background work 能否暫時超過 non-operational power limit。
Admin
Administrative，建立、設定、查詢或管理 controller 與 queue 的控制路徑。
來源：Base 2.4 §5.2.30.2.3

來源：NVME-BASE-2.4, Rev. 2.4, §5.2.30.2.3, 文件頁 516-519, PDF 頁 542-545

03.04.HMB 不會跨 Controller Level Reset 保存在 controller。reset 後 host 應重新提供資源；若 MR=1 表示歸還先前內容，size、descriptor-list address、descriptor-list contents 與 HMB contents 必須完全相同。RTD3 前宜先 disable，恢復後再依是否保留內容選 MR。

來源：Base 2.4 §8.2.4

來源：NVME-BASE-2.4, Rev. 2.4, §8.2.4, 文件頁 744, PDF 頁 770

04 DSTRD、NDT 與 NDM 的單位

04.01.DSTRD、NDT 與 NDM 都是編碼值，但換算方式不同。DSTRD 決定相鄰 Doorbell 的間距，使用指數關係；NDT 與 NDM 則以 Dword 計算資料與 metadata 的傳輸量。它們看起來都像長度，不能共用「全部加 1」或「全部直接當 bytes」的規則。

metadata
隨 logical block 儲存的附加資料，可包含資料保護資訊，也可有其他用途。
DSTRD
Doorbell Stride，CAP 中決定相鄰 doorbell register 間距的欄位。
Dword
Dword（Double word）；32 bits，也就是 4 bytes。對比 word=16 bits；例如 zero-based dword count=3 代表 4 個 Dwords，也就是 16 bytes。
NDM
Number of Dwords in Metadata Transfer，standard vendor-specific format 中的實際 metadata dword 數。
NDT
Number of Dwords in Data Transfer，standard vendor-specific format 中的實際 data dword 數。

04.02.例如 DSTRD=4 得到 4×2^4=64 bytes 的間距。NDT=0100h 則是 256 Dwords，也就是 1024 bytes，沒有加 1。廠商自訂命令還要先確認採用哪種標準格式及適用能力；長度欄位只描述傳輸量，不能據此猜測廠商資料的內容。

來源：Base 2.4 §3.1.4.1, 8.2.3 · Base 2.4 §5.2.14.2.1, 8.1.29 · Base 2.4 §4.1.1, 8.1.29

來源：NVME-BASE-2.4, Rev. 2.4, §3.1.4.1, 8.2.3, 文件頁 56, 744, PDF 頁 82, 770

來源：NVME-BASE-2.4, Rev. 2.4, §5.2.14.2.1, 8.1.29, 文件頁 356, 374, 733, PDF 頁 382, 400, 759

來源：NVME-BASE-2.4, Rev. 2.4, §4.1.1, 8.1.29, 文件頁 143, 733, PDF 頁 169, 759

04.03.CAP.DSTRD 的實際間距是 2^(2+DSTRD) bytes。DSTRD=0／2／4 分別得到 4／16／64 bytes；software emulation 可用 64-byte stride 把 doorbells 分散到 cacheline，硬體 NVMe interface 的 expected value 是 0h。

NVMe
Non-Volatile Memory Express，主機與非揮發性記憶體子系統之間的介面規範家族。
CAP
Controller Capabilities，offset 00h 的 controller property，回報 queue、page size、timeout 與其他能力。
來源：Base 2.4 §3.1.4.1, 8.2.3

來源：NVME-BASE-2.4, Rev. 2.4, §3.1.4.1, 8.2.3, 文件頁 56, 744, PDF 頁 82, 770

04.04.standard Vendor Specific command format 是 optional。AVSCC.VSCF 控制 vendor-specific Admin commands；ICSVSCC.SNVSCF 控制 vendor-specific I/O commands。兩個 capability 必須分開讀，不能因其中一個為 1 就假設另一類命令也使用 Figure 94。

ICSVSCC
I/O Command Set Vendor Specific Command Configuration，回報 vendor-specific I/O command format 的 Identify field。
SNVSCF
Same NVM Vendor Specific Command Format，ICSVSCC 中表示 I/O commands 是否使用 Figure 94 的 bit。
AVSCC
Admin Vendor Specific Command Configuration，回報 vendor-specific Admin command format 的 Identify field。
VSCF
Vendor Specific Command Format，AVSCC 中表示 Admin commands 是否使用 Figure 94 的 bit。
I/O
Input/Output，對 namespace 執行資料輸入與輸出的操作類別。
來源：Base 2.4 §5.2.14.2.1, 8.1.29

來源：NVME-BASE-2.4, Rev. 2.4, §5.2.14.2.1, 8.1.29, 文件頁 356, 374, 733, PDF 頁 382, 400, 759

04.05.Figure 94 保留 common CDW0、NSID、metadata/data pointers 與 CDW12-CDW15，並把 CDW10／11 定義成 NDT／NDM。若 command 不使用 NSID，必須清為 0；invalid NSID 在使用時必須回 Invalid Namespace or Format，inactive NSID 行為仍是 vendor specific。

NSID
Namespace Identifier，controller 用來指向 namespace 的數值 handle；identifier 不等於 namespace 物件本身。
來源：Base 2.4 §4.1.1, 8.1.29

來源：NVME-BASE-2.4, Rev. 2.4, §4.1.1, 8.1.29, 文件頁 143, 733, PDF 頁 169, 759

04.06.NDT 與 NDM 是實際 dword 數，不是 0's-based。NDT=00000100h 代表 256 dwords=1024 bytes；driver 可用 NDT／NDM 驗證 application buffer，避免 data 或 metadata transfer overflow。是否支援 standard format 仍先由 VSCF／SNVSCF gate。

0's-based
0's-based encoding，以 0 表示實際數量 1；依欄位換算公式通常是欄位值加 1。
來源：Base 2.4 §4.1.1, 8.1.29

來源：NVME-BASE-2.4, Rev. 2.4, §4.1.1, 8.1.29, 文件頁 143, 733, PDF 頁 169, 759

學完後想一想

1. HMB 記憶體原本由 host 配置，host 是否能在 controller 使用時直接重用？

06.01.不能。提供給 controller 的期間必須維持記憶體與描述資訊有效；應完成規定的停用及交還程序後才回收。實體配置者與目前可使用者是不同概念。

來源

來源：NVME-BASE-2.4, Rev. 2.4, §5.2.30.2.3, 8.2.4, 文件頁 515-516, 744, PDF 頁 541-542, 770

來源：NVME-BASE-2.4, Rev. 2.4, §5.2.30.2.3, 文件頁 515-516, PDF 頁 541-542

2. 知道 HMB descriptor 有 4 筆，就知道總容量了嗎？

06.02.還需要每筆 buffer size 和 page size。Descriptor 數只計算分段數；總容量是各段 page 數乘 page size 後加總，並需符合 HSIZE 與能力限制。
